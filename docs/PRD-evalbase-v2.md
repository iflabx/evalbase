## 1. 文档职责与权威

v1 PRD 保留为已交付合同。v2 通过本文件声明新增和替代的行为；未受影响的 v1 功能按 §2 继承，不复制另一套定义。v2 批准后，新增/变更能力以本 PRD 为产品合同，CONTEXT 定义词汇；架构、ADR、测试计划及未来 Ticket 不得扩大产品范围。

[冻结原型记录](prototypes/phase1a-login-multiuser-vnext-freeze.md)与[差异审计](reviews/login-multiuser-vnext-delta-audit.md)提供依据。冻结原型用于页面、组件顺序、状态和交互对照；Owner 决策覆盖原型中的项目负责人角色、草稿串线、重复发布及 Metadata 空值阻断。正式 UI 仍使用“期望输出”，并按 frontend-v1 donor 的字体、颜色、布局、图标和组件样式实现。

本文件中已明确的规则用于形成可评审的完整方案。§11 单列补足原型空白的草案默认值；它们随 PRD 一起评审，不写成已经实现或已经单独获批。原型的 Mock 账号、浏览器存储、客户端权限和 BroadcastChannel 不作为正式实现。

## 2. 继承、替代与范围

| v1 范围 | v2 处置 |
| --- | --- |
| FR-01 项目与隔离 | 保留项目对象和列表；仅管理员创建，普通账号按成员关系访问 |
| FR-02–FR-04 数据集、上传、统一浏览 | 保留全部已有行为、浅层数据集、确认前不可见、去重、映射、分页和原始内容预览；加入真实账号授权 |
| FR-05–FR-06 创建与派生 | 整页共享草稿替代编辑弹窗；保存草稿不生成正式版本，发布仍遵守原有分支规则 |
| FR-07 来源、修改与下载 | 保留来源和两份 CSV；页面增加可信修改者，CSV 列结构继续沿用 v1 |
| FR-08 回收、恢复、永久删除 | 保留确认方式、墓碑和后代可读性；操作只授予管理员，补草稿依赖处理 |
| v1 存储、容量与不变量 | 保留 PostgreSQL/MinIO 职责、不可变版本、Delta/Checkpoint、重启持久化、稳定身份、容量及安全约束 |
| v1 无登录/无成员/无设置/无共享草稿限制 | 在 v2 中由下述需求替代 |
| v1 数据使用边界 | 沿用已批准的数据类别和敏感数据限制；不恢复已取消的 Production Gate 或生产部署/公网访问禁令 |

v2 增加登录、账号注册、管理员、成员邀请、账号设置、在线状态、字段级共同编辑和共享草稿。评测执行、SSO、邮箱验证码、邮件投递、密码找回页面、组织层、项目管理员、审批、评论、任意字段 Schema、版本合并/rebase、覆盖正式叶子版本仍不属于本轮。

本轮不增加项目/数据集重命名和删除、批量 Metadata 改写、独立变更工作台、富文本逐字光标或保存筛选视图。调研建议不自动成为承诺。

## 3. 用户、角色和权限

账号层面分管理员与普通账号。管理员默认可查看和管理所有项目，无需加入项目；仅管理员创建项目。普通账号在每个已加入项目中分别拥有「编辑」或「查看」权限，同一账号在不同项目可有不同角色。界面角色名称使用「编辑」「查看」，内部角色标识仍为 `editor`、`viewer`。没有项目管理员或项目负责人角色。

| 操作 | 管理员 | 项目「编辑」 | 项目「查看」 | 未加入该项目 |
| --- | --- | --- | --- | --- |
| 项目列表、内容、版本、来源、CSV | 所有项目 | 所属项目 | 所属项目 | 不可见、不可访问 |
| 新建项目 | 允许 | 禁止 | 禁止 | 禁止 |
| 新建数据集、上传、移动文件 | 允许 | 允许 | 禁止 | 禁止 |
| 新建/保存/发布/删除草稿 | 允许 | 允许 | 禁止 | 禁止 |
| 浏览草稿及草稿内编辑位置 | 允许 | 允许 | 禁止 | 禁止 |
| 回收、恢复、永久删除正式数据 | 允许 | 禁止 | 禁止 | 禁止 |
| 查看项目成员 | 允许 | 允许 | 允许 | 禁止 |
| 邀请、撤销邀请、改角色、移除成员 | 允许 | 禁止 | 禁止 | 禁止 |
| 自己的资料、信息、登出 | 允许 | 允许 | 允许 | 登录后允许 |

管理员身份属于账号，不通过成员邀请或项目角色下拉赋予。首次初始化建立管理员；本轮没有新增管理员、管理员降级、账号删除或所有权转让的产品入口。

服务端同时保护 HTTP、下载、订阅与后台提交。普通账号移出项目后不能继续读取、导出或修改；编辑者降为查看者后退出草稿并停止草稿订阅，保留正式内容的授权读取。页面提示变化，保留尚未提交的本地输入供用户知晓，不继续发送未授权内容。

## 4. 页面与导航

1. 新安装未初始化时进入管理员注册；完成后所有正常访问进入登录，登录页只提供“账号注册”，不再显示管理员注册。
2. 登录后进入有权访问的项目列表。无项目账号显示空态及“设置 → 信息”的邀请入口；不能误显示演示项目。
3. 保留项目内数据集和测试集导航；侧栏底部提供“设置”。设置按“我的账号：个人资料、信息”和“当前项目：成员”分组，无项目时没有项目成员入口。
4. 右上角显示在线用户的彩色首字头像和“登出”；头像悬浮/键盘聚焦显示名称和当前权限。离线用户不显示。
5. 新建测试集及派生编辑进入整页工作区。查看者浏览正式版本，不提供只读草稿工作区。
6. 新建草稿与已发布测试集在测试集列表中明确标识；已有版本草稿在对应版本、版本图及列表处可发现，上述草稿入口仅向管理员和编辑者展示，显示“继续编辑草稿”、父版本、最近修改者和时间。
7. 整页编辑使用“草稿记录 / 添加资料”；点击整行打开右侧编辑记录。右侧直接编辑问题、期望输出和 Metadata 键值，不再为 Metadata 弹出编辑框。窄视口仍能访问选中记录和主要操作。
8. 已有上传、记录查看和删除确认遵循 v1 对应交互，本次整页化针对测试集创建与派生编辑。

## 5. 功能需求

### V2-FR-01 初始化、注册与会话

- 新安装首次管理员表单包含显示名称、邮箱、密码和确认密码；一次初始化只有一个成功结果，竞争请求不能再创建管理员。
- 账号注册填写邮箱、密码、确认密码，无邮箱验证；成功后登录为普通账号且没有项目成员权限。显示名称初始取邮箱前缀（超过 30 个字符时截取前 30 个），可在设置中修改。
- 密码至少 8 个字符；输入时提示长度和两次是否一致。错误凭据、重复邮箱和确认不一致有明确提示；注册校验失败保留已输入内容。
- 邮箱去除两端空白、按不区分大小写唯一；不做点号删除或其他供应商特有归并。邮箱是登录标识，本轮不能修改。
- 登录刷新后会话仍可用，登出使服务端当前会话失效并清理身份相关页面缓存；会话到期进入登录，重新认证后仍复检目标项目权限。
- 会话失效不能自动回到原有无凭据 Owner 模式。未初始化状态和旧数据升级见 V2-FR-10。

### V2-FR-02 项目、成员与邀请

- 管理员创建项目后即有访问权；普通账号只能从项目成员关系获得权限。
- 管理员按邮箱邀请，角色仅可选「编辑」或「查看」。仅可邀请已注册账号；邮箱尚未注册时提示先注册，不创建邀请。
- 邀请有效期为 7 天。状态包括待接受、已接受、已撤销、已过期；同项目同邮箱只有一份有效待接受邀请。到期/撤销后可以重新邀请。
- 已是成员时提示已加入；接受邀请具备幂等性，不重复创建成员。接受与撤销、接受与到期竞争时只出现一个一致结果。
- 管理员可调整普通成员角色或移除成员，不删除其账号或抹除历史归属。成员变化及时反映在页面、订阅及后续请求。
- 只向管理员展示邀请管理；项目成员可以查看当前成员与角色。没有邮件发送或复制演示邀请链接要求。

### V2-FR-03 设置与信息

- 个人资料允许修改显示名称与头像颜色；名称去掉首尾空白后为 1–30 个字符，头像提供预设颜色和颜色盘。
- 修改显示名称不改变身份或权限，修改颜色同步到在线头像。邮箱只读。
- 信息显示当前账号邮箱对应的有效邀请、项目名称、邀请角色、到期时间和接受操作；无邀请时显示空态。
- 接受后可进入相应项目；失效邀请不能通过旧页面继续接受。本轮信息只承载邀请，不扩展聊天或通用通知中心。

### V2-FR-04 草稿身份与生命周期

- 同一测试集同一父版本最多一个活跃共享草稿；不同父版本各自独立。父版本固定，不能在已有草稿中悄悄更换。
- 新建测试集草稿独立编号，不共享“项目:new”槽；可有多个新建草稿，列表各自显示名称或“未命名草稿”、创建者及最近修改时间。
- 创建者不独占草稿；具有编辑权限的成员可共同编辑，查看者不能访问草稿内容或草稿内编辑位置。
- 首次创建草稿和重复打开须避免重复草稿。草稿名称可暂未填写；发布 v1 时必须有合法测试集名称和至少一条记录。
- 成功保存后可退出、刷新、换设备继续；保存状态分别表示未保存/保存中/已保存/失败，只有服务端确认后才显示已保存。
- “保存并退出”先确认保存；失败保留页面输入和重试入口。普通离开不删除草稿；未保存或冲突状态离开前明确提示。
- 删除草稿是单独确认操作，说明共享未发布修改无法恢复、正式版本不受影响。删除后其他编辑者收到终止提示，迟到保存不能恢复草稿。发布进行中暂不可删除草稿，需等待发布结果或恢复到编辑状态。
- 发布成功关闭该草稿，版本成为不可变快照；后续编辑从明确选择的正式版本建立下一草稿。

### V2-FR-05 整页记录与资料选择

- 派生草稿直接继承父版本完整记录，允许只改现有数据；只有需要追加时进入添加资料。
- 资料文件支持名称搜索及数据集定位；文件和记录分别分页。选择本页与全部筛选结果有不同的标签和明确数量，跨页选择不会丢失。
- 全选固定本次命中的资料与记录集合；后续上传新文件或改变筛选不会静默扩张已有选择。取消选择只移除对应选择范围。
- 同一草稿重复选择已纳入的同一源记录不生成重复行；不同来源的相同文本仍是不同记录，沿用 v1 重复内容提示。
- 草稿记录支持搜索、分页、点击整行、单条增删改和右侧完整编辑；来源显示原文件/原始记录或手工新增事实，并分别标注继承父版本。
- Metadata 保持有序键值；字段名非空且忽略大小写唯一，值允许空字符串。完全空白的新增占位行不作为有效项；有值无字段名或重复键提示错误并保留输入，不能宣称该输入已保存或发布。
- 容量维持 v1：编辑最多 5 个资产、100,000,000 原始 bytes、10,000 条源记录；正式版本最多 10,000 条记录、100,000,000 规范化 bytes。单文件限制仍为 50,000,000 bytes/10,000 条。草稿也不能借批量选择绕过限制，超限保留可调整输入。
- 问题未填写、重复内容等数据核对仍仅提示，不变成发布审批。

### V2-FR-06 在线与共同编辑

- 项目头像表示目前在线的已授权用户；同一用户多标签页合并为一个头像。退出、断开或超时后移除。
- 草稿行和字段旁显示正在编辑者；“在线”“正在输入”“最后保存修改者”含义不同，不能用在线头像伪造修改历史。
- 同一草稿不同记录或不同字段可并行修改并看到对方已确认内容；不同草稿的内容与编辑位置不能串线。
- 同字段竞争保留本地输入和对方已保存值，提供采用对方或重新提交本地输入的明确选择；不能静默后写覆盖。
- Metadata 整体按一个字段处理；本轮不承诺不同 Metadata 项逐字自动合并。行删除与字段编辑、批量资料添加与编辑也必须处理冲突。
- 断线后显示未同步状态，重连先获取服务端现状并处理冲突，再继续提交。多个冲突逐项保留，不以新冲突覆盖旧冲突提示。
- 同步成功、失败与编辑者移除有可观察反馈，不能把演示广播成功视为服务端保存成功。

### V2-FR-07 发布

- 发布固定一个服务端已确认的草稿修订；发起者有未保存输入或未解决冲突时先处理，不能直接发布。
- 同一草稿一生最多生成一个正式版本。双人发布、重复点击、不同请求幂等键和响应丢失重试都返回同一成功结果；不同草稿仍各自发布。
- 发布与保存竞争由服务端确定顺序；发布开始后未被纳入的迟到输入保持在原编辑者页面并提示，不能偷偷写入新版本，也不能声称已经包含。
- 确定未提交的发布失败可恢复草稿并重试；结果未知时先查询恢复，不能同时重新编辑和提交旧发布任务。不消耗标签或留下半版本；发布成功后保留固定父版本、来源、记录顺序和修改事实。
- 标签由服务端决定；页面显示的计划标签只是预览。正式叶子版本也不可原地覆盖。

### V2-FR-08 修改归属与来源

- 草稿的「最近修改」只显示在本草稿内成功保存的记录或字段修改者与时间；从父版本继承且本草稿尚未修改的记录和字段不显示最近修改信息，不得把草稿创建者或父版本作者冒充为本草稿修改者。父版本发布归属仍用于正式版本溯源；新增和移除操作记录操作者。
- 来源与修改页在原有前后值和变化字段旁显示对应操作者；发布者与字段编辑者分别记录。
- 修改归属保存稳定用户 ID，页面展示该用户当前名称；改名后历史页面随之显示新名称，身份归属不变。不保存操作时的名称快照。未记录的旧历史显示“未记录”，不能批量推定为管理员。
- 内容最终与父版本相同的字段沿用父版本的发布归属；草稿中最近编辑提示仍可反映操作。已发布修改事实继续只描述相对直接父版本的净变化。
- 来源记录和用户归属分别建模；移除成员不损害已授权项目用户查看历史。CSV 格式仍继承 v1。

### V2-FR-09 草稿与回收/删除

- 父版本或所属测试集回收时，相关活跃草稿暂停，停止编辑与发布；保留已保存内容，恢复后可继续。暂停页面不向已失去内容访问权的账号暴露正文。
- 永久删除/墓碑化直接父版本或删除整个测试集时，相应未发布草稿终止并清除其独占正文；其他存活父版本的草稿继续受原有依赖保护。
- 删除与保存/发布互斥决胜；不得由迟到请求或协作重放复活已删除内容。
- 既有版本墓碑、后代可读性、共享内容保护与 CSV 缓存删除仍遵循 v1/ADR-0011。

### V2-FR-10 升级兼容

- 区分新空库初始化与已有 v1 数据升级。旧管理员绑定由部署操作者完成，公开账号注册不能领取旧 Owner 数据。
- 旧项目、文件、case/revision、版本标签、父边、内容、来源和现有下载保持可读；legacy 与 delta 两种格式继续兼容。
- 旧 user_owner 及其历史引用保留稳定身份；旧测试身份不能通过打开测试开关直接成为真实成员。
- 新增草稿、账号与邀请经正常服务重启后仍存在；在线状态可以重新建立。升级失败不允许自动退回无凭据 Owner 登录。

## 6. 关键状态

| 对象 | 状态及转换 |
| --- | --- |
| 初始化 | 未完成 → 已完成；不可由普通请求回退 |
| 邀请 | 待接受 → 已接受 / 已撤销 / 已过期；重新邀请创建新邀请 |
| 草稿 | 编辑中 → 发布中 → 已发布；可删除；依赖回收时暂停，恢复后继续；依赖永久删除时终止 |
| 本地修改 | 未保存 → 保存中 → 已保存；失败/冲突时保持未确认内容并重试或解决 |
| 正式版本 | 保持 v1 的可见、回收、墓碑/永久删除状态和不变量 |

## 7. 视觉与实现边界

**前端 UI 必须严格对齐冻结原型**：以 `prototype/login-multiuser-vnext` 对应原型为页面与交互基准，逐项对齐页面布局、导航位置、字段与控件顺序、文案、表格与编辑侧栏、弹窗、操作反馈，以及启用/禁用、空态、错误态。字体、颜色、间距、图标和组件样式严格沿用 frontend-v1。不得自行重新设计页面或以“功能相同”为由改变布局、组件或交互。

原型与本 PRD 已明确确认的规则存在差异时，仅调整该差异对应部分（例如全局管理员、仅邀请已注册账号、查看者不进入草稿、Metadata 空值等），其余 UI 继续严格对齐原型。原型中的 Mock/演示专用控件按既定范围排除。实现前记录对照表，验收时在固定 HEAD 逐页核对实际 UI；未经确认的偏离须修正后再交付 checkpoint。

正式前端在 frontend-v3 内迭代，frontend-v1 永久只读。新页面复用 donor 的组件和样式；每个受影响页面需要字段、顺序、文案、启用条件、空态/错态/只读态对照。原型的演示账号、体验邀请、强制过期、检查按钮和本地存储提示不进入正式 UI。

## 8. 质量与容量

保留 v1 请求校验、Origin/CSRF、项目隔离、流式容量、安全 CSV、幂等和删除保护。账号凭据不能写入前端持久存储、正文日志或事件。页面“已保存”与实际持久化一致。

本轮不承诺生产 SLA、无限用户或无限草稿。正常网络下实时同步目标和测试规模由测试计划明确；容量结论只能引用实际测量。更大规模的部署属于后续验证，不据此降低本轮共同编辑要求。

## 9. 验收与完成标准

测试计划为 V2-FR-01–10 分别提供可观察成功路径、关键失败/竞争路径和旧数据兼容证据。至少完成管理员、编辑者、查看者、无项目账号的完整浏览器闭环，以及两独立账号的草稿共编、冲突、同时发布和撤权。

正式实现与批准 PRD/架构一致，必要测试通过并保存固定提交证据后才能记为完成。文档 Draft、原型冻结和本轮文档提交均不等于 v2 已实现或验收通过。

## 10. 与后续工作的关系

实施拆分与进度见 [v2 Implementation Spec](../.scratch/evalbase-v2/spec.md)：4 张功能 Ticket、3 个 checkpoint 批次。创建 Ticket 不等于开始实现或验收通过；不复用旧 Ticket 的完成状态宣称 v2 功能已完成。

## 11. 本草案补足的默认规则

本轮范围复核已确认：仅邀请已注册账号；修改者使用稳定身份与当前名称；查看者不进入草稿工作区。另已确认允许多个独立的新建测试集共享草稿，在测试集列表中显示并继续编辑。父版本或测试集回收时保留并暂停相关草稿，恢复父对象后继续；永久删除时终止相关草稿，按 FR-09 清理并保护其他存活依赖。下表保留尚未单独确认的默认规则。

| 原型/审计未完整定义的事项 | 本草案采用的规则 |
| --- | --- |
| Metadata 并发粒度 | 整个 Metadata 字段为冲突单位 |
| 账号扩展能力 | 不增加管理员管理、密码找回、邮件服务或 SSO 页面 |

以上默认值是本 PRD 的具体评审点；Owner 已确认的管理员权限、按父版本隔离、一草稿一版本和 Metadata 空值继续按决策记录执行。
