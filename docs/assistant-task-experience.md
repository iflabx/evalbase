# 项目助手：持续任务与候选审核

2026-10-05。Owner 已授权根据助手体验审查完成方案、文档、审查、开发和测试；选择“自动做到候选结果”。本文件补充 [模型助手 PRD](PRD-data-selection-and-assistant.md) §7，覆盖旧版逐轮推动、首步强制工具调用和不自动继续已授权任务的约定。基线 `519d94256026`，沿用 `codex/agent-data-processing` 与当前隔离验收库。

## 1. 用户体验

- 用户描述目标、来源和要求后，助手自行检查资料、准备步骤、生成候选、核对结果；关键信息缺失才询问。后台处理完成后自动继续原任务，用户无需发送“继续”。
- 任务持久保存原始目标、后续用户补充、结构化要求、当前对象、实际处理运行及当前阶段。有限聊天历史不会清除数量、标签范围、保留字段和目标对象。
- 显示资料检查、生成候选、结果核对、等待审核等实际阶段。数量、进度和完成均依据领域结果；工具调用成功不能代表任务目标已完成。
- 确认采纳后按原目标继续已有授权步骤；仅要求候选时完成结果汇总。发布仍需要固定内容的用户确认卡，模型或自动继续事件不提供新授权。
- 候选在面板内分页预览，点击记录查看完整修改前后内容。显示数量是否达标、空问题、完全重复、期望输出分布、受保护字段核对及格式问题；语义正确性明确由用户审核，不伪造通过率。
- 支持选中候选后用自然语言局部调整，也支持助手按明确标签或内容条件定位范围。新一批候选保留未选记录，处理记录保留原结果和真实来源。
- 会话用任务名称辨认；当前页面对象与任务处理对象分别标明，切换页面不会暗中改变正在执行的任务。操作记录默认折叠，实时状态集中显示，历史回复不充当当前状态。
- 失败提供“重试未完成步骤”；核对已提交回执再执行，保留输入和候选。提供停止任务，取消未开始的处理，防止旧模型响应继续写入任务状态。

## 2. 实现与公共接口

- 继续复用 AI SDK ToolLoopAgent、现有业务工具、PostgreSQL 与模型处理 Worker；增加持久任务状态和服务端调度，不新增工作流平台或客户端凭据。
- 会话保存当前任务和单调修订号；回合记录事件来源、任务修订和执行令牌。服务端周期检查已关联处理运行的终态并幂等安排后续回合，浏览器关闭或 Web 重启后可继续调度。处理中不调用模型反复轮询。
- 处理入队与任务关联在同一事务提交；停止与取消处理在同一事务提交，报告响应丢失仍可恢复真实运行。局部调整候选 ID 绑定固定输入位置，失败批重试后仍指向同一记录。
- 每次调用及最终提交核对当前权限、依赖、回合令牌和任务修订。并发领取只执行一次；权限撤销、删除或停止阻止旧执行提交。来源删除沿用原清理规则，并清除新增任务正文。
- 新用户补充或改变目标、范围、允许字段时增加任务修订，作废旧待确认卡；确认提交再次核对修订，响应丢失只恢复真实回执。
- 新用户指令更新持久要求；同会话保持单个运行回合，后台处理等待期间允许补充指令。自动事件在界面标明，不能展示成用户说过的话。
- 模型传输层的控制事件以显式请求消息发起下一次响应，携带事件类型和“不构成新的用户授权”说明；数据库及界面仍保留自动事件来源，不使用助手回复作为续写前缀。
- 会话读取增加任务、名称和后续执行状态；增加任务停止、重试及候选分页读取窄接口。既有草稿、选取、处理、采纳、发布接口继续复用，权限与容量约束保持有效。
- 增加计划工具，持久保存任务标题、明确要求、目标数量及允许的标签；规划信息不能扩大工具权限。纯解释或澄清允许直接回复，取消首步强制调用工具。
- 计划应声明下一业务工具；准备性读取不能替代该操作。计划之后不能只承诺“接下来执行”便结束；未实际执行时显示可重试失败。纯回答或真正缺少信息时显式暂停并给出问题。旧计划至少完成一次实际工具调用，采纳与发布仍只生成确认卡。
- 候选局部调整建立引用上一批结果的新处理运行，仅把选中记录送给模型，未选记录原样保留；新运行保留每个候选对应的原始记录身份、最初字段值与修订；后续多次重改也不能把候选当作草稿基线。原始来源及父运行依赖进入删除清理闭包，已接受的独立资料沿用既有保留规则。采用仍通过既有服务端确认和原子提交。
- 全量核对由服务端计算，不用第一页样本推断。数量不足、标签越界、部分批次失败均不能显示目标完成；空问题与重复给具体数量，模型语义仍需审核。
- 失败重试复用原回合和逻辑操作键，写操作沿用保存的参数和逻辑键，先核对成功工具与领域回执；只读工具重新读取实际状态；旧执行令牌失效。每段自动继续最多 12 回合，明确重试或用户补充开启有界下一段并保留结果；每会话达到 50 回合要求新建会话，不展示不可用重试。

### 2026-10-05 十项实测后的修复约定

- 全文件类别统计与条件查询复用只读 `read_records` 工具，在服务端对完整授权来源计算；返回来源总数、匹配总数、期望输出分类数量及最多 20 条预览。沿用现有筛选条件和 10,000 条容量限制，HTTP 预览接口上限不扩大。
- 模型没有交付结果时不得用成功占位文案收尾；耗尽步骤显示未完成，保留真实操作记录。后台已提交或待确认的状态按真实回执说明。
- 已完成且没有失败批次的运行，重试返回真实终态，不重新排队。扩充批次不足时，保留有效候选、只补缺少条数；含初次请求最多 3 次模型调用，共享原 60 秒批次期限，仍不足或补齐失败则保留部分结果。补齐不自动采用或发布。
- 新运行关联时清除旧核对结果和终态标记；核对结果绑定运行 ID，只展示当前运行的统计。旧候选和历史记录保留。
- 原始文件的局部重改允许没有草稿修订字段；不能序列化未定义值。未选候选、最初来源与受保护字段仍须原样保留。
- 普通文本回复显示中文诊断名称，去掉模型格式标记；不执行模型 HTML 或生成模型链接。用户指定会话名称时保留名称，未命名任务先显示简短占位，随后由已有计划工具命名。类别定义、准确单位及多样性写入生成要求，语义正确性仍由人工审核。
- 新提交必须显式指定允许修改的字段；恢复已有旧缺省提交时保留原“只改问题”语义和逻辑操作键。清洗/改写不增减记录；模型传入与实际选中数相同的冗余输出数量可忽略，不一致则拒绝。
- 自动核对使用全部候选统计，预览页大小不代表总数；只报告语义疑点，不据自身评价擅自局部重改。局部重改不能补齐数量，用户明确要求的调整继续有效。对象定位失败的计划需纠正或明确澄清，不能显示假等待或误称计划服务不可用。

- 处理提交、局部重改和实际排队的重试在持久关联成功后结束当前模型循环；同响应内夹带的后续工具延后，不覆盖任务。恢复成功提交时先读取真实回执，保留原运行与候选，不重复提交。
- 处理完成事件先读取捕获的当前运行，不能以同项目旧运行替代；读取失败不得成功收尾。首读约束独立于原待执行步骤，重试继续履行原用户已授权义务，不能清空后只作文字承诺。
- 勾选候选后的“提交处理”计划对应局部重改；选择范围和允许修改字段仍由原服务校验。失败恢复存在匹配义务的成功处理/重改回执时，服务端先以原参数和原操作键读取并恢复该运行，不让模型重新提交；旧 `any` 义务沿用原含义，其他未执行步骤保留。

## 4. 验收证据

1. 公共 HTTP 与真实 SDK：一个完整目标自动到候选；处理完成无需新消息；确认后继续原授权步骤；解释/澄清可无工具调用。
2. 持久化与竞争：并发调度同事件一次；关闭浏览器和 Web 重建后读取同任务；停止、撤权、来源回收/删除阻止继续；旧响应不能覆盖新任务。

## 6. 接口清单与执行边界

- `reused`：会话创建/列表/读取/发消息、固定确认与拒绝、原草稿创建和发布、选取采用、处理创建/读取/控制/采纳；发布在原事务内核对可信助手修订与令牌。
- `narrowed`：会话任务的停止/失败重试、当前任务候选分页；处理运行的全量结构核对、固定候选范围局部调整及轻量状态读取。接口仍校验项目权限与对象范围，客户端不能提供执行令牌。
- 无公开任意 SQL、终端、网络、凭据、工具注入接口。连续执行仍受每回合 8 步/12 工具/80 秒、每任务 12 个自动后续回合、每会话 50 回合及最多 3 个并行助手回合约束。预算耗尽保留结果并展示未完成。
- 处理运行使用原 Worker 的失败批次重试；已成功候选原样保留。已成功但内容不满意时使用局部调整。
- 当前源身份进入原删除闭包；每代局部调整保存相同根来源，因此删除根来源同时清理各代，避免触发器递归修改同一批行。明确采用产生的独立资料保留。
