# 项目助手采用有界模型循环与现有数据库作业

- Status: Accepted for implementation
- Date: 2026-10-04
- Authority: Owner 本轮授权代理研究、设计并完整实现；功能范围以新 PRD 为准，本文不代表实现完成。
- Scope: 筛选选取、模型连接、处理运行和自然语言助手。

## 决策

采用 AI SDK ToolLoopAgent 和明确的 OpenAI-compatible provider 模型对象，在现有 Fastify 内执行有界对话。耗时模型处理通过现有 PostgreSQL job/Worker，新增领取 kind 范围与模型消费者；沿用 PostgreSQL/MinIO 职责和事务发布协议。

权威状态由应用持久化：会话、固定预览/结果、当前权限、一次性确认、业务操作回执。操作回执与业务修改同事务，不能靠 SDK 日志或模型 tool_call_id 实现业务幂等。普通循环中断后明确报告并核对效果；暂不引入持久图运行时。

模型凭据采用 AES-256-GCM，以部署环境提供的主密钥加密存储；缺少主密钥不允许保存明文连接。端点由管理员维护，成员/模型不控制目的网络地址。日志不记录凭据或任意正文。

固定随机选取使用 `sha256-rank-v1`：种子和稳定来源身份决定排名，输入与规则冻结，补选仅限候选。正文仍从授权的固定解析视图读取，预览不创建第二份原件。

本轮原件保存可延后字段整理，但仍由确认动作形成可见资产，且显式标识未整理；这补充 ADR 0009，不改变确认前不可见或原件不可变。

## 后果与验证

需要新增迁移、提交回执、处理产物引用清理和生成归属；在旧数据升级、并发、重试及永久删除场景验证。LangGraph 等检查点即使后续引入，也不能取代这些业务约束。

已有发布、源数据容量与权限规则保持；新行为只在 [PRD](../PRD-data-selection-and-assistant.md) 指定范围覆盖旧合同。具体接口和恢复见 [架构](../architecture/data-selection-and-assistant.md)，证据见 [测试计划](../test-plan-data-selection-and-assistant.md)。

## 2026-10-05 持续任务补充

Owner 已选择自动推进到候选并授权执行 [任务体验合同](../assistant-task-experience.md)。有限模型回合保留，但后台终态与确认回执由服务端安排幂等后续回合；任务目标与补充独立于聊天窗口保存。PostgreSQL 修订、执行令牌与业务事务守卫阻止停止后的旧写入；重启重领沿用同一操作回执，不持久化浏览器 Cookie。局部调整保留原始记录身份和最初字段修订，确认采用仍使用原草稿冲突检查。该补充覆盖上文“中断后仅明确报告”的恢复方式，不引入外部工作流平台。

## 2026-10-06 会话背景补充

本轮 [优化合同](../assistant-optimization.md) 授权 PDF/MD/TXT 背景。背景不是测试记录资产，不保存原文件二进制或提供原件下载；只将有定位的受限提取文本、原文件 SHA-256 和提取版本保存在个人会话所属的 PostgreSQL 表。处理运行冻结当时选用的片段、真实页/行引用及用户纠正后的要求，正文仍进入该运行的 MinIO 输入快照，不另建知识库。这样可复用会话正文清理、任务修订和处理产物生命周期，避免原件对象与会话再维护两套引用。

PDF 在可终止的 Node Worker 中使用固定 `unpdf@1.8.1`；`pdfjs-dist@5.6.205` 仅提供同版本字符映射和标准字体资源，读取限定于包内文件，不访问文档提供的外部路径。文本提取不需要 native canvas、OCR 或 embedding。具体容量与删除行为由优化合同定义；此决策及通过提取测试不代表前端和最终 200 条闭环完成。

新增运行采用 `processing-v2` 的完整请求预算分批；恢复 `processing-v1` 时保留旧分批计划和成功产物，不以同一批序号执行重新划分后的记录。候选局部调整继承首次候选的稳定采用身份，并将该身份随实际采用回执持久保存；实际处理运行、结果编号和来源继续记录当前真实值。无需新增采用表，细节与兼容校验见架构和优化合同。
