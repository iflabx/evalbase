## 1. 适用范围

- 只允许在 Project Owner 已批准访问路径内的非生产服务器上开发和使用；Web 沿用已批准绑定地址与端口，不扩大暴露面。
- 唯一真实用户是 Project Owner / Sole Developer。应用无登录页、凭据、成员、角色、分享或审批。
- 服务端可非交互式绑定唯一 Owner，并继续实施项目隔离、Origin / CSRF 和写请求保护；这些是内部边界，不是用户功能。
- 只允许合成数据、公开且许可清晰的数据，或已确认完全去标识的非敏感数据。
- 禁止真实个人信息、客户 / 生产数据、秘密凭据、商业机密、受限数据、许可不明数据、真实多人协作和外部共享。
- 不实现 Phase 1B，也不把 Production Gate 当作当前研发功能。

## 2. 容量决定

| 容量项           | Phase 1A 上限                                             |
| ---------------- | --------------------------------------------------------- |
| 单个源文件       | 50,000,000 原始 bytes；10,000 条 Source Record            |
| 一次编辑所附来源 | 5 个资产；100,000,000 原始 bytes；10,000 条 Source Record |
| 单个发布版本     | 10,000 条正式记录；100,000,000 规范化 bytes               |

所有边界均为精确十进制值：恰好等于上限允许，下一 byte / record 必须失败且不能产生半成品或丢失可恢复编辑。当前决定不授权提高容量、分块上传、断点续传、Join、测试记录自动去重或大数据服务；FR-03 定义的同项目原始文件精确字节重复阻止是唯一例外。

## 3. 用户可见产品决定

[PRD](../PRD-evalbase-v1.md)与冻结原型共同固定当前用户表面：

1. 首屏是项目列表；Owner 新建或打开项目。
2. 项目内只有“数据集”和“测试集”两个子入口；UI“数据集”对应内部 Raw Material Collection。
3. 数据集支持浅层归类、两步确认上传、统一记录浏览和同项目文件移动。
4. 数据集记录以序号打开详情；单文件原始内容只在页内只读预览开头最多 1,000,000 bytes，超出时明确提示截断。
5. Metadata 由有序的字段和值组成；旧单文本按唯一 `Metadata` 项无损读取和导出，不引入 Schema 或 JSON 编辑器。
6. 测试集支持选记录、三列增删改、创建 `v1`、从任一版本派生、版本分支图、来源 / 修改查看和两个 CSV 下载。
7. 测试集版本记录支持服务端搜索、分页及固定白名单筛选；筛选不保存、不构成任意查询。
8. 测试集与版本支持 Trash、恢复和冻结原型定义的永久删除；中间版本永久删除保留墓碑关系。

原型中的每个用户动作都必须存在；原型没有的动作、表单、页面、筛选、状态选择、下载或 CLI 不得加入。数据核对只提供警告，不阻断创建版本或下载。

## 4. 内部安全与一致性决定

- PostgreSQL 是身份、关系、状态、项目范围、版本分配、来源和审计真源；MinIO 是原始、暂存、版本和 CSV 字节真源。
- 对象先完整提交，数据库后建立可见引用；确认前上传、失败发布和失败删除不得产生领域可见半成品。
- 接收保持流式，写入保持幂等；测试集版本不可变，标签在事务内分配且不得复用。
- 稳定 case / revision / source edge 继续记录来源；前端只显示冻结原型中的可理解摘要。
- CSV 必须绑定显式版本，采用稳定顺序、正确 quoting 和 spreadsheet formula 防护。
- 日志、错误和指标不得记录文件 / 记录正文、凭据或对象 URL。
- 公共 HTTP 请求、响应和动作必须恰好符合冻结原型；对应 Ticket 优先原位收紧可复用旧路由，底层可靠能力继续复用。旧前端和历史测试不构成保留超范围路由的理由。
- 历史 Owner / Editor / Viewer、Schema、Recipe、Candidate、Job、Package、Delivery、Offline Validator 和 Langfuse 实现若暂时保留，只能不可导航、不可见，且不能定义当前产品行为。

## 5. Trash 与永久删除

- 移入 Trash 只改变日常可见性，内容和关系保留并可恢复。整套测试集只能从列表垃圾桶回收；回收站按测试集与版本/版本分支分组，整套恢复会恢复其已吸收的可恢复分支。
- 永久删除使用冻结原型中的精确名称或版本号输入作为唯一用户提交边界；中间版本墓碑同样要求版本号。不增加理由、审批人、外部副本清单、影响预览页或删除作业页。
- 服务端必须在后台验证依赖闭包并 fail closed：先阻断读取、下载和新引用，再幂等清理。
- 有未受影响引用的共享 blob 不得物理删除。
- 中间版本删除内容后保留最小墓碑、原标签和父子边；后代不得改挂，墓碑不可浏览、下载或作为派生父版本。
- 永久删除不可恢复。该能力不是法务、隐私或合规认证。

## 6. Production Gates

当前没有生产批准。进入生产、真实敏感数据、真实多人或外部共享前，至少需要重新评估并由实际责任主体批准：

- 身份认证、最小权限、网络边界、TLS 和密钥管理；
- 备份恢复、RPO / RTO、监控告警、容量和故障演练；
- 数据分类、保留 / 删除政策、外部副本、隐私 / 法务 / 合规责任；
- 依赖、供应链、安全测试和正式发布流程。

在这些条件完成前，不得声称生产、安全、隐私、法务或合规通过。

- `frontend-v1/` 是不可修改的视觉和组件 donor，不是产品合同。

- Ticket 27 经 Owner 验收后，正式运行路径只构建和服务 `frontend-v3/`。
