## 1. 结论

当前合同和 Tickets 19–26 **不完全符合**冻结原型 v5。主要流程已经接近，但还不能直接把现有文档当作后续实现合同：

- `项目 → 数据集 → 测试集` 的工作区层在原型中已经成立，正式文档仍普遍写成“打开后直接进入原始资料”和“两页 / 两条主线”。
- 原型只允许创建数据集，不提供重命名；Ticket 19 却已经把重命名写成验收项并实现为可见操作。
- 数据集列表、文件行选择与进入方式、测试集创建字段、版本操作、来源页面和下载形式均存在可观察差异。
- 原型提供测试集 / 版本分支的回收、恢复和永久删除，以及中间版本“删除内容、保留关系”；正式合同却禁止从回收站永久删除，并把中间版本内容移除改成一套原型没有展示的受控删除流程。
- Standard / Full Package、Offline Validator、`langfuse.csv`、任意版本比较、默认版本切换、归档、处理运行登记等仍被写成 Phase 1A 用户能力，但不在冻结原型中。它们不是普通的内部事务或安全机制，不能以“后台能力”为由绕过原型边界。

在同步完成前，不应授权 Ticket 20 或以后 Ticket 按当前文本实现用户可见行为。最小修复原则是：**先删去超出原型的用户能力，再补齐原型已有而合同遗漏的能力，不改变底层已确认的数据安全和一致性机制。**

## 2. 审计口径

### 2.1 结论标记

| 标记       | 含义                                       |
| ---------- | ------------------------------------------ |
| `aligned`  | 文档与原型对同一用户行为的描述一致         |
| `missing`  | 原型已有用户行为，但文档或 Ticket 没有承诺 |
| `exceeds`  | 文档或 Ticket 要求原型没有的用户行为       |
| `conflict` | 两边对同一行为给出互斥结果                 |

### 2.2 不属于功能扩张的内部机制

以下内容即使原型没有展示，也可继续作为不可见实现约束：原始字节不可变、PostgreSQL / MinIO 持久化、流式大小限制、项目隔离、Origin / CSRF、幂等、原子发布、版本标签并发分配、稳定记录身份、记录级来源事实、CSV 公式注入防护、重启持久化、错误恢复和必要审计。

这些机制只能支撑原型动作。例如，“永久删除”可以在服务端先计算影响、阻断读取并安全清理，但不能额外要求用户进入原型没有的治理页面、填写结构化理由、处理 Delivery Record 或操作独立的后台 Job。

## 3. 冻结原型事实

下列事实均来自 `92b0113` 的实际 HTML 或同标签采用记录：

1. 首屏为项目列表；项目可搜索、分页、新建和打开。新项目只填写名称与可选说明，并自动创建“未整理”；进入项目后侧栏显示项目名，“数据集 / 测试集”成为子项；可切换项目，但没有项目设置、重命名或删除（HTML 3788–3815、4611–4639、5366–5376；采用记录 49、80–88）。
2. 数据集列表显示名称、类型、文件数、统一记录数、状态、最近更新和“查看”，支持名称搜索、类型 / 内容筛选、更新时间排序与分页；数据集只可新建，不可重命名或删除（HTML 3764–3787、4537–4579、4641–4647；采用记录 50、68–78）。
3. 数据集内文件列表只提供文件名搜索。单击整行只改变行的选中状态，页面没有右侧文件信息面板；点击“查看”才进入文件记录。文件可移动到当前项目内的其他数据集（HTML 3725–3763、4785–4815）。采用记录 35、51 仍声称单击行会更新右侧面板，与最终冻结 HTML 自身矛盾，应以实际 HTML 为用户可见事实。
4. 上传是“选择文件 → 字段映射与预览”两步；支持多选 CSV / JSON / JSONL，选择目标数据集，逐文件映射到问题 / 预测输出 / Metadata 或不导入，查看真实预览后确认保存（HTML 5105–5130、5289–5296；采用记录 52、96–100）。正式用语“期望输出”是采用记录明确要求正式实现修正的唯一术语例外。
5. 新建测试集只填写名称和可选用途；随后按数据集 → 文件 → 记录选择，在固定三列表格中增删改并创建 `v1`。页面没有版本修改说明、逐行修改原因、抽样器、字段筛选器、Schema 或默认版本选择（HTML 5132–5194、4429–4461；采用记录 54、102–110）。
6. 可从当前选中的任一历史版本继续创建或创建分支，可不添加新资料；版本标签、父边和旧版本都保留。版本图支持切换、高亮祖先路径和溢出时适应视图（HTML 3348–3502、4462–4521、4891–4948；采用记录 55–56）。
7. 版本详情显示父版本、创建时间、记录数、用途、来源、修改摘要和只提示不阻断的数据核对；没有设置默认版本、归档、任意两版本比较或编辑已发布版本（HTML 4970–4977、5075–5096）。
8. “来源与修改”是独立文字 / 表格页：显示父版本、本次新加入资料、增改删计数、按需字段映射，以及“本次有变化 / 全部 / 未改变 / 已修改 / 新增 / 已移除”筛选和记录详情；没有来源关系图、处理运行、Prompt / 工具、血缘粒度选择或多跳图（HTML 4979–5073；采用记录 58、112–120）。
9. “下载 CSV”下载当前版本数据 CSV；“下载数据与溯源”连续下载数据 CSV 和 `provenance.csv` 两个独立文件，不生成 ZIP（HTML 4649–4737）。
10. 测试集和叶子 / 完整后续版本分支可进入回收站、恢复并在回收站永久删除；中间版本还可“删除内容、保留关系”，形成不可浏览、不可下载、不可派生的墓碑节点（HTML 4196–4320、5075–5096、5216–5232；采用记录 57）。

## 6. 建议同步顺序

1. 先在 PRD 固定唯一规则：v5 是用户可见合同；先项目、后数据集 / 测试集；UI 用“数据集”；原型外用户能力不属于当前 Phase 1A。
2. 同步 `CONTEXT.md` 的 UI / 领域术语映射和删除含义，再同步 Architecture 与 frontend reuse；只保留必要内部机制。
3. 精简 Spec 和 Test Plan，使公共 HTTP / 浏览器 seam 只暴露原型动作；删除 Package / CLI 等额外公开产品 seam。
4. 回写 Tickets 19–26：对已完成 Ticket 19记录对齐处置，不改写历史证据；修正 20–26 的 AC 与 checkpoint。
5. 在 Ticket 19 与 20 之间增加一个独立的 v5 项目工作区 / 数据集首页对齐 Ticket，并将 Ticket 20 改为依赖该票；这是用户开始上传前必须先有的交互，不应延迟到 Ticket 26。
6. 做一次链接 / 术语 / 状态校验和冻结原型路径对照。合同同步本身不授权任何后续实现 Ticket。

## 7. 同步后的最低验收清单

- 无登录，首屏可查看 / 新建项目；进入项目后仅有数据集与测试集子项。
- 数据集列表、创建、搜索 / 两项筛选 / 排序 / 分页与冻结原型一致；无重命名、删除和首页右侧面板。
- 上传、文件移动、文件 / 跨文件记录浏览和原始内容查看与原型一致；不新增逐文件取消、上传阶段原始切换、格式 / 状态筛选、右侧面板或治理字段。
- 测试集只按原型选择记录、三列编辑、填写名称与可选用途；不要求版本说明、Schema、抽样或默认选择。
- 分支图、来源与修改页、记录筛选 / 详情及当前版本绑定与原型一致。
- 下载形式是数据 CSV，以及数据 CSV + provenance CSV 两个文件；不提供额外 Package / CLI / Langfuse 能力。
- Trash、恢复、永久删除和中间版本墓碑与原型一致；后端安全删除机制不增加用户页面或步骤。
- 正式 `frontend-v2/` 继续使用 `frontend-v1/` donor，但任何 donor 旧业务都不能越过原型合同。
