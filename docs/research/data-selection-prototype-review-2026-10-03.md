# 数据选取与抽样调研审查

日期：2026-10-03。输入为用户提供的《EvalBase_数据选取与抽样调研_重排版.md》，原报告只读。用户授权“先审查，没问题之后直接修改原型”。

## 结论

**未发现阻止原型推进的问题。** “范围 → 条件筛选 → 抽样 → 固定预览 → 人工调整 → 加入草稿”适合现有工作流。首版原型只覆盖简单条件及随机数量/比例，不引入独立选取平台、模型服务、规则模板库或分层配额。

审查依据为服务器 EvalBase 的 [V1 PRD](../PRD-evalbase-v1.md)、[V2 PRD](../PRD-evalbase-v2.md)、[领域术语](../../CONTEXT.md)、[V2 架构](../architecture/evalbase-v2-architecture.md)、[Phase 1A 架构](../architecture/phase1a-architecture.md)及[前端迁移规则](../architecture/phase1a-frontend-reuse.md)。本地旧 AgentBench 文档不作为当前项目合同。

## 外部证据核对

| 项目 | 已核对事实与借鉴范围 |
| --- | --- |
| Label Studio | Data Manager 支持条件筛选、排序和筛选标签页；按预测分数排序依赖已有分数，部分高级筛选受版本限制。借鉴列表筛选及批量操作，不把社区版描述为完整智能选样平台。见[官方文档](https://labelstud.io/guide/manage_data)。 |
| Hugging Face Datasets | `filter`、`select`、`shuffle(seed)`及按比例/数量划分可组合使用；IterableDataset 的缓冲区打乱与普通 Dataset 的整体打乱有区别。借鉴操作语义，首版无需引入 Python/Arrow 服务。见[官方文档](https://huggingface.co/docs/datasets/process#sort-shuffle-select-split-and-shard)。 |
| PostgreSQL | `TABLESAMPLE` 在 `WHERE` 前执行，比例是近似值，BERNOULLI 会扫描全表；`REPEATABLE` 也受数据变化影响。因此不能直接用于“筛选后精确取 N 条”。见[官方 SELECT 文档](https://www.postgresql.org/docs/current/sql-select.html#SQL-FROM)。 |

设计推断：仅有随机种子不足以完整复现。应固定来源、映射、候选身份和算法，并保存实际选中身份清单；翻页及确认读取同一次结果。以上证据不能证明当前应用的查询性能。

## 与当前产品一致的边界

- 记录经已有字段映射后进入选取；确认后才加入草稿，发布仍生成不可变正式版本。
- 同一原始记录按来源身份识别，不重复加入；不同来源的相同文本可以保留，不引入语义去重或自动合并。
- 派生草稿继承记录保持不变，仅对本次选择的新增资料抽样。
- 草稿变化沿用当前乐观并发方向；原型只模拟“结果保留、核对后再次确认”，不证明真实双人并发正确性。
- Metadata 值允许为空；筛选已有字段，不隐含语言识别、质量评分或自动生成标签。
- 原型不扩大正式产品的文件、记录、字节或用户容量限制。

## 此次原型展示的建议口径

| 情况 | 原型行为 |
| --- | --- |
| 多条件 | 所有条件同时满足；问题、期望输出及已有 Metadata 字段支持包含、等于、为空、非空。默认无条件。 |
| 空值 | 缺失、null 和空白字符串按空处理；数值 0、布尔 false 不按空处理。Metadata 按现有字符串值演示。 |
| 按比例 | 以筛选后数量为分母，向下取整；不足 1 条时提示且不允许空确认。 |
| 候选不足 | 显示目标与实际数量，取全部可用候选，提示不足。 |
| 人工调整 | 可排除选中记录，也可在“全部候选”补选；不自动补足被排除的数量。 |
| 固定预览 | 分页、搜索和确认不重新抽样；相同来源/规则/种子可复现；明确“重新抽样”才更换种子。 |
| 与已有草稿重叠 | 显示重叠数量，确认时跳过相同来源身份；只报告实际新增量。 |
| 草稿变化 | 保留结果，先核对草稿，再明确重新确认；不会覆盖已有记录。 |
| 追溯 | 发布后的“来源与修改”中折叠显示选取规则、种子、数量；实际身份清单保留在 Mock 选取记录中。 |

这些新增口径用于体验和确认，不自动成为正式 PRD。日期范围、正则、嵌套条件、分层配额、模板、模型选样及语义去重留待后续。
