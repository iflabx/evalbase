## 修复内容

- **上传超限**：原代码对 HTTP 请求流直接 destroy，真实请求无法收到 413。原生 HTTP 的 CSV/JSON/JSONL × Content-Length/chunked 六例先 RED（socket hang up），修复后全部 GREEN。借用的 HTTP 流保持可回复；自有 Worker 流在检测超限时同步 unpipe/destroy，避免等 Promise catch 才停止同步生产。MinIO SDK 的 multipart pipe 不传播输入错误，失败时先结束部分 staging、等待存储客户端结束、再清理，避免无期限等待。十项回归另含精确 50,000,000 byte 存储、后续小上传、异步与同步生产流取消及暂存清理；同步生产用例先 RED（100 块全生产），修复后 GREEN。
- **分页**：仍先完整解析成员并检查数量、哈希与跨测试集引用，再筛选、分页；临时表只保留成员 ID/序号，最后读取当前页正文。来源/Metadata 选项仍来自完整版本，在搜索、空结果、页尾仍完整。嵌套查询计划显示 Checkpoint 引用校验逐条查找成本明显，改为完整成员引用物化后检查，保留原 fail-closed 条件；没有修改共享数据库全局配置。JIT on/off 三次诊断没有显著差异，没有用关闭 JIT 代替修复。
- **CSV 缓存**：每次先授权、检查可见状态并持有原有删除锁，统一解析当前及可读父成员；数据库内对实际正文、成员、来源状态、父状态及切断事实生成证据指纹。正确命中时直接返回原 CSV，不再把整版正文送到 Node 重建 diff 和字段作者。缓存内部版本换为 2，公开 CSV 字节、排序、转义与公式保护不变。手工损坏正文但未改 content_hash 仍能使缓存失效；损坏数量/跨集合成员仍拒绝，删除期间不返回旧内容。

没有增加 API、数据表、UI、依赖或容量；前端和冻结原型未改。原路由全部 reused。
