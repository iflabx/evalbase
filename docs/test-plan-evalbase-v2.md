# EvalBase v2 测试与验收计划

- 日期：2026-09-28；状态：Draft，尚未执行 v2 功能测试。
- 需求依据：[PRD](PRD-evalbase-v2.md)；技术依据：[架构](architecture/evalbase-v2-architecture.md)。
- 本文定义实现的验证条件；Ticket 与执行批次见 [Implementation Spec](../.scratch/evalbase-v2/spec.md)，不代表批准合并或部署。

## 1. 环境和测试数据

使用隔离数据库、对象存储前缀及独立测试进程。准备管理员 A（不加入任何项目）、编辑者 E1/E2、查看者 V、未加入项目用户 N；项目 P/Q、测试集 S、父版本 v1/v2、分别对应的草稿 D1/D2，以及两个独立新建测试集草稿。旧数据夹具来自匿名合成的 v1 结构，覆盖 legacy、Checkpoint、Delta、空 Metadata 值和历史未知作者。

双人验证使用两个独立浏览器上下文或不同浏览器配置文件。同浏览器普通标签页共享 cookie，不能作为两账号隔离证据。另测同账号多标签页聚合在线头像。测试中仅使用合成邮箱、密码及数据。

每次执行记录精确 Git HEAD、迁移版本、环境配置、浏览器版本、测试命令、结果和失败证据。原型 mock 演示不能算正式服务验收。

## 2. 需求追踪矩阵

| 需求 | 测试组 | 通过标准 |
| --- | --- | --- |
| V2-FR-01 账号与初始化 | AUTH | 首位管理员唯一、登录登出和注册有效、错误保留输入 |
| V2-FR-02 权限与邀请 | ACL/INV | 管理员全局管理，普通用户只访问授权项目 |
| V2-FR-03 设置与信息 | PROFILE/INV | 名称颜色可保存，邀请可见且仅本人接受 |
| V2-FR-04 共享草稿 | DRAFT | 同父共享、异父隔离、退出恢复及删除正确 |
| V2-FR-05 草稿编辑 | EDIT | 全页、分页选择、Metadata 与来源符合合同 |
| V2-FR-06 实时协作 | COLLAB | 不丢更新、冲突可解决、在线与作者含义分离 |
| V2-FR-07 唯一发布 | PUB | 同一草稿任何并发重试只生成一个正式版本 |
| V2-FR-08 变更归属 | TRACE | 修改者可信，发布者分离，历史未知不伪造 |
| V2-FR-09 回收与删除 | DELETE | 暂停/恢复正确，永久删除不泄漏已删内容 |
| V2-FR-10 升级兼容 | UPGRADE/REG | 旧数据身份保持、存储协议和导出不回归 |

## 3. 服务端集成用例

### AUTH：账号与会话

- AUTH-01：空数据库首次访问显示管理员注册；并发提交两个初始化请求，只有一个管理员及初始化结果。重启后入口保持关闭，直接调用端点也拒绝。
- AUTH-02：账号注册只填邮箱、密码和确认密码所需的原型字段，不要求邮箱验证；注册不能赋予 admin。邮箱首尾空格及大小写按 PRD 规范处理，规范化重复邮箱拒绝。
- AUTH-03：错误邮箱、短密码、确认密码不一致时保留表单；输入时显示密码规则及一致性提示。服务端仍独立校验密码。
- AUTH-04：登录、刷新、会话过期、登出、旧 cookie 重放；登出后实时连接不能继续取得内容。无空请求自动登录，无明文密码或 token 持久化。
- AUTH-05：Origin/CSRF、cookie 配置和未登录 API 拒绝符合部署方式；拒绝响应不含密码哈希及内部异常。

### ACL / INV：权限与邀请

- ACL-01：不在项目成员表的 A 可创建、查看和管理 P/Q，包括邀请、调整角色、回收、恢复、永久删除。
- ACL-02：E1 可编辑授权项目、发布和删除共享草稿，但不能创建项目、管理成员或执行管理删除。V 只读正式内容，不显示草稿入口，直接请求草稿列表/内容/编辑位置及订阅均拒绝；N 只看自己的资料和信息，无项目内容。
- ACL-03：替换 URL、body、查询参数中的 project/test-set/version/draft/record ID，验证跨项目访问、下载、来源和订阅均拒绝；不存在固定 project_demo 授权。
- ACL-04：写入与降权/移除并发，断言事务顺序与架构一致；撤权后重连和后续写入拒绝；降为查看者后草稿读取与订阅也拒绝，正式内容仍按权限可读。
- INV-01：A 邀请已有账号；对方在设置→信息接受，项目出现且权限正确；重复接受无重复成员。
- INV-02：邀请未注册邮箱时提示先注册且不创建邀请；注册后管理员重新邀请，只有匹配目标账号的登录用户可接受。不要求邮箱验证码，也不允许另一账号提交邮箱参数代领。
- INV-03：过期、撤销、重复邀请、过期后重邀、邀请角色变化；接受与撤销/到期竞态只有一致的终态。
- INV-04：普通用户看不到他人的信息，不能自行创建邀请或修改角色；邀请中不包含管理员权限选项。

### DRAFT / EDIT：共享编辑

- DRAFT-01：同时从同父版本创建草稿，返回同一活动 draft ID；D1/D2 属于不同父版本时完全隔离。
- DRAFT-02：两个新建测试集草稿独立列出；未命名也可识别创建者及更新时间，不误覆盖。草稿排在正式测试集前，同表的全部／草稿／已发布筛选与统一 10 行分页正确，搜索无结果可清除；查看者只见正式测试集。
- DRAFT-03：名称、用途、问题、期望输出与整体 Metadata 离焦保存；退出、切换记录和发布等待未完成写入，重新进入恢复服务端数据；另一用户看到更新者。保存期间其他字段仍可编辑，旧响应不覆盖新输入；网络失败保留输入与重试入口，不能关闭并声称成功。
- DRAFT-04：删除共享草稿后，其他标签页失效；迟到请求、重连和缓存不得使草稿复活。已发布草稿不能再次编辑；发布中删除请求拒绝，不得与发布任务互相覆盖。
- EDIT-01：整行点击打开右侧编辑；checkbox、行内动作等交互不误触；Metadata 在侧栏直接编辑。
- EDIT-02：Metadata 非空键、大小写不重复；值为空字符串可保存发布并重新读回。只填值但无键拒绝；完整空白占位行不写入；已有空值不被过滤。
- EDIT-03：来源搜索与分页，本页文件／全部搜索文件、本页记录／全部搜索记录标签清晰；文件区预先显示 5 个上限及剩余额度，单选与批量超限均阻止而可取消已选。跨页选择 500 条后排除 3 条应准确导入 497 条；筛选变化不偷换选择范围。重复来源 ID 去重，相同文本不同来源不擅自合并。
- EDIT-04：覆盖 10,000 条记录及文件/草稿字节容量边界，边界内成功、超出拒绝且保留可恢复输入；继承记录不要求全部加载到浏览器才能编辑。
- EDIT-05：测试集名称未填、重名或记录数为零可保留草稿，但不能发布；修复后可继续。问题为空和重复内容仍仅提示，不能被新增必填校验阻断。

### COLLAB：并发、在线与断线

用事务屏障或可控请求暂停制造竞态，避免依赖偶然的 sleep 顺序。

- COLLAB-01：E1/E2 同时改同一记录不同字段，均保存成功且最终两项存在；不能用全草稿 revision 锁误判冲突。
- COLLAB-02：两人改同字段，后提交者看到远端值、修改者及自己的保留输入；选择远端或重新提交本地均得到明确结果。
- COLLAB-03：连续产生多个字段冲突，每个都可查看解决；不能只保留最后一个。Metadata 两个键同时编辑按整字段冲突策略处理。
- COLLAB-04：删除与编辑同一记录，行 revision 保证不静默吞掉已经保存的新值；返回明确冲突或已删除状态。
- COLLAB-05：断网编辑、重连、重复/乱序事件、游标过期、Web 重启；重取快照后保留本地输入并检测冲突，不整页覆盖别人的工作。
- COLLAB-06：同账号两标签页只显示一个在线头像；关闭一页仍在线，全部失联超过 15 秒后移除。编辑头像只出现在对应草稿/记录/字段。
- COLLAB-07：两个独立账号在正常本机测试网络下，已确认保存内容应在 2 秒内出现在另一浏览器；记录实测延迟。该值为本期验证目标，非尚未测量的性能承诺。
- COLLAB-08：接收事件期间登出、被移除或父项目回收；后续事件不泄漏正文，客户端退出编辑状态。

### PUB：只生成一个版本

- PUB-01：E1/E2 对同一已保存 revision 同时发布，使用不同幂等键；只有一个正式版本、一个版本号消耗，双方取得相同 version ID。
- PUB-02：同人双击、不同键重试、请求超时后重试、发布成功响应丢失后重试，结果仍相同。
- PUB-03：在冻结后、对象写入后、数据库提交前、提交后响应前分别注入故障并重启；只有未发布或一个可完整读取的已发布版本，不出现半成品或第二版本。故障恢复到 editing 后，旧 Worker 迟到提交必须因发布代次失效而拒绝。
- PUB-04：编辑与发布交错，冻结 revision 前已确认的数据全部包含；之后写入被拒绝且本地输入保留。发起者有未保存数据/未解决冲突时前端阻止发布。
- PUB-05：发布中撤权、父版本删除，按事务顺序只有一个合法结果；失败不消耗正式版本号、不遗留公开测试集。
- PUB-06：旧 actor 级幂等机制继续正常，新 draft 级唯一约束可直接从数据库数量和返回结果验证，不能仅看按钮禁用。

### TRACE / DELETE / UPGRADE

- TRACE-01：伪造修改者字段不能改变服务端身份；字段作者、记录加入者和版本发布者可不同。派生草稿中未修改的继承记录及字段不显示最近修改信息；保存字段修改后，仅对应行及字段显示本草稿修改者，父版本正式归属保留。账号改名后历史页面显示当前名称，稳定用户 ID 和归属不变，不要求历史名称快照。
- TRACE-02：旧记录显示“未记录”；净修改后改回父值不伪造正式变更；继承、新增、修改、删除的来源信息准确。
- DELETE-01：回收父版本/测试集使草稿暂停，恢复后可继续；权限不足者不能通过草稿读出回收内容。
- DELETE-02：永久删除直接父内容终止相关草稿并清理正文/暂存/缓存；仍可读后代与无关草稿不受损。旧事件/重连不能复活正文。
- DELETE-03：仅对合成数据执行永久删除；人工浏览器操作遵循执行时确认要求，不能对正式用户数据做破坏性验收。
- UPGRADE-01：旧 Owner 由受控迁移绑定邮箱，ID/哈希/归属保留；重复邮箱和不明确归属停止迁移；公开注册不能认领旧数据。
- UPGRADE-02：迁移可重试，服务重启不覆盖密码、不自动插入生产测试账号；备份恢复演练验证旧版本可读。
- REG-01：legacy、Checkpoint、Delta 读取和 CSV 导出与原合同一致；覆盖阈值建 Checkpoint、依赖切断、重启恢复。作者数据不改变内容哈希和 CSV 列。
- REG-02：上传确认、映射、原始数据管理、来源检索、容量检查和回收站保留现有针对性回归测试。界面导航、类型筛选、列表标签及关联入口使用「原始数据」与「默认收纳区」，筛选对象和文件归属不变。

## 4. 浏览器人工验收批次

按 [Implementation Spec §2、§5](../.scratch/evalbase-v2/spec.md) 的三个功能批次执行：A 合并 V2-01/02 验收账号与项目入口；B 验收 V2-03 完整草稿工作流；C 验收 V2-04 实时协作及最终受影响闭环。V2-01 不单独要求人工 checkpoint，仍须完成本 Ticket 的自动化、复审和提交证据。

每批提供固定 HEAD、访问地址、测试账号、数据说明、3–8 个主要步骤和预期结果。批次通过后按 Spec 回收本批独占资源，保留证据；下一批使用可重建夹具。功能测试分配由各 Ticket 引用本计划，不额外增加纯测试 Ticket。

## 5. 完成条件与报告

批次 C 的 Owner 后续决定覆盖冻结原型中的草稿手动保存和状态卡、测试集列表筛选分页、资料选择提示及版本页操作收纳；其余部分继续严格对齐。前端 UI 对齐是各 checkpoint 的必验项，按 [PRD §7](PRD-evalbase-v2.md#7-视觉与实现边界) 对照冻结原型检查布局、导航、字段与控件顺序、文案、表格/侧栏/弹窗、状态及交互，并核对 frontend-v1 样式。记录页面证据和已确认差异；未经确认的 UI 偏离修正后才能通过，不以功能可用代替对齐。

服务端权限与竞态用例必须提供自动化证据；浏览器覆盖真实服务端和两独立账号，附关键截图及数据断言。视觉复验对照 frontend-v1 和冻结原型，覆盖登录、设置、信息、草稿、来源与修改、空态、错误态及不同窗口宽度。

最终报告列出通过、失败、未执行和已知限制。未执行项不能写成通过；纯原型结果不能替代实现测试。文档确认、功能验收、代码合并与部署分别记录，本计划不自动授权后两者。

## 6. 架构与性能优化验证

按 [性能优化规格](../.scratch/architecture-performance/spec.md) 与 [实施 Ticket](../.scratch/architecture-performance/issues/01-architecture-performance.md) 验证。对同一确定性 10,000 条合成数据及隔离资源执行至少三次热运行和 10 个并发会话，记录原始结果、p50/p95、错误/冲突、SQL 次数、空闲领取次数和进程内存；未控制冷缓存则不报告冷启动收益。既有 COLLAB/PUB/DELETE/REG 与容量合同继续成立。Owner 验收库只保留一个项目和管理员/编辑两个账号，自动化夹具使用另库/桶。

性能优化的实际数据、基线失败集合、编码固定字节、并发上传/批量回滚及浏览器结果见 [优化结果报告](research/architecture-performance-optimization-2026-10-02.md) 和 PERF-01 Comments；编码线程必须覆盖生产编译路径及错误后队列释放。

针对 2/3 个独立用户并发使用、最大字节容量、重操作干扰及分层瓶颈定位的扩展范围见 [性能与瓶颈测试方案](test-plan-performance.md)。本轮执行已结束，正常六轮和固定到达探针完成；超限上传失败，重操作出现慢读取，随后触发内存保护停止，未整体通过。实际覆盖及未执行项见 [验证结果](research/performance-validation-2026-10-02.md)。没有运行 5/10 人、两小时稳定运行、断线和重启恢复；Owner 验收仍 pending。
