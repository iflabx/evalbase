## 1. 本轮完整目标

1. 将原型“筛选与选取”落到正式草稿添加资料页面：条件、全部/随机、固定预览、人工调整、确认加入与选取来源记录。

## 3. SEL-01 筛选与选取

### 3.1 页面与条件

- 草稿“添加资料”依次显示来源文件范围、筛选与选取配置、固定预览、确认加入；选取页不改变现有草稿内容，确认才提交。
- 文件可搜索与分页，最多 5 个；候选范围是选中文件的所有有效、已整理记录，最多 10,000 条和 100,000,000 原始 bytes。继承的父版本记录不参与此次抽取。
- 条件全部同时满足，字段为问题、期望输出或已发现的 Metadata 字段；操作符为包含、等于、为空、不为空。比较去除首尾空白；包含/等于不区分大小写；缺失 Metadata 项按空值处理。禁止任意查询表达式。
- “全部选取”说明为“选取筛选后的全部记录；未设置筛选条件时选取全部记录”。
- “随机抽取”支持数量或比例，数量 1–10,000，比例大于 0 且不大于 100%；比例分母为过滤后的候选数，向下取整。数量超过候选数时取全部并提示，不足一条时禁止确认。
- 数量与比例分别记住输入，初值 500 条 / 5%；种子可填写，空值由服务器生成并回显。

### 3.2 固定预览与人工调整

- 生成预览冻结文件及解析视图、规则、种子、算法版本、候选身份、抽中身份和草稿 revision。相同输入、规则、种子得到相同身份集合；正式算法不沿用 Mock 算法保证。
- 预览分页每页 20 条；分页、预览内搜索、确认不重新抽取。点击整行、Enter/空格可查看完整内容，复用现有弹层；复选框独立操作。
- 可以排除抽中记录、从全部候选补选；补选必须属于已冻结且符合条件的候选。排除不自动补足。恢复原结果撤销人工调整但保留种子；重新抽一批换种子。
- 文件、条件、方式、数量、比例或种子修改后，立即标记旧预览失效并禁用确认；旧结果保留供对照，更新预览后重新计算，输入不丢失焦点。
- 确认区在结果表上方显示已选、已在草稿、本次新增；新增为零禁止确认且不产生空历史。
- 生成后草稿发生变化，保留预览并要求核对当前草稿、明确再次确认；不能默默覆盖基准 revision。来源失效必须重新生成预览。
- 确认原子写入，按 assetId + ordinal 去重；解析视图单独冻结用于复现，映射变化不产生新的来源身份；不同来源的同文记录不合并。失败保留预览和选择。
- 成功保存选取规则与最终身份摘要，在草稿及正式来源与修改页折叠展示；不把未接受预览计入正式来源。

## 5. AI-02 原件保存与整理

- 保留既有上传映射确认流程，增加“先保存原文件，稍后整理”；仍需要用户确认，确认前不产生可见资产。
- 继续校验格式、编码、语法、文件大小与记录上限。稍后整理只延后字段映射，不接受无法解析的伪记录。
- 未整理文件在文件列表和详情明确标识；可以查看源字段、原始内容、整理字段和提交处理，不能作为已经映射好的问题记录直接加入草稿。
- 整理使用现有问题/期望输出/Metadata 拖拽映射样式；保存创建可用解析映射，不改变原始字节或来源身份。并发整理/预览时使用明确解析视图，不混用不同映射。
- 同字节上传去重、确认幂等与取消语义保留。派生处理文件有自己的资产和来源身份，不覆盖原件。

## 6. AI-03 清洗、改写、扩充

### 6.1 任务配置

- 输入表直接展示问题、期望输出和 Metadata 摘要及完整查看入口；配置页只显示输入选择及处理要求，通过“返回处理任务”进入任务列表。
- 从原始文件或测试集版本/草稿选择明确记录范围，选择清洗、改写或扩充，填写要求与字段保护；可先处理小样本，再创建全量任务。
- 清洗中的字段映射、空白整理、空值/重复检测优先使用确定规则；内容语义改写、抽取、翻译和扩充才使用模型。重复检测不擅自删除来源不同的记录。
- 默认保护期望输出及 Metadata；用户明确选择允许修改的字段才能改变它们。扩充说明数量及生成方向，仍遵守当前三字段结构。
- “测试类型”采用可填写的任务要求/已有 Metadata，不硬编码安全、意图或实体分类体系；技能以版本化配方实现，无脚本执行入口。

### 6.2 运行与结果

- 任务列表、配置、结果为同一路由的独立页面状态，由既有来源/运行参数区分；结果列表直接展示问题、期望输出、Metadata 摘要及变化，点击记录查看完整原文/结果对比，返回处理任务后不同时展示输入选择。2026-10-09 确认的紧凑列表与按需详情覆盖此前默认并排铺开全部字段的布局。
- 提交固定输入对象、记录范围、内容哈希、目标草稿与基准修订、提示词版本、模型配置、操作人和预算。请求重试返回同一任务；一轮聊天不承担逐行任务调度。
- 后台分批执行，显示等待、处理中、部分成功、已完成、失败、已取消及真实进度；刷新或关闭面板不丢已入队任务。
- 每批保留成功产物，有限重试失败批次；取消停止后续批次。不能承诺取消请求一定终止远端已经开始的推理。
- 每条输出必须匹配输入来源、允许字段和结构；受保护字段采用原值，不让模型重写。无效、缺失、重复/超量输出分别标记，不能静默视为全部成功。
- 预览显示原文/结果、来源和校验情况，可选择全部有效结果或部分结果；结构正确不等于语义正确，保留人工选择。
- 可以将接受结果保存为派生原始文件，或加入新建/指定草稿；针对草稿已有记录的改写，按字段修订确认替换。扩充追加新记录。
- 保存派生资料及应用草稿均提交去重；同操作同参数返回原结果，不同参数拒绝。保留真实来源和模型处理记录，不能冒充“手工新增”。
- 模型输入、结果和聊天历史必须遵守权限、回收/永久删除和对象清理规则；删除后不得从这些副本恢复已删除的独占正文。

## 7. AI-04 项目助手

本节为当前整改目标，实施状态见 [台账](../.scratch/assistant-optimization/spec.md)。通用数据任务沿用 §6 的三字段、来源和字段保护合同；不得将安全风险分类或某个样例数量设为产品默认。

### 7.1 用户目标与交互

- 用户可以用简短自然语言查询资料、筛选记录、清洗、改写、扩写、提取信息和创建测试集。当前页面、已有要求、成果及已选背景用于理解目标；仅在来源、允许修改字段或目标有实质歧义时澄清，不要求用户填写内部 ID 或工具参数。
- 简单操作不强制先展示计划。复杂任务保留可理解的业务步骤；“先给方案”只查询和规划，“开始执行”沿最新方案执行；初始请求已明确要求执行时不重复询问开工。
- 助手可以先查看资料和背景，再选择或组合筛选、清洗、改写、扩写、提取等已有能力；用户无需逐步指定工具或处理顺序。根据中间结果可调整后续方法，仍遵守生效目标、允许修改字段和预算；目标或业务取舍存在实质变化时才向用户澄清。
- 同一任务在同一会话中推进到候选审核，后台完成后自动继续已授权步骤。候选待审核不等于已采用或已发布；两项操作仍需用户点击固定确认卡。
- 当前页面对象和任务对象分别显示。切换页面不改变进行中的任务范围；已保存的成果和失败位置可在刷新、重新打开会话后继续读取。

### 7.2 当前生效要求

- 来源范围、目标数量及其新增/最终总数含义、允许修改字段、期望输出规则、Metadata 分类及选用背景明确分开。标签规则只约束指定字段，不因类别名称相似而跨字段套用。
- 每项要求只有一个生效版本。文字展示与执行规则一致；用户替换或撤销要求后不累加失效限制。服务端负责数量和配额计算，不要求模型在多处维护同一数字。
- 执行前核对可证的规则冲突，包括配额总数、允许类别、受保护字段与要求是否相容。模型自行提出的参数错误由助手修正；用户明确指定的业务矛盾才需要澄清，不擅自删约束或改目标。
- 用户更正使受影响的后续步骤和待确认操作失效，保留仍可复用的成果。无法证明成果适用时保留它并重新核对，不能默认沿用或删除；说明哪些工作需要恢复。正在处理的固定输入不能原地换要求；旧结果只按旧要求标识，不作为新目标已完成的证据。

### 7.3 步骤完成与恢复

- 每个执行步骤须对应明确的来源、范围、允许动作和完成条件；后续步骤使用实际前序成果。一次同名工具成功不能替代这些条件，错误来源或只读样例不能完成全量处理步骤。
- 处理提交、处理中、处理终态、结构核对、内容审核、采用和发布分别呈现。确定性的分页、计数、选取、合并和回执核对由服务端完成；需要语义理解或调整方法时再调用模型。
- 保留有界模型回合和后台批处理。预算耗尽时保存进度；有进展且仍在原授权内可续做，无进展或达到限额时说明原因并保留成果。后台等待不反复消耗模型查询回合。
- 重试先核对回执，只继续未完成工作。模型总结失败不抹掉已经成功的数据操作；失效回合不能覆盖新要求或重复提交。
- 错误显示失败步骤、具体原因、已保留成果及恢复动作。规则错误、数据质量问题、处理失败与模型响应失败分别解释；不能只提示“补充要求或重试”。

### 7.4 审核与确认

- 全量结果核对数量、来源、字段保护、空值、重复和用户指定分类。结构通过不代表语义通过；分类、改写和扩写内容须可逐条对照、选择及按授权调整。测试中人工纠错单独记录。
- 整任务采用须核对当前完整目标；用户明确选择部分成果时显示部分范围，不把它记为全任务完成。沿用同一业务服务的确认、修订、来源、容量和幂等规则。
- 采用和发布确认绑定当前用户、项目、任务修订、固定内容及目标、有效期和操作 ID。用户修改要求或草稿变化后重新核对；模型文本或自动事件不能替代确认。
- 成果入口展示实际资料、草稿或版本。只有用户目标要求的动作取得真实回执，才显示该任务完成；仅要求候选的任务可以结束在内容待审核，不冒称采用或发布。

### 7.5 既有会话与安全能力

- 继续使用当前个人会话与 PDF/MD/TXT 背景，容量、提取和删除规则见 [背景合同](assistant-optimization.md#3-背景文档与短请求)。附件不是跨会话知识库，不授予操作权限。
- 用户仅管理自己的会话。重命名为去除首尾空白后的 1–80 字，不被自动命名覆盖。删除须确认，停止未完成任务并删除消息、背景和未确认操作；已创建的资料、草稿和正式版本保留。失败保留输入；删除最后会话回到新会话空态。
- 消息提交即时反馈，不清空后来输入；读取历史不强制滚动到底部。界面沿用 donor 样式，在现有助手工作区集中显示当前生效要求、实际阶段、已有成果及需要用户决定的事项，历史工具明细折叠。正常推进、后台等待、待审核和失败分别反馈；用户可对照来源查看候选，并在同一会话提出局部调整。
- 模型只能使用当前用户有权访问的业务工具。客户端不提供权威工具历史；原始数据与背景内的指令不能获得额外权限。账号管理、永久删除、任意终端、SQL 和 URL 操作继续排除。
