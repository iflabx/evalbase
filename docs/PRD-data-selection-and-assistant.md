## 1. 本轮完整目标

1. 将原型“筛选与选取”落到正式草稿添加资料页面：条件、全部/随机、固定预览、人工调整、确认加入与选取来源记录。
2. 管理员配置并测试已有兼容模型连接；凭据保留服务端。
3. 原始文件可先确认保存原件，后整理字段及处理；原件不可覆盖。
4. 在原始数据、版本/草稿中提交清洗、改写、扩充任务；后台分批运行、可查看进度/结果、取消与重试，选择结果保存为派生资料或应用到草稿。
5. 项目助手以自然语言查询项目、创建草稿、提出选取/处理操作、提交处理、查看结果及按用户确认应用、发布；页面和聊天使用同一业务服务。
6. 保留多人协作、字段冲突、一次草稿一次发布；新增操作具有结果可核对的重试语义。

正式 UI 在 frontend-v3 开发，字体、颜色、间距、按钮、卡片、弹层、表格和导航直接复用 frontend-v1。选取页面对齐 `96b1868` 的 THROWAWAY-data-selection-vnext.html；智能体部分按本轮授权直接开发，不另改原型。frontend-v1 与已有原型保持只读。

## 3. SEL-01 筛选与选取

### 3.1 页面与条件

- 草稿“添加资料”依次显示来源文件范围、筛选与选取配置、固定预览、确认加入；选取页不改变现有草稿内容，确认才提交。
- 文件可搜索与分页，最多 5 个；候选范围是选中文件的所有有效、已整理记录，最多 10,000 条和 100,000,000 原始 bytes。继承的父版本记录不参与此次抽取。
- 条件全部同时满足，字段为问题、期望输出或已发现的 Metadata 字段；操作符为包含、等于、为空、不为空。比较去除首尾空白；包含/等于不区分大小写；缺失 Metadata 项按空值处理。禁止任意查询表达式。
- “全部选取”说明为“选取筛选后的全部记录；未设置筛选条件时选取全部记录”。
- “随机抽取”支持数量或比例，数量 1–10,000，比例大于 0 且不大于 100%；比例分母为过滤后的候选数，向下取整。数量超过候选数时取全部并提示，不足一条时禁止确认。
- 数量与比例分别记住输入，初值 500 条 / 5%；种子可填写，空值由服务器生成并回显。

### 3.2 固定预览与人工调整

- 生成预览冻结文件及解析视图、规则、种子、算法版本、候选身份、抽中身份和草稿 revision。相同输入、规则、种子得到相同身份集合；正式算法不沿用 Mock 算法保证。
- 预览分页每页 20 条；分页、预览内搜索、确认不重新抽取。点击整行、Enter/空格可查看完整内容，复用现有弹层；复选框独立操作。
- 可以排除抽中记录、从全部候选补选；补选必须属于已冻结且符合条件的候选。排除不自动补足。恢复原结果撤销人工调整但保留种子；重新抽一批换种子。
- 文件、条件、方式、数量、比例或种子修改后，立即标记旧预览失效并禁用确认；旧结果保留供对照，更新预览后重新计算，输入不丢失焦点。
- 确认区在结果表上方显示已选、已在草稿、本次新增；新增为零禁止确认且不产生空历史。
- 生成后草稿发生变化，保留预览并要求核对当前草稿、明确再次确认；不能默默覆盖基准 revision。来源失效必须重新生成预览。
- 确认原子写入，按 assetId + ordinal 去重；解析视图单独冻结用于复现，映射变化不产生新的来源身份；不同来源的同文记录不合并。失败保留预览和选择。
- 成功保存选取规则与最终身份摘要，在草稿及正式来源与修改页折叠展示；不把未接受预览计入正式来源。

## 4. AI-01 模型连接

- 设置页增加管理员可用的“模型连接”，沿用设置菜单、表单、按钮和反馈样式。
- 第一版一个实例连接：显示名称、兼容服务地址、模型名称、API key、启用状态；可以更新。保留最后连接测试时间/结果，失败显示脱敏错误，禁止伪造可用状态。
- API key 输入后不回显、不写浏览器存储、不放 URL、日志或聊天；服务器加密保存，主密钥通过部署环境提供。缺少主密钥时明确提示部署配置缺失，不能退化明文。
- 模型连接由管理员设定，端点只允许 http/https，拒绝 URL 凭据、片段和请求重定向；成员或模型不能覆盖地址。私有网络部署地址可以由管理员明确配置。
- 同一个连接供短轮助手和批处理使用，分别设置超时、输出量、并发与提示词；不承诺接口兼容就代表全部能力可用。

## 5. AI-02 原件保存与整理

- 保留既有上传映射确认流程，增加“先保存原文件，稍后整理”；仍需要用户确认，确认前不产生可见资产。
- 继续校验格式、编码、语法、文件大小与记录上限。稍后整理只延后字段映射，不接受无法解析的伪记录。
- 未整理文件在文件列表和详情明确标识；可以查看源字段、原始内容、整理字段和提交处理，不能作为已经映射好的问题记录直接加入草稿。
- 整理使用现有问题/期望输出/Metadata 拖拽映射样式；保存创建可用解析映射，不改变原始字节或来源身份。并发整理/预览时使用明确解析视图，不混用不同映射。
- 同字节上传去重、确认幂等与取消语义保留。派生处理文件有自己的资产和来源身份，不覆盖原件。

## 6. AI-03 清洗、改写、扩充

### 6.1 任务配置

- 从原始文件或测试集版本/草稿选择明确记录范围，选择清洗、改写或扩充，填写要求与字段保护；可先处理小样本，再创建全量任务。
- 清洗中的字段映射、空白整理、空值/重复检测优先使用确定规则；内容语义改写、抽取、翻译和扩充才使用模型。重复检测不擅自删除来源不同的记录。
- 默认保护期望输出及 Metadata；用户明确选择允许修改的字段才能改变它们。扩充说明数量及生成方向，仍遵守当前三字段结构。
- “测试类型”采用可填写的任务要求/已有 Metadata，不硬编码安全、意图或实体分类体系；技能以版本化配方实现，无脚本执行入口。

### 6.2 运行与结果

- 提交固定输入对象、记录范围、内容哈希、目标草稿与基准修订、提示词版本、模型配置、操作人和预算。请求重试返回同一任务；一轮聊天不承担逐行任务调度。
- 后台分批执行，显示等待、处理中、部分成功、已完成、失败、已取消及真实进度；刷新或关闭面板不丢已入队任务。
- 每批保留成功产物，有限重试失败批次；取消停止后续批次。不能承诺取消请求一定终止远端已经开始的推理。
- 每条输出必须匹配输入来源、允许字段和结构；受保护字段采用原值，不让模型重写。无效、缺失、重复/超量输出分别标记，不能静默视为全部成功。
- 预览显示原文/结果、来源和校验情况，可选择全部有效结果或部分结果；结构正确不等于语义正确，保留人工选择。
- 可以将接受结果保存为派生原始文件，或加入新建/指定草稿；针对草稿已有记录的改写，按字段修订确认替换。扩充追加新记录。
- 保存派生资料及应用草稿均提交去重；同操作同参数返回原结果，不同参数拒绝。保留真实来源和模型处理记录，不能冒充“手工新增”。
- 模型输入、结果和聊天历史必须遵守权限、回收/永久删除和对象清理规则；删除后不得从这些副本恢复已删除的独占正文。

## 7. AI-04 项目助手

- 当前项目提供助手面板，展示当前上下文、消息、任务进度、操作结果和页面链接；使用 donor 组件，不引入另一种聊天视觉体系。
- 使用 AI SDK ToolLoopAgent 与明确 provider 模型对象。会话和回合服务端保存；浏览器只提交新消息及明确操作，不提供权威工具历史。
- 2026-10-06 Owner 补充：会话选择旁提供“重命名”和“删除会话”。用户仅管理自己的会话；名称去除首尾空白后为 1–80 字，保存后不被自动任务标题覆盖。删除须在确认框再次确认，移除消息、会话背景和未确认操作，停止未完成任务；已经创建的资料、草稿和正式版本保留。失败保留当前会话及输入；删除成功选择剩余会话，没有剩余时回到新会话空态，不自动创建空会话。
- 工具覆盖查询项目/文件/版本、建立草稿、筛选预览、提交处理、读取结果、请求应用及发布。名称歧义或关键参数缺失时询问必要信息。
- 只读查询不逐次确认。范围清楚且在额度内的处理可按明确指令启动；批量应用和发布显示目标、范围及动作卡片，由用户确认。
- 确认绑定当前用户、项目、固定参数/结果摘要、目标与 revision、有效期、一次性操作 ID；服务端消费并提交。聊天里一句模型生成的“已同意”不构成授权。
- 单会话每次只推进一个回合；限制循环步骤、时长和输出。大文件按工具分页/引用读取，不把整个项目装入上下文。
- 连续操作以已授权的当前页面对象、最近确认回执和当前对象状态定位目标。界面显示名称、范围与实际处理进度；未知引用先查询或澄清，不以新建空草稿恢复。会话按创建顺序显示编号，最近更新时间不改变编号。
- 消息提交时即时显示受理过程；响应不清空后来输入的消息。失败保留原消息并可按原提交重试；查看历史时新结果不强制改变阅读位置，停留底部时自动跟随。
- 工具只调业务服务；用户内容及来源中的指令是待处理文本，不能改变工具权限、运行任意代码或自行选择网络地址。
- 完成消息只描述实际成功结果。失败、冲突和中断提供可恢复状态；进程中断后可核对回执并重试，但本轮不承诺任意中间模型步骤透明自动续跑。

## 8. 兼容、体验及验收

- 正式版本不可覆盖，发布继续复用 Delta/Checkpoint 与草稿唯一发布；不改 CSV 既有三字段合同。
- 选择及处理输入/输出继续遵守 5 资产、100,000,000 bytes、10,000 记录等已有边界，超过时给出可调整提示。
- 窄窗口卡片上下排列，表格内部滚动，页面无横向溢出；按钮有明确加载、禁用、错误和键盘状态。
- 手工验收只留下一个易读项目、一个管理员和一个编辑账号；自动化其他身份只存在另一隔离测试库。验收通过后释放专属资源，保存证据。
- 完成标准是 [测试计划](test-plan-data-selection-and-assistant.md) 的每项要求有真实证据、独立复审无 P0/P1、固定 HEAD 隔离环境可用。Owner 人工验收不能由代理代签；本轮不包含合并、推送 GitHub 或正式部署。
