## 1. 权威规则

冻结原型 v5.3 是 EvalBase v1 全部用户可见功能的上限和下限：

- 原型中可见的页面、字段、操作、状态和顺序，正式产品必须提供。
- 原型中没有的 UI、CLI 或其他 Owner 可操作能力，正式产品不得提供。
- 原型中的“预测输出”在正式产品中统一显示为领域词“期望输出”，这是唯一已批准的文案修正。
- 原型的浏览器内存 Mock、示例数据和客户端 parser 不是实现合同。
- 持久化、事务、幂等、容量、安全、来源、原子发布、安全删除和审计等不可见机制可以保留，但不得增加用户步骤。
- HTTP API 也是产品表面：请求字段、响应字段和可调用动作必须恰好支撑冻结原型。旧 API 超出该边界时应在对应 Ticket 中原位收紧或退出公共运行路径，不能仅由前端隐藏。

权威关系依次为：本 PRD、[CONTEXT.md](../CONTEXT.md)、[冻结原型采用记录](./prototypes/solo-workflow-reference-adaptations.md)、[Architecture](./architecture/phase1a-architecture.md)、相关 ADR、Implementation Spec 和 Ticket。下游文档不得扩大本 PRD。

## 2. 产品目标

EvalBase v1 让唯一 Owner 在浏览器中完成一个简单闭环：

`选择或新建项目 → 管理数据集中的原始文件 → 映射并确认上传 → 选择和编辑记录 → 创建测试集版本 → 查看版本、来源和修改 → 下载 → 回收或永久删除`

目标：

1. 以项目隔离不同领域或方向的数据。
2. 以数据集归类原始文件，不改变原始内容。
3. 以统一三字段视图浏览 CSV、JSON 和 JSONL。
4. 以不可变版本保存测试集的每次修改和真实父子关系。
5. 让每条测试记录能追到来源文件、原始记录或手工新增事实。
6. 让 Owner 直接下载当前选中版本的数据与来源。

## 3. 用户和运行边界

唯一真实用户是 Project Owner / Sole Developer。应用没有登录页、登录按钮、凭据字段、成员、角色、审批或共享功能。服务端可以非交互式绑定唯一 Owner 身份并实施项目隔离。

当前只允许：

- VPN 内已批准的远程非生产服务器；
- 合成数据；
- 公开且许可清晰的数据；
- 已确认完全去标识的非敏感数据。

当前禁止生产部署、公网开放、真实敏感数据、客户数据、生产 Trace、秘密凭据、多人协作、外部共享、备份承诺、RPO、RTO 和 SLA。

## 4. 页面与导航

### 4.1 项目首页

应用打开后直接进入项目列表，不经过登录。

项目列表支持：

- 显示名称、数据集数量、测试集数量和最近更新时间；
- 名称/说明搜索；
- 10 条分页；
- 新建项目，仅填写名称和可选说明；
- 打开项目。

新项目自动创建固定“未整理”数据集。项目不支持重命名、删除、设置、成员或跨项目引用。

### 4.2 项目内导航

进入项目后，侧栏显示当前项目名称，并只显示两个子入口：

- 数据集；
- 测试集。

项目名称处可切换到其他项目或新建项目。切换项目时不保留另一个项目的具体对象选择。

### 4.3 数据集首页

“数据集”是资料集合的用户界面名称，与“测试集”不是同一概念。

列表显示名称、类型、文件数、统一记录数、状态、最近更新和“查看”，并提供：

- 名称/说明搜索；
- 数据集/系统数据集筛选；
- 有文件/空数据集筛选；
- 更新时间升降序；
- 10 条分页；
- 新建数据集，仅填写名称和可选说明；
- 上传文件，首页默认目标为“未整理”。

数据集不可重命名、不可删除、不可嵌套。首页没有右侧详情面板。

### 4.4 数据集详情

详情页在“文件”和“全部记录”之间切换。

文件页：

- 只按文件名搜索；
- 显示名称、格式、大小、记录数、上传时间、状态和操作；
- 单击行只改变选中样式，不显示右侧详情面板；
- 点击“查看”进入单文件统一记录页；
- 点击“移动”将文件移到当前项目的另一个数据集。

全部记录页跨本数据集文件分页显示序号、来源文件、问题、期望输出和 Metadata。单文件页显示序号、问题、期望输出和 Metadata。点序号在当前页面查看完整记录；Metadata 默认显示前两项“字段：值”，可原处展开其余项；两页均可选择紧凑、适中或展开行高，刷新后回到紧凑。

单文件可在当前页面查看只读原始内容。超过 1,000,000 bytes 时只显示开头的有效文本边界和明确的截断提示；日常流程不提供原始内容编辑、整文件浏览器缓冲或额外下载动作。

### 4.5 测试集首页和版本页

测试集列表显示名称、当前版本、记录数、来源、状态、更新时间和“查看”；每行“查看”右侧的垃圾桶图标只用于将整个测试集移入回收站。它支持搜索和分页，页头提供新建测试集与回收站。

版本页显示：

- 当前版本摘要：父版本、创建时间、记录数、用途、来源和本版本修改；
- 提示性数据核对：问题未填写、完全重复和来源已记录；
- 全部历史版本的横向父子关系图；
- 当前版本记录搜索、分页、详情和紧凑/适中/展开行高；
- 当前版本记录的固定筛选：来源文件、问题是否填写、原始资料/手工新增、Metadata 字段和值包含；
- 查看来源与修改；
- 下载 CSV；
- 下载数据与溯源；
- 基于当前版本继续创建或创建分支；
- 版本或测试集删除入口。

数据核对只提示，不阻止创建或下载。

## 5. 功能需求

### FR-01 项目工作区

1. 项目可创建、列出、搜索、分页、打开和切换。
2. 每个项目独立拥有数据集、文件、测试集和回收站内容。
3. 跨项目对象 ID 不泄漏其他项目内容。
4. 项目没有重命名、删除、成员、设置或共享能力。

### FR-02 数据集和文件

1. 每个项目恰有一个固定“未整理”；它不可重命名、删除或重复创建。
2. 普通数据集是浅层容器，可创建但不可重命名或删除。
3. 一个文件同一时刻只属于一个数据集。
4. 文件移动只改变归类，不改变资产 ID、字节、哈希、映射、来源或原始记录位置。
5. 数据集列表和详情严格使用第 4 节规定的列、搜索、筛选、排序、分页、记录详情和行高。

### FR-03 两步确认上传

1. Owner 可一次或连续选择多个 CSV、JSON 或 JSONL，并选择当前项目中的目标数据集。
2. 系统逐文件流式接收和自动解析；用户不操作编码、分隔符、表头、JSON 路径或类型配置工作台。
3. 第二步把带样例值的原始字段卡拖至“问题”“期望输出”或“Metadata”目标；已分配字段以目标内 chip 和源字段卡的透明勾选显示，不另加字段下拉、Schema 或转换工作台。
4. 每个源字段只能保留一个映射；问题和期望输出各最多映射一个源字段，多个字段可进入 Metadata，并保留各自原始字段显示名和值。
5. 页面显示真实记录数、可定位解析问题和前几条映射预览。
6. 完成全部文件映射后统一确认保存；关闭弹窗取消尚未保存的批次。
7. 确认前不产生日常可见资产；失败、取消或过期不留下可见半成品。
8. 同一项目内以原始字节 SHA-256 去重：重复文件跳过并提示已有文件/数据集；同名不同内容允许，不同项目允许相同字节。该规则不合并或修改测试记录。
9. 确认、响应丢失和重试不得重复创建资产。
10. 上传表单不要求责任人、用途、许可状态或敏感级别。

### FR-04 统一记录浏览

1. CSV、JSON、JSONL 均按问题、期望输出和结构化 Metadata 浏览。
2. 原始文件字节、字段和值保持不变。
3. 数据集“全部记录”保留来源文件；单文件记录可回到原始内容。
4. 搜索、排序和分页稳定，不重复或遗漏记录；点序号可查看完整记录。
5. 不提供全文搜索、Join、自动去重、记录身份合并或高级查询构建器。

### FR-05 创建测试集 `v1`

1. 用户只填写测试集名称和可选用途。
2. 用户按数据集 → 文件 → 记录选择一个或多个来源；选择页展示真实内容。
3. 编辑页固定显示问题、期望输出和 Metadata，可新增、修改和删除行。
4. Metadata 以可增删的字段和值呈现；同一记录内重复字段名被阻止。界面不要求 JSON Schema、JSON 语法或类型选择步骤。
5. 问题未填写、完全重复和来源数量只产生数据核对提示。
6. 创建成功形成不可变 `v1`；失败不产生半版本或消耗版本标签。
7. 系统自动记录来源和实际增删改，不要求版本说明、逐行原因、Schema、默认版本选择或审批。

### FR-06 派生版本与分支

1. 用户可选择任一完整历史版本作为父版本。
2. 编辑从父版本的全部记录开始，可不添加新数据，也可选择额外数据集、文件或记录。
3. 新版本发布后，父版本和其他历史版本保持不变。
4. 版本标签使用 `vN` 或 `vN-bK`；`publication_order` 只表示发布顺序，父边和 generation 决定图位置。
5. 分支号在测试集内全局唯一且不复用；并发发布不得产生重复标签。
6. 版本图可切换节点、高亮当前祖先路径，并在溢出时提供“适应视图”。
7. 不提供合并、rebase、重命名、改父版本、覆盖历史、归档、默认版本切换或任意两版本比较。

版本记录浏览只支持搜索、分页和以下固定筛选：一个或多个来源文件、问题是否填写、原始资料/手工新增、指定或全部 Metadata 字段的值包含。不同筛选条件同时满足；多选来源文件在来源条件内匹配任一项。已应用条件可逐项移除或清除全部；筛选不保存到 URL、浏览器或服务端。

### FR-07 来源、修改和下载

来源与修改页必须：

1. 显示直接父版本、当前版本、本次未改变/已修改/新增/已移除数量。
2. 显示本次新加入的文件和按需展开的字段映射。
3. 默认显示“本次有变化”，并可切换全部、未改变、已修改、新增和已移除。
4. 支持搜索记录或来源、分页和打开逐条详情。
5. 详情显示当前内容、修改前或移除前内容、来源文件、来源记录和变化字段。
6. 手工新增记录明确显示为手工新增，不伪造原始文件来源。

下载必须绑定当前选中的 version ID：

- “下载 CSV”产生一份数据 CSV；
- “下载数据与溯源”产生同一版本的数据 CSV 和 provenance CSV 两个独立文件；
- 历史和分支版本分别下载，不偷换成最新版本；
- CSV 使用问题、期望输出和 Metadata，正确处理 Unicode、换行、逗号和公式前缀；Metadata 保持字段顺序并以“字段：值”文本呈现。

EvalBase v1 不提供 ZIP、Standard/Full Package、Offline Validator、Delivery Record、`langfuse.csv` 或 Langfuse 导入/同步。

### FR-08 回收站与永久删除

1. 整个测试集只能从测试集列表的垃圾桶图标移入回收站；测试集版本页只提供版本级删除。
2. 叶子版本可以单独移入回收站；中间版本可连同全部后代作为完整分支移入。
3. 回收站按“测试集”与“版本与版本分支”分组显示；整套测试集回收会吸收其已单独回收的版本分支。
4. 恢复整套测试集时，其仍可恢复的版本一并恢复，且不留下孤立的版本分支回收条目；回收/恢复不改写父边、标签、发布顺序、来源或内容。
5. 回收站中的测试集永久删除前必须输入完整测试集名称；版本或版本分支永久删除前必须输入根版本号。输入不匹配时动作不可执行，删除后不可恢复。
6. 中间版本可以选择“删除内容、保留关系”，且必须输入该版本号；后代仍指向墓碑节点，不改挂祖先。
7. 墓碑版本不可浏览、下载或派生，只显示删除时间、保留信息和后代关系。
8. 永久删除的内部依赖检查、共享内容保护、失败恢复和审计不得成为额外治理页面、理由表单或审批流程。

## 6. 不可见实现约束

### 6.1 存储与一致性

- PostgreSQL 保存身份、关系、状态和来源事实；MinIO 保存文件和生成字节。
- 原始字节不可变并记录 SHA-256。
- 对象先 staging 后提交；数据库只引用已提交对象。
- 正常进程/容器重启和重新部署后数据必须保留。
- 本地持久化不是备份。
- 测试集版本始终表现为完整不可变快照；底层允许采用记录级增量与周期检查点，减少少量修改时的重复传输和存储，但不得改变记录内容、顺序、来源与修改事实、分支关系、下载结果、回收与永久删除语义，也不得增加用户操作步骤。

### 6.2 容量

- 单文件最多精确 50,000,000 bytes 和 10,000 条源记录。
- 一次测试集编辑最多涉及 5 个资产、精确 100,000,000 原始 bytes 和 10,000 条源记录。
- 一个正式版本最多 10,000 条记录，内部规范化内容最多精确 100,000,000 bytes。
- 达到边界允许，超过边界阻断并保留可恢复编辑内容。

### 6.3 请求与安全边界

- Web 只绑定 Owner 已批准的非生产地址和端口。
- PostgreSQL、MinIO 和 Worker 不发布宿主机入站端口。
- 服务端非交互式绑定 Owner，校验 Origin/CSRF、项目范围、请求大小和下载范围。
- 用户内容按不可信文本处理；日志、错误和指标不输出原始记录正文或秘密。
- 这些边界不构成生产、安全、隐私、法律或合规批准。

### 6.4 后台编排

解析、候选生成、原子发布、CSV 生成和永久删除可以使用后台作业、租约、幂等键、重试与审计。页面只显示当前动作所需的等待、成功或可恢复错误，不显示 Job、Lease、Candidate、Formal Schema、Delivery 或 correlation ID。

## 7. 状态与关键不变量

- 待确认上传：`receiving → previewable → confirmed`，或进入 failed/cancelled/expired；只有 confirmed 创建数据资产。
- 数据资产确认后不可覆盖；移动只改变数据集归属。
- 测试集版本发布后不可编辑；任何变化创建新版本。
- 版本标签、父版本和 publication order 一经发布不改变、不复用。
- 正常列表与回收站之间可恢复切换；整套测试集恢复同时恢复其被吸收的可恢复版本分支；永久删除后不可恢复。
- 中间版本墓碑保留标签和父边；后代不改挂。
- 同一测试记录在版本间保持稳定内部身份；未改变、修改、新增和移除事实可重建来源页。

## 8. 明确不属于 EvalBase v1

- 登录、密码、SSO、成员、角色、审批、评论、共享或多人协作；
- 高级 parser 配置、任意字段映射、Schema 编辑、Langfuse CSV 或同步；
- 评测执行、模型输出、评分和报告；

## 9. EvalBase v1 验收

Owner 必须通过正式浏览器 UI 完成：

1. 打开项目首页，新建或选择项目。
2. 新建数据集，确认固定“未整理”和列表筛选/排序/分页。
3. 上传至少一个允许范围内的文件，完成两步映射预览并确认。
4. 在文件和全部记录视图浏览，移动一个文件，并查看原始内容。
5. 新建测试集，选择真实记录，在三列表格完成增删改并创建 `v1`。
6. 从当前版本创建线性版本，再从历史版本创建一个分支，确认旧版本未覆盖。
7. 查看版本摘要、数据核对、来源与修改详情。
8. 分别下载数据 CSV，以及数据 CSV + provenance CSV。
9. 回收并恢复一个测试集或叶子版本。
10. 验证中间版本整支回收或墓碑行为，以及回收站按名称或版本号的永久删除确认。

验收不要求直接修改数据库、运行临时修复脚本或理解任何内部对象。

## 10. Definition of Done

- 正式文档、Spec、Test Plan 和 Tickets 与冻结原型 v5.3 无用户行为差异。
