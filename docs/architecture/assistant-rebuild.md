## 1. 决策与实施范围

从当前 main 的独立工作树重建助手入口、通用运行时及业务工具适配；保留账号、资料、共享草稿、版本、处理任务、Worker、PostgreSQL 和 MinIO。新入口不调用旧 executeAssistantTurn，也不把旧规划器包装成一个新框架工具。

正式采用 **Deep Agents TypeScript + LangGraph** 作为重建目标栈，LangChain 承担模型和工具适配；以[收口审查](../research/assistant-rebuild-adoption-review-20261027.md#2-审查方法与证据版本)所列实测版本及当前 lockfile 为起点。首次选择依据和后续证据见 ADR 0015。已完成的最小闭环支持继续正式接入，但不代表原方案同版本整轮门槛或全部业务能力验收通过；[验证方案](../assistant-rebuild-validation-plan.md)保留原门槛和首次结果。后续实际版本/API 变更验证受影响合同，不暗中回落旧编排器，也不自动重开已关闭验证活动。

上游现有通用工具循环、上下文管理和人工中断应优先复用，具体启用项以所锁版本验证为准；不从裸图再手写一套通用 Agent。Deep Agents 官方提供这些通用能力，业务工具仍由应用提供。[官方概览](https://docs.langchain.com/oss/javascript/deepagents/overview)。LangGraph 检查点与跨线程 Store 解决不同持久化需求；本轮需要线程检查点，不默认另建长期记忆库。[官方持久化说明](https://docs.langchain.com/oss/javascript/langgraph/persistence)。

不额外引入 Python 服务、Redis、可视化工作流平台、通用插件市场、向量库或默认多智能体。框架的 shell、真实文件系统、任意网络及委派工具不因默认配置而向项目助手开放；工具注册采用允许清单，并在测试中枚举实际工具集合。不是简单传空配置就假设危险默认能力已关闭。

## 2. 谁负责什么

以下 Module / Interface / Adapter 仅用于说明已有真实调用者之间的分工，不要求新增多层包装类或通用可插拔平台。

| 责任方 | 负责的事实与操作 | 不负责 |
| --- | --- | --- |
| 新通用运行时 | 模型循环、工具派发、对话上下文、必要工作安排、检查点、中断恢复、流事件 | 授予权限、批准采用、判断数据库写入成功、重建另一套处理轮次 |
| 应用执行宿主 | 认证身份与项目绑定、单任务执行归属、停止令牌、预算计量、确认入口、运行时与作业的持久关联 | 重新理解每句话并编译另一份步骤计划；无限重试 |
| 业务操作 Module | 对象与范围、字段规则、修订、容量、事务、幂等、采用/发布/删除回执 | 读取旧会话 task.stage/executionPlan 决定能否执行 |
| 既有处理 Worker | 固定输入分批生成/清洗/改写/扩充、已完成批次、失败批次恢复、不可变产物 | 决定下一句对话或唤醒旧规划器；替用户确认 |
| 前端页面与动作桥 | 当前对象/选择、未保存输入同步、原生文件/凭据输入、确认、下载、真实结果展示 | 提供权威权限或工具历史；给新助手伪造已成功的业务事实 |
| 旧格式兼容读取器 | 按当前权限读取旧消息、要求、失败记录、成果链接及预算 | 派发新任务、自动转换旧检查点、继续旧语言纠错链 |

业务 UI 和新工具是共享业务 Interface 的两个真实调用者。仅在路由中混有业务逻辑或存在旧助手反向依赖处抽取 Module；已有清晰函数直接复用，不为每个页面再建 Controller/Service/Repository 三层。

### 2.1 唯一事实归属

| 事实 | 权威位置 | 其他位置如何使用 |
| --- | --- | --- |
| 用户、角色、对象归属 | 现有账号/成员/业务记录 | 每次读写及确认提交复检 |
| 资料/草稿/版本、处理 task/run/round、来源 | 现有业务表、不可变产物及回执 | 运行时只保存引用和必要预览 |
| 当前目标、已确认修改、交付身份 | 应用任务事实；新运行时持久状态引用 | 只保存一份有效要求；展示从该事实投影，不维护第二份可写摘要 |
| 模型消息、工具调用和等待位置 | 新运行时检查点 | 不是数据库写入已完成的证明 |
| 采用/发布/删除确认 | 应用侧固定确认记录与实际业务回执 | 框架中断引用确认 ID，不自行解释为用户已批准 |
| 额度、实际请求消耗、追加授权 | 应用预算账本 | 框架限制只是额外执行上限，不替代账本 |
| 待办/进度文案 | 运行时安排及上述事实的只读投影 | 勾掉待办不能把候选变成已采用或已发布 |

不恢复旧 executionPlan/current、nextAction、stage 等多套字段共同推进任务的结构。复杂多交付只保留用户需要的名称、数量、目标和稳定身份；总数量从明细计算，不要求模型同步改写多处同义数字。不要求每个简单查询先创建计划。

## 4. 工具输入、业务提交与错误边界

### 4.1 一份业务输入合同

以能力清单的领域操作组织工具，不必 85 项各建一个工具，也不提供允许任意 operation/body 的超级写入工具。身份、项目、执行令牌、幂等键及确认授权由服务端绑定，模型不能填写；模型只提交用户目标、真实可见对象引用及该操作必要业务参数。

业务命令的权威 Schema 同时用于工具声明和服务端校验；必要的模型协议 Schema 投影必须由它生成并验证语义一致，不再手写规划 Schema、纠错 Schema、执行 Schema 三份。只能做不改变含义的格式归一，不能借纠错改来源、数量、字段、分类或保存目标。语义业务验证仍由领域函数执行。

来源 revision 来自向用户/模型展示过的可信快照。不得收到冲突后自动读取最新 revision 再覆盖，借此绕过并发保护。新写工具和人工入口都走同一提交保护，只有服务端创建的调用上下文才能选择人工或运行时身份。

### 4.2 写入回执与重放

- 写入前持久绑定操作 ID、参数摘要、目标和执行归属；操作 ID 不只依赖临时 SDK tool_call_id。
- 同一操作重试和检查点恢复沿用同一 ID。相同 ID 参数改变直接冲突；明确新的用户操作才分配新 ID。
- 业务修改与其回执同事务提交。框架检查点和业务事务不是一个原子事务，因此“业务已提交、检查点未落盘”必须能查回执恢复。
- 未知结果先查原回执；禁止换键再提交。对缺乏现成幂等的新增写能力，在共享业务边界补足，不把补偿交给模型猜测。
- 工具结果区分已提交待完成、已完成、待用户确认、被拒绝和结果未知，并返回真实对象/链接。模型总结失败不能覆盖已经保存的业务成功事实。
- 多份交付使用服务端稳定标识；按名称定位有歧义就澄清，不通过模型重排数组索引表达“第二份”。改名、另存、取消交付是不同命令。

### 4.3 只留一条受限纠错路径

由新 Harness 处理工具参数反馈与有限纠正；应用返回简短、结构化的字段/业务错误及必要的当前对象提示，不再套旧 tool-repair、plan-preparation、plan-request 等连续修补链。解析截断、网络超时、业务冲突和真实用户歧义分别记录。

正式宿主的原始参数完整性以SDK消息保留的arguments为准，不以其部分JSON解析结果或另一份SSE拼装结果替代。当前支持按权威Schema对对象/数组JSON字符串做有界无损解码；纠错期间持久保留首个可信工具/参数/错误路径，只提供并绑定原工具，成功后解除绑定。缺失原业务值不授权猜测补入；纠正再次截断不覆盖原快照。实际实现、SDK证据及尚未覆盖的包装结构等价转换见[REBUILD-04验证记录](../../.scratch/assistant-rebuild/r04-verification.md#2026-10-28-参数纠错机制修复及第三轮有界复测)。

Provider 传输重试和参数纠正各有职责但共用实际请求预算；关闭重复的叠加重试。参数无法合法修好时保留目标和成果，明确暂停，不能伪报通过，也不能要求普通用户填写内部字段。新框架不会保证模型永不犯错，交付要求是有界失败、可解释及不造成错误业务写入。

## 5. 计划、后台等待、暂停、确认与预算

### 5.1 一条执行链

1. 用户普通要求连同当前页面对象、有效选择进入已授权会话；简单操作可直接调用工具，复杂请求才需要可读计划。
2. 执行所需事实来自当前业务记录、已授权证据和唯一生效要求。只要求方案时，允许查询与保存会话要求，不创建业务草稿或处理作业。
3. 工具提交长任务后返回真实 task/run 与等待事实；运行时持久等待，Worker 继续固定输入的处理。
4. 终态通知只唤醒同一所有者、未撤销且有额度的检查点；通知重复或丢失通过绑定与业务终态核对，不重跑已有成果。
5. 需要采用、发布等操作时准备固定确认。用户确认后业务事务产生真实回执，运行时只整理结果或推进仍获授权的剩余目标。

宿主可以扫描数据库补发已落库终态，但不能再维护一套推导计划下一步骤的调度器；不增加消息总线作为前提。

### 5.2 停止优先与确认

停止按钮、明确独立暂停指令走高优先级控制入口，不被普通消息 busy 状态阻挡。可以复用小型共享控制识别，但它只识别明确控制动作，不扩展成“改名、清洗、取消第二份”另一套语言规划器。混合修改由运行时在暂停保护下理解和提交。

暂停事务失效该执行的令牌；已经提交的业务回执保留，尚未提交的旧执行被拒绝。处理 Worker 的取消/保留结果仍按其业务合同处理。查询不能恢复，继续只能恢复有效的未完成工作。停止确认与已提交回执的先后顺序要可核对。

采用、发布、不可恢复删除、敏感管理和追加额度保持 PRD 的确认边界。确认记录包含用户、项目、具体动作、对象、固定范围、目标、修订、有效期及操作 ID；框架审批/中断只关联它。用户改要求、来源变化或权限丧失使受影响确认失效；模型不注册 confirm/grant 作为可自行调用的普通工具。

### 5.3 预算不成为第二个工作流

沿用任务授权与实际消耗账本的含义，抽离其对旧计划字段的依赖。请求计量位于模型 HTTP 边界；正文生成、参数纠错、上下文摘要、Provider 重试若实际调用模型均入账。框架 max_steps 或上下文窗口只是附加上限，不是任务额度。

预算用完持久暂停；普通继续不能新建任务清零。新授权仅追加服务端明确 offer，保留旧累计与用途。UI 等待、Worker 等待不靠模型轮询；业务处理自身预算与助手模型预算分别记账，并同时受外层验收上限约束。

会话不是固定少量调用次数用尽即报废的容器。单次输出/上下文容量、单次图执行步数、任务费用和验证活动限额必须分开；有授权且有实际进展时可跨执行分段持续推进，不要求用户每段输入继续，也不能用自动续接绕过任务账本或掩盖无进展循环。测试用例的具体上限只在验证方案维护，不作为正式产品默认值。

不在本轮文档指定提高 token、超时、调用次数的默认值，不授权新增真实验证额度。具体新试验预算须在执行前记录；已关闭旧验收不可重开。

## 6. 哪些旧机制退出

| 退出新路径的机制 | 保留/迁出的能力 | 退出证据 |
| --- | --- | --- |
| executeAssistantTurn 巨型闭包和内嵌业务 SQL | 共享业务操作、真实回执 | 新入口不调用该函数或把它当工具 |
| 强制 plan_task、deliveries→steps 编译、重复阶段推进字段 | 生效要求、复杂任务安排、稳定交付身份 | 简单操作不依赖旧计划；无旧 executionPlan 写入 |
| 多层参数修复、投影合并、失败规划恢复 | 单一输入校验与有界错误反馈 | 真实 SDK 链只出现新运行时的一条纠错路径 |
| 大量自然语言特判的意图/改名/清洗/取消分支 | 明确控制协议、领域操作、真正歧义澄清 | 新任务不读旧语句分支决定业务动作 |
| collectProcessingEvents/queueContinuation 旧续步链 | 持久等待、终态通知、停止后的失效保护 | 同一任务只有一个派发者；旧任务不能由新消息唤醒 |
| 旧 task JSON 工作台推断 | 当前事实投影、候选审核、历史兼容展示 | 新 UI 不由旧 stage/nextAction 组合推导完成 |
| 业务导入旧 fence/background/requirements 编排 | 中立提交保护、证据快照、纯业务约束 | 共享业务不运行时依赖旧 agent/plan/tasks；兼容读取单独隔离 |

“退出”指退出新任务执行及最终切换后的派发，不要求第一天删除历史读取文件。旧数据表、回执、预算、处理产物和删除保护不在代码清理范围内。仅在兼容依赖已查清后删除不再使用的执行代码，不能为目录看起来干净破坏历史。

## 7. 旧会话、成果、预算的保留

| 对象 | 切换后的读取 | 执行/修改政策 |
| --- | --- | --- |
| 旧会话、消息、要求、失败诊断 | 当前本人及项目权限下只读，标记历史会话 | 不因打开/搜索触发新模型调用；重命名和显式删除仍可走受权会话管理，不恢复旧执行 |
| 旧运行中/暂停/失败任务及检查点 | 显示停在哪、已完成什么与真实成果 | 不自动解释成新框架检查点，不继续旧 scheduler |
| 旧待确认卡 | 保留历史状态及失效原因 | 切换时停止新确认消费；过期旧卡不能用于新运行时。需要采用时基于真实结果重新核对准备 |
| 已确认操作回执、草稿、版本、来源和处理产物 | 原 ID、归属、来源、链接保持 | 不复制或重放已经完成的生成/保存/发布；正常页面仍按业务权限可操作 |
| 旧授权、消耗、尝试与关闭记录 | 保留原值和关联，可审计 | 不清零、不回填、不自动追加、不把旧额度复制为新额度 |
| 旧背景文档与快照 | 沿现有私人范围和删除规则读取 | 不批量复制进长期记忆；删除/撤权要同步阻断新检查点及缓存 |
| 新检查点中的工具结果或背景节选 | 先核对当前权限及依赖，再恢复/返回 | 与源资料建立可清理关联；必要时清除受影响检查点正文并阻止恢复，保留独立预算和业务回执事实 |

用户明确希望继续旧的未完成目标时，首先核对真实已完成成果、剩余要求与当前权限；在新会话建立关联旧任务的独立执行记录，并由用户明确授权新限额。只携带获准的业务引用/必要要求，不导入旧工具历史为可信执行事件，不自动继承待确认卡或旧余额。不开发通用旧检查点转换器；首批没有安全的承接入口时展示说明和业务成果入口，不能用一个貌似可用的“继续”按钮触发旧执行器。

这项跨运行时承接是迁移例外：新运行时内部的普通继续仍沿同一任务及原预算，不把每次恢复伪装成新任务。旧总量、实际已用、新授权与新消耗在关联记录中分开展示；新额度不能用来重跑已完成工作。

现有保留不抵消用户后续明确删除。会话/背景/来源删除仍遵守原依赖和清理合同；已经独立保存的业务成果按其真实依赖处理，不能承诺删除后的敏感正文继续可读。新表不得使用危险级联反向删除业务资产。

## 8. 切换与回退边界

以下仅是未来切换规程，本次未执行。

1. **开发隔离。** 独立工作树和后续获准的隔离环境；不自动更新正式部署或 4217。新会话固定 runtime/version 所有者，不用请求超时作为切到另一引擎的条件。
2. **预先对账。** 记录旧活跃会话/turn、处理 job/run、待确认卡、操作回执及预算。先证明旧业务和新适配共享同一保护，回收站读取权限差异等 P0 已关闭。
3. **停止新派发并排空。** 关闭旧会话新增执行和旧自动续步。已受理工作按原授权有界收尾；不能安全收尾的按既有取消/暂停语义终结未完成部分，保留成功批次。不悄悄将仍有旧提交依赖的 Worker 留在切换后继续执行。
4. **形成写入屏障。** 对账已提交回执，失效旧执行/确认令牌及剩余调度资格；未提交迟到结果不再写入，残留产物按既有孤儿清理处理。记录确切切换状态，不把停止标为任务完成。
5. **启用新入口。** 新会话走新运行时；旧会话仅兼容查看和管理。待确认范围需新生成；不因浏览旧数据产生调用或额度。
6. **回退。** 停新派发、结算已发请求、核对在途业务、失效新令牌，再切回兼容人工页面或停用新助手。保留新增检查点/关联/账本，不降级数据库，不让旧引擎读取新格式继续任务。若要重新启用旧助手，只能对显式新建的旧格式会话重新授权，不能重启已封存任务。

本轮不建设长期双引擎自动容灾，不维护双写业务状态。数据库检查点属于必要持久状态，可用独立 namespace/schema；不改现有业务主键和公开页面 URL。具体增量 DDL 在实现票中确定，先满足以上不变量。

## 9. 后续实施顺序与完成边界

完整能力与原型决策的实施分工见[范围核对与票据拆分建议](../assistant-rebuild-scope-and-batches.md)：三批十张票已落为[REBUILD-01～10](../../.scratch/assistant-rebuild/spec.md)，实施进度以 Spec 唯一进度表为准；不改变本架构的事实归属、保护和切换约束。

最小纵向适配已完成；仍需把有限验证接入整理为正式产品能力。收口保留项及处理时点统一见[采用审查 §5](../research/assistant-rebuild-adoption-review-20261027.md#5-保留事项与正式接入条件)，不另建平行任务清单。

- 第一阶段：在已采用框架及已验证闭环上完成正式宿主、业务工具和提交保护的必要整理，补齐状态事实/事件分类及应用级长会话证据；完成其余受影响业务调用的实际解耦。只按真实调用者拆分，不能把验证宿主原样堆到全部工具，也不重新开发通用编排。
- 第二阶段：按能力清单补齐工具和前端动作桥，保持角色、确认、范围、名称/对象/链接一致；补足历史读取与新旧运行时识别。
- 第三阶段：验证持久恢复、停止、未知写入、撤权/删除、预算及切换回退；通过后才执行另行授权的环境切换。

## 10. 正式助手工作区接入约束（REBUILD-04）

frontend-v3保留项目壳，assistant-ui ExternalStore仅作展示；正式会话、消息提交、执行、确认与回执仍由既有宿主及持久账本负责。认证SSE输出公开正文和持久事实，重连按稳定身份归并；不输出内部参数/摘要，不在客户端自动续步或重新判断无进展。文档/成果/草稿按真实身份打开动态标签，关闭视图不删除对象。

从业务编辑页进入助手先等待原保存队列，原勾选范围连同上下文修订交接，服务端重新核对。异步结果必须匹配项目/用户、会话与切换代次；未确认提交信封和新输入分别保留。暂停后普通查询暂存原执行的恢复上下文，完成只读查询后回到原暂停事实；Worker不因查询启动，继续使用原检查点与账本。实现不增设第二套编排或规划器。

供应方兼容层将框架系统说明及当前权威事实合成为唯一前置System，保留user/assistant/tool顺序；使用实际SDK请求断言验证，不只检查内部消息对象。当前有限接线、前端兼容对照及尚未通过的实模门槛见[REBUILD-04验证记录](../../.scratch/assistant-rebuild/r04-verification.md)，完整领域能力和切换仍归后续票。
