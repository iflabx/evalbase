# EvalBase v2 架构草案

- 日期：2026-09-28
- 状态：Draft；产品范围以 [v2 PRD](../PRD-evalbase-v2.md) 为准。
- 基线：main 70c2272f43927d7bb4e1ac632091a39d7b2cd955；延续 [Phase 1A 架构](phase1a-architecture.md) 与既有 ADR。
- 本文描述待实现方案，不表示当前服务已具备登录与实时协作能力。

## 1. 边界与复用

继续使用现有 Fastify、PostgreSQL、MinIO、frontend-v3 和 Web/Worker 结构。复用密码 scrypt、服务端会话、Origin/CSRF 检查、统一版本读取层及 Sparse Delta/Checkpoint 发布器。遵守 [ADR 0011](../adr/0011-incremental-test-set-version-storage.md) 的版本存储协议。

frontend-v1 仅作为视觉与组件样式来源；正式实现落在 frontend-v3，参照 [前端复用矩阵](phase1a-frontend-reuse.md)。登录、设置、全页草稿使用相同按钮、输入框、间距、表格和侧栏体系。冻结原型仅约束确认的交互，localStorage 身份、BroadcastChannel 和模拟在线状态不能移入正式实现。

不恢复已退役的完整 drafts/candidates API。新增明确的协作草稿接口；旧内部 working_draft 的独占租约和每测试集一个草稿约束不适合作为新共享草稿合同。

## 2. 账号、初始化与授权

### 2.1 身份和权限分离

账号保存稳定 user ID、规范化邮箱、密码哈希、显示名称、头像颜色和全局角色 admin/user。项目成员关系仅保存 editor/viewer。管理员不依赖成员关系即可管理所有项目；成员权限按请求中的真实项目计算，不能继续固定读取 project_demo。

所有资源请求先解析资源所属项目，再授权。列表、下载、CSV、来源查询、实时订阅和后台发布任务均遵守同一权限模型。禁止只在前端隐藏按钮。普通用户不可借客户端字段设置 admin。

复用数据库会话与密码工具；移除前端 401 后自动 POST 空会话的单人模式。会话 cookie 为 HttpOnly，沿用 SameSite 与 CSRF 防护，HTTPS 部署使用 Secure。密码、会话令牌不得写入浏览器持久存储或日志。登出立即撤销当前会话。

### 2.2 首次初始化与旧系统升级

空实例使用数据库唯一初始化记录，事务锁定后创建唯一首位管理员并标记完成。两个首次注册请求并发只能一个成功；完成后的管理员注册端点拒绝再次初始化。部署者应在开放实例前完成首次初始化，避免首个访问者取得管理权。

已有业务数据的实例不能被判断为空实例。升级前由运维通过受控迁移输入为既有 user_owner 绑定邮箱并转为全局管理员，保留用户 ID、密码哈希和历史引用；不得通过公开注册认领旧数据。关闭每次启动重建/覆盖 Owner 密码及自动演示项目的生产启动路径。测试身份仅保留在隔离测试环境。

迁移按“备份 → 校验旧身份及邮箱冲突 → 事务迁移 → 验证登录及数据 → 启动 v2”执行。发现重复邮箱、多个不明 Owner 或无法确定旧身份时报告并停止迁移，不猜测归属。回滚以受测备份恢复为边界；v2 已写入后不得直接运行旧程序解释新身份数据。

### 2.3 邀请

邀请记录包含项目、规范化邮箱、editor/viewer、邀请人、到期时间及状态；唯一约束保证同项目同邮箱只有一个有效待接受邀请。接受时从会话读取邮箱，事务锁定邀请并校验有效期、状态、项目和账号；写入成员关系及 accepted 状态。重复接受返回同一结果。

撤销、接受、移除成员与调整权限通过共同锁顺序和事务授权校验处理竞态。移除与写入以提交顺序界定：移除提交后开始授权的操作必须拒绝；已提交结果保留历史归属。实时流在发送数据前重新检查会话和权限，不以连接建立时的授权永久放行。

## 3. 持久化协作模型

以下名称是逻辑实体，最终迁移名称可调整，但约束不能减弱。

| 实体 | 关键数据与约束 |
| --- | --- |
| collaborative_draft | ID、project、可空 test_set、可空 parent_version、状态、revision、创建/更新用户与时间 |
| draft_record | 稳定草稿记录 ID、继承 case ID 或新增来源 ID、内容、每字段 revision、行 revision、删除标记 |
| draft_operation | draft ID、actor ID、operation ID、请求摘要、提交 revision、结果；防重复执行 |
| draft_event | draft ID、递增序号、操作类别、受影响记录/字段 ID；与操作同事务落库 |
| draft_publication | draft ID 唯一、冻结 revision、任务状态、唯一正式 version ID |
| field_attribution | 正式版本、case、字段、修改者 ID 与当时名称；与内容版本关联 |
| project_invitation | 项目、邮箱、角色、状态、有效期、邀请者 |
| installation_state | 唯一初始化状态；区分新安装与旧数据升级 |

派生草稿的有效唯一键是 project + test_set + parent_version；editing、publishing、suspended 都占用该键。终止或已发布后允许从同父版本新建另一份草稿。新建测试集草稿独立 ID，发布前没有公开测试集；发布时分配测试集和 case ID，并在同一持久化发布结果中保存映射。

每个接口和事件必须携带 draft ID，服务端校验它所属的项目、测试集及父版本。test_set ID 不能代替 draft ID 作为协作频道。不得将不同父版本的草稿快照相互覆盖。

## 4. 保存、冲突与同步

### 4.1 HTTP 写入与字段比较

客户端发送 operation ID、目标记录、修改字段及各字段的已知 revision。服务端锁定草稿，检查 editing 状态、权限和目标字段 revision 后提交，并递增全局草稿 revision。全局 revision 用于排序和发布边界，不作为所有字段写入的统一排他条件。

不同字段可以基于同一旧快照分别成功；同字段 revision 不符返回冲突，携带可读取的当前值、revision 和修改者。客户端保留本地输入并提供采用远端/重新提交本地的明确动作。Metadata 暂按一个完整字段比较；这一粒度是 PRD 中待确认的默认方案。

删除记录使用整行 revision，避免覆盖别人已经保存的字段。冲突集合按记录/字段保存，不能只保留最后一次冲突。无效输入保留本地，不伪装成已保存；草稿可暂缺测试集名称或记录，发布前校验名称、记录数量和结构；问题为空、重复内容等 v1 数据核对仍只提示，不升级为发布阻断。

操作去重键为 draft + actor + operation ID，并校验请求摘要；同 ID 不同载荷拒绝。批量操作原子提交或明确返回逐项结果，客户端不能把部分失败表示为全部保存。

### 4.2 接收事件

建议采用 HTTP 写入 + SSE 接收，避免为本期引入独立消息中间件。数据库事件和业务变更同事务提交；Web 按有界游标读取事件并推送，不能依赖进程内通知保证正确性。SSE 事件携带失效范围和 revision，客户端按需读取授权后的记录内容。

事件保留最近 24 小时且每草稿最多 10,000 条；游标过旧返回 reset 指令，客户端重新读取快照并保留未提交本地输入。分页读取、重连和事件重复均以 revision/operation ID 去重。时间窗口和容量属于可配置建议值，不是产品无限回放承诺。

在线状态单独维护为短期状态，不进入正式版本。建议心跳 5 秒、失联 15 秒过期；同用户多个连接聚合为一个头像，所有连接消失才离线。编辑位置包括 draft、record、field；焦点离开或过期清除。在线和正在编辑不能替代已保存修改者。

重连先重新授权，再恢复快照/事件；权限失效或项目回收后停止发送业务内容。任何旧标签页未提交输入都不能在重连时盲目覆盖服务器。

## 5. 唯一发布与崩溃恢复

1. 请求携带 draft ID 和客户端确认的已保存 revision。事务校验权限、状态、父依赖及内容；锁定草稿并创建唯一 draft_publication，冻结 revision，将草稿置为 publishing。
2. 所有后续编辑拒绝并保留客户端未提交输入。发布内容只取冻结 revision；其他人的未到达输入不会隐式进入发布。
3. 调用既有正式发布逻辑，使用 draft ID 作为跨用户发布身份；原有 actor + idempotency key 仅提供请求重试去重，不能保证一草稿一版本。
4. PostgreSQL 事务原子提交版本、发布结果、case 映射、标签计数和 published 状态。正式 version 关联 draft 的唯一约束是最终防线。
5. 若需要 MinIO 暂存，使用可重试的不可变暂存对象和持久化任务阶段。数据库提交前失败不对读者暴露版本；孤立暂存对象由已有清理机制处理。
6. 重启扫描 publishing 任务，依据持久化结果继续或回到可重试失败状态；不得重新分配第二个版本。只有确认尚未提交且旧任务已失效时，才允许草稿恢复 editing；为发布尝试分配递增代次，最终提交检查当前代次，阻止超时旧 Worker 在用户重新编辑后提交旧快照。结果未知时保持 publishing 并查询恢复。再次请求无论用户或幂等键是否变化，都返回同一发布结果或同一正在发布状态。

正式提交前再次校验权限与父依赖，并与权限变更、永久删除共享可预测锁顺序。删除先完成则发布失败；发布先完成则删除按既有依赖规则处理新后代。版本号只在有效提交中消耗。

## 6. 来源查询和变更归属

新增有界来源查询，支持项目授权、资源/记录搜索、分页和稳定排序；不可延续一次返回全项目全部记录的接口。跨页选择使用冻结的候选集合或确定的来源 ID 集合，明确全选范围与排除项。列表数据变化不改变已确认选择；导入前再校验授权和来源有效性。

继承记录复用 case ID；新增记录保存来源资源、来源记录和加入者。相同来源记录重复选择去重，相同文本但不同来源记录不按文本擅自合并。

字段修改者由服务端会话生成，与保存同事务记录。正式版本的归属使用附属数据，不改动 ADR 0011 的内容哈希、Delta/Checkpoint 编码或旧 CSV 合同。发布者与字段修改者分开。旧数据无法追溯时明确“未记录”，不得归给升级者。净变更回到父版本值时，正式归属保持父版本；草稿操作历史可保留最后编辑行为。

事件不保存旧字段正文。永久删除同时清理相关草稿正文、暂存内容及可能泄漏正文的缓存，保留必要无正文关系；不能借事件回放恢复已删除内容。

## 7. 生命周期与旧功能

父版本或测试集进入回收站时草稿 suspended，拒绝写入/发布，恢复后重新校验依赖再继续。直接父内容永久删除时相关草稿终止并清理其专属内容；仍可读的其他后代及其草稿保持可读。依赖切断与 CSV 缓存继续执行既有删除协议。

保留既有记录/资源容量限制、版本不可变性、旧版本读取、Delta 回放阈值和 Checkpoint 语义。这里的存储 Checkpoint 与人工验收 checkpoint 不是同一概念。

## 8. 接口与前端分工

| 接口族（拟定） | 行为 |
| --- | --- |
| installation/status、installation/admin | 查询初始化状态、一次性首次注册 |
| accounts、session、me | 自助注册、登录登出、个人资料 |
| projects/:id/invitations、me/invitations | 管理邀请、查看与接受自己的邀请 |
| projects/:id/drafts | 创建/列举有权限的草稿 |
| drafts/:id、records、operations | 快照、分页记录、字段写入与删除 |
| drafts/:id/events、presence | 恢复同步与短期在线位置 |
| drafts/:id/publication | 发起发布、查询同一结果 |
| projects/:id/source-records | 有界来源检索与选择 |

实际 URL 可沿用仓库路由规范。所有子资源再次校验归属，非法跨项目 ID 返回一致的拒绝响应；不可从错误信息泄漏内容。前端区分未保存、保存中、已保存、冲突、发布中和已发布，保存退出只在收到服务器确认后导航。

## 9. 交付与验证

迁移、权限、字段 CAS、唯一发布和删除竞态必须先通过服务端集成测试，再按 [测试计划](../test-plan-evalbase-v2.md) 进行独立浏览器身份验收。本文不创建 Ticket，不改变部署。架构决策见 [ADR 0012](../adr/0012-v2-account-and-project-authorization.md) 与 [ADR 0013](../adr/0013-v2-shared-draft-publication.md)；状态均为 Proposed，产品确认项不能被技术实现弱化。
