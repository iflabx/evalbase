## 1. 公共测试边界

2026-10-06 短请求纠错补充：公开 HTTP + 真实 SDK 故障注入工具格式文本及必选工具协议失败；验证同回合原生纠错、失败范围修正后的真实 200 条输出目标与固定参考输入、成功操作不重复。七次来源读取后仍能实际提交，纠错共享 10 步、12 次工具、80 秒预算；最终回复不能显示待执行代码或冒充完成。真实模型在同一新会话用 GB 背景与 ChineseSafe 短请求复测，原失败会话和既有成果保留。

2026-10-07 背景导航补充：公共 HTTP 核对原文/匹配列表各自的 `nextFrom`、末页空位置、真实原文片段编号及无匹配导航。真实模型首次短请求规划出现连续查询不存在章节的失败；修复后在同一测试会话重试，不增加提示词中的人工分类表，也不改动用户原失败会话。

2026-10-07 规划检查点补充：真实 SDK/HTTP 注入连续背景查询，核对预算耗尽前保存 plan 模式、有序未执行步骤和数量，且不提交处理或准备采用卡；先保存旧方案后提出新要求，以及本轮仅更新文字要求的情况，均须保存完整的新方案，不能用旧步骤和旧数量冒充更新成功。同回合先保存完整方案、再仅改文字要求时，也必须以最新规划回执判断，不接受较早回执绕过检查点。缺少模式或步骤的检查点须拒绝，并允许同轮及过期重领后纠正，不能保存空方案冒充成功；内部检查点不进入用户响应。查看权限仍可只读查询，不因强制规划触发写权限错误。正常查询汇总、已有执行计划、后台完成与澄清恢复分别复核。

2026-10-07 规划反馈补充：原生 SDK 成功保存非空方案后分别返回空回复和文本工具模板，公开 HTTP 应显示从当前方案回执生成的真实要求与步骤，明确未执行且不创建处理或采用卡；旧回合方案不能掩盖新回合未完成，保存方案后的 SDK 参数校验失败与业务工具失败均须保留失败回执并阻止摘要回退。原生拒绝尚未产生业务意图，重试及过期重领允许纠正参数，真实业务意图的参数保护仍有效；工具预算终止不误记为业务失败。普通文本工具调用仍需原生协议纠正。真实模型同会话复测记录方案质量与执行效果，不能仅以保存成功认定业务目标达成。

2026-10-06 会话管理补充：通过公共 HTTP 验证名称校验、刷新后持久化、后续模型计划不覆盖名称、跨账号/项目拒绝及 CSRF；删除清除会话/背景/提案，停止未完成任务并拒绝迟到执行，已创建草稿和正式版本仍可读。浏览器检查重命名、取消删除、二次确认、失败保留输入与重试、删除最后会话后的空态和窄窗口。复用现有隔离测试库及一个 Owner 验收项目，不增加长期账号或项目。

2026-10-06 追加实测优化的 REL、FLOW、DOC、UI、FINAL 验证矩阵，权威定义和完成证据位于 [优化 Spec](../.scratch/assistant-optimization/spec.md)。数量不足恢复、采用跨入口回执及 ZIP 内两种 CSV 需实际验证；历史通过记录不代替本轮证据。

此前实施曾授权代理制定并执行测试；本次 OPT-08 开发和实测已获单独授权。沿用现有 HTTP、PostgreSQL/MinIO、Browser、CSV、Deployment seams；纯选择算法和模型输出合同提供有独立期望值的单元测试。每个垂直功能先红后绿，不一次编写覆盖未实现假合同的大量测试。

### 5.1 小样本通用场景

在一个已有验收项目内准备有清晰期望结果的少量合成资料；每个任务从初始请求到交付使用同一会话，不通过换会话丢掉失败状态。不同用例可以独立会话，完成后不遗留无关长期项目或账号。

| 编号        | 用户初始请求示例                                                          | 规模与人工判定依据                                          | 完成要求                                                                             |
| ----------- | ------------------------------------------------------------------------- | ----------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| REM-CLEAN   | “清理这份资料的首尾空白，其他内容不变，给我检查结果。”                    | 12 条，包含空值、重复与有序 Metadata；预先保存预期差异      | 仅指定变化；报告问题但不自行删除记录；不要求用户补工具参数                           |
| REM-REWRITE | “把这组问法改得自然一些，原意和答案保持不变。”                            | 10 条，包含数量、时间、否定和条件                           | 逐条核对原意、保护字段和来源；只对未达标范围调整                                     |
| REM-INTENT  | “参考这些客服问题扩写 12 条，保持已有意图分类，表达多样一些。”            | 6 条来源、3 种清楚且互斥的意图；未指定精确配额              | 新增 12 条，分类与问题一致、无精确重复；不能擅自增加等量配额要求                     |
| REM-ENTITY  | “从这 10 条句子提取城市和日期，放到 Metadata，缺失留空，原句和答案不变。” | 10 条含缺失、相似名称和多个实体；预先规定多个值的可接受表达 | 每条对象与字段对应正确，空值处理一致；如果多值表达存在实质歧义，只澄清这一点         |
| REM-DOC     | “按附件的类别整理这批记录，保留原文，然后每类选 2 条给我审核。”           | 12 条来源、3 类小型 MD/TXT 规则；另保留既有 PDF 提取回归    | 读取真实依据、分类与内容一致、按结果固定选取；无某类时报告不足，不编造来源或强改标签 |

上述提示为验收输入示例，不是产品内置模板或要求用户背诵的格式。任选一个小样本任务继续完成“采用 → 草稿 → 发布 → 刷新 → CSV/溯源下载”完整交付；其余用例验证到各自用户要求的终点，不为覆盖表重复发布多个测试集。

在这些样本内增加一次目标式请求：“根据附件和这份资料，帮我做一组 6 条可用测试题，先给我审核。”不向助手指定工具和处理顺序。准备可判断的资料缺口，使助手必须先了解资料，再选取合适处理方式；同会话补充一项明确的范围或字段修改，观察其调整。允许不同合理方法，不断言固定工具顺序；核对是否使用真实依据、满足目标、复用兼容成果并交付可审核内容。使用已有小样本，不另建业务子系统或大型数据集。

### 5.2 执行与恢复关键检查

| 编号         | 公共观察                                                                              | 必须成立的结果                                                                                                     |
| ------------ | ------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------ |

### 5.3 通过标准与记录口径

- **任务体验**：已提供清楚目标和来源的场景，一条初始业务提示应能推进到用户要求的审核点。必要业务澄清、用户主动修改需求和采用/发布点击分别记录；因系统错误要求用户补 ID、工具格式、配额算术、重复“继续”的次数必须为零。工程人员代写技术提示或直接改库不算用户成功。
- **内容质量**：先固定小样本的判断依据，再逐条核对全体候选。清洗和实体提取与预期结果比较；改写和扩写检查语义、标签、明确性、多样性和来源。初次正确数量、发现的问题、调整轮数及人工改动分别报告；有未解决的明确错误不能记为“可用”。只有人工修正后才能成立的结果不能写为模型一次成功。
- **结构与一致性**：全量数量、字段、配额、来源及导出一致；语义未审核时只标结构通过。部分采用不得标成全任务完成。
- **性能**：分别记录规划、排队、模型处理、核对、恢复的耗时、调用次数和峰值资源；记录输入/输出规模与实际模型。当前不指定未经测量的延时或准确率承诺；长耗时先定位到阶段，再决定优化。
- **复验**：修复发现后复跑该失败路径及一个直接相关正常对照；交付前在固定代码版本跑上述小样本矩阵一次。不为每个文案改动重复完整矩阵，也不挑选多次运行中唯一成功的一次隐藏失败。
- **浏览器**：管理员执行一个完整交付，编辑账号验证其有权使用的处理与恢复；查看权限、跨项目与错误态优先复用已有自动测试。桌面和窄窗口检查生效要求、真实阶段、成果、下一操作及来源对照是否清楚；用户无需展开工具日志即可区分等待、审核和失败。保持 donor 风格、键盘操作和输入保留。
- **实现范围**：复审确认新增结构对应上述用户流程，处理与确认继续复用业务服务，替代路径的旧写入已退出。不同测试类型共用业务能力，不要求新增通用规则引擎、动态依赖图、专用监控或历史计划迁移系统；兼容性、幂等与权限检查不因简化而省略。
