## 3. 执行与证据

- 首个红测：公共选择规则函数在已知文字/Metadata 输入上返回准确候选及确定种子身份，非法规则失败；接着以 HTTP 测试固定预览和事务应用。
- 使用现有 Vitest、Playwright 和构建工具，不增加同用途框架。现有历史集成用例若依赖退役路由，记录边界，不能恢复旧接口来使其变绿。
- 每 Ticket 执行受影响类型检查、lint、测试和文档检查，最后执行单元全套、正式前端构建、现行受影响集成与浏览器流程；异常需有对应修复或明确未完成状态。
- 模型大批量测试使用假服务；真实端点只发有限合成样本。所有凭据由环境注入，证据脱敏。
- 证据保存到 `.scratch/agent-data-processing/evidence/`：命令/返回、固定 SHA、截图、需求覆盖与未完成清单。每次只把已核实的编号标为通过。
- 人工验收环境保留至用户明确接受；自动化测试数据在独立库/桶清理。用户验收前不记为 Owner accepted。
