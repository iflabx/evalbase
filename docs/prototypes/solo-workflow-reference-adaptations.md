## 1. 使用边界

本记录说明原型采用了哪些公开项目的交互和信息组织模式。它只帮助 Project Owner 判断页面是否易用，不能据此复制对方源码、商标、图标、产品名称或未获许可的资产。外部源码是否可复制、改写或仅能参考，以 [`test-dataset-lineage-source-reuse-register.md`](../research/test-dataset-lineage-source-reuse-register.md) 的逐 Ticket 登记和核准为准。

原型保持三个一级入口：`项目`、`数据集` 与 `测试集`。`项目` 是单人工作边界，同时容纳其数据集和测试集；切换项目会同时切换两类内容，创建测试集时不能选择其他项目的资料。`数据集` 是原先内部称为“资料集合”的原始文件容器，用于按领域、方向或批次把文件放在一起；它不是“测试集”的同义词，不修改内部领域术语，也不会改变任一文件的原始内容、字段映射或记录级来源。它不新增登录、成员、角色、数据目录、Bucket、数据库、任务、流水线、Package、Registry、Git/DVC 或治理中心。

视觉风格仍以 [`frontend-v1/`](../../frontend-v1/) 为唯一 donor：保留其冷灰背景、白色内容面板、蓝色主操作、紧凑表格、侧栏、Dialog、Button、Input 和 Badge 的样式语言；下面的参考项目只影响任务顺序与信息层级。

## 3. 可点击验证路径

1. 在“项目”首页创建一个只填写名称的新项目，确认它自动显示一个空的“未整理”数据集；进入另一个项目后，确认两边的数据集与测试集彼此不可见。
2. 在“数据集”首页确认仅有搜索、类型/内容筛选、更新时间排序、分页和“上传文件 / 新建数据集”；点名称或“查看”进入数据集，确认首页没有右侧信息面板。
3. 在数据集内选择文件行，确认只改变选中样式且不出现右侧文件面板；再点“查看”进入统一记录浏览。切到“全部记录”后，确认每一行显示来源文件。
4. 从首页上传一个 CSV、JSON 或 JSONL，确认先选择文件与目标数据集，再在同一页核对字段映射和统一记录预览；从数据集详情上传并一次选择多个文件，逐个调整字段映射，确认最终全部保存到当前数据集。
5. 在“未整理”或任一数据集的文件列表，点击单个文件的“移动”，确认目标只包含当前项目的其他数据集；确认后文件从源列表消失、在目标列表出现，文件内容、映射和既有测试集来源不变。
6. 在“测试集”新建流程中按“数据集 → 文件 → 记录”选择，确认只出现当前项目的数据集；取消部分记录或全选一个文件，确认选择摘要变化；在编辑页增删改记录，确认修改摘要变化。
7. 打开“客服基础问答”，切换 `v3 / v2 / v1`，确认版本摘要、记录、来源摘要和 CSV 下载都随所选版本改变；编辑当前版本后，确认形成同一个测试集的下一版本，而非另一份测试集。
8. 在有分支的测试集中点击 `v3-b1`，确认只有 `v1 → v2-b1 → v3-b1` 被高亮，`v2 → v3` 仍可见但对比度降低；窄视口下确认图可横向滚动，且仅在溢出时出现“适应视图”。
9. 在测试集列表把一份测试集移入回收站并恢复；打开 `v2`，确认中间版本只能选择“删除整个后续分支”或“删除内容、保留关系”。选择后者后，确认 `v3` 仍指向灰色虚线 `v2`，而不是被改挂到 `v1`。选择末端版本时，确认它可移入回收站并恢复。
10. 打开“客服基础问答”的 `v3` 并选择“查看来源与修改”；确认上方以文字说明父版本、本次新增资料及增改删计数，不显示关系图或活动术语。按需展开资料的字段映射；筛选“本次有变化”和“已移除”，打开记录后核对修改前内容或移除前内容，并确认“下载数据与溯源”的 CSV 包含相同的记录级事实。

## 4. 后续实施约束

正式实现与原型一致不提供登录步骤；上传临时接收/取消清理、来源事实、版本发布、删除语义和下载合同的具体规则，以已同步的 PRD、Architecture 和 ADR 为准。原型仍没有证明服务端事务、物理擦除、共享内容引用分析、请求边界、性能或任何合规结果。

前端迁移不是重画原型样式：Ticket 20 完整复制 `frontend-v1/` 为 `frontend-v3/`，保持 donor 不变，在副本中按本交互合同替换旧业务并连接真实 API；`frontend-v2/` 只保留历史且不得继续开发、预览或部署，Ticket 27 正式切换后当前 `src/web/` 退出运行路径。

资料集合的详细对比、许可核对与一手资料索引见 [`raw-dataset-container-patterns.md`](../research/raw-dataset-container-patterns.md)；测试集/版本删除的资料索引见 [`test-set-version-deletion-patterns.md`](../research/test-set-version-deletion-patterns.md)；其他原型模式的选择理由见 [`solo-data-asset-prototype-patterns.md`](../research/solo-data-asset-prototype-patterns.md)。

## 5. `v2` 数据集、测试集与记录浏览视觉修订（已验收）

本次修订不移动 `7f3d56a` / `prototype/solo-workflow-v1`。它在原型 HTML 中为同一交互模型增加候选 UI：`数据集` 是原先“资料集合”的用户界面名称，仍只容纳原始文件，不会变成 Test Set 或改变产品领域模型。

首页直接采用 `frontend-v1/` 数据集列表页的应用 shell 和信息密度：16rem 可折叠至 3rem 的侧栏、48px 顶栏、页头、搜索、两个筛选器、更新时间排序、白色全宽表格 Card 与 10 条分页。表格字段只映射为名称、类型、文件数、统一记录数、状态、最近更新和查看；没有采纳 donor 的 Langfuse、默认版本、负责人、登录或其他旧业务动作。

数据集内的“文件 / 全部记录”与单文件统一记录浏览继续沿用同一 donor 层级：工具栏、实时搜索、匹配数、全宽表格 Card 和分页保持一致。单文件页将文件名、格式和记录数放在页头，只保留“返回数据集”和“查看原始内容”操作；它不显示跨文件的来源列，也不额外显示映射说明卡。

测试集首页采用同一 donor 表格几何：仅显示名称、当前版本、记录数、来源、状态、更新时间和查看；移除旧的右侧信息面板，名称和“查看”都直接进入该测试集。版本浏览页也使用 donor 页头、操作区、记录搜索、全宽记录表和分页；现有版本图、溯源查看与下载、创建版本/分支、回收站与墓碑版本行为保持不变。版本关系和来源摘要仅换成相同的 Card/Table 表面，不增加新的字段或操作。

Project Owner 已在浏览器完成验收；本修订与后续 `v3`–`v5` 修订共同冻结在 `prototype/solo-workflow-v5`。`v1` 标签始终保留为历史冻结基线。

## 6. `v3` 项目工作区层（已验收）

本次候选修订不修改 `prototype/solo-workflow-v1`。它在同一 Throwaway HTML 中增加“项目”首页，并直接延续 `frontend-v1/` 的应用 shell、工具栏、全宽表格、搜索、分页和“查看”动作。项目列表只在未选择项目时显示；进入项目后，侧栏将当前项目名称显示为父节点，并将“数据集”和“测试集”缩进为子项。

点击项目名称右侧的箭头会展开项目下拉菜单。选择其他项目时，原本位于“数据集”或“测试集”的用户保留在同类列表；若原本浏览具体文件、记录或版本，则安全回到目标项目的对应列表。下拉菜单最后保留“新建项目”，不新增常驻的项目管理、成员或设置入口。

新项目只需名称和可选说明，原型自动创建一个固定“未整理”数据集。上传、新建数据集、资料选择、新建测试集、版本、下载和回收站均保留原有交互，但不允许跨项目选择或显示内容。原型不提供项目删除、移动、共享、成员、权限、设置或跨项目引用；刷新页面后新建项目仍会消失。

该层使用仓库已有 `project_id` 作为术语和关系校验依据，但它仍只是浏览器内存 Mock，不改变现有正式产品合同或实现。Project Owner 已验收该交互；它应通过后续差异审计转写为正式合同和 Ticket，而不能直接把 Mock 当作实现。

## 7. `v3` 创建表单视觉修订（已验收）

“新建项目”和“新建数据集”采用 [`frontend-v1/src/components/ui/dialog.tsx`](../../frontend-v1/src/components/ui/dialog.tsx) 的窄型 `max-w-lg` Dialog 几何、24px 内边距、左对齐标题与描述、右上角 `X` 图标和右对齐操作区；输入控件及“取消 / 创建”按钮分别沿用 donor 的 `Input` 与 `Button` 尺寸、边框、阴影和状态。

两者不再借用上传映射所需的“字段 → 目标”横向布局。它们仅显示必填名称、可选多行说明及一条简短的结果提示：项目会创建“未整理”数据集，数据集用于归类当前项目的原始文件。创建校验、项目隔离、自动“未整理”数据集和浏览器内存 Mock 均保持不变。

## 8. `v3` 上传与文件归类修订（已验收）

上传弹窗继续使用 `frontend-v1/` 的 Dialog、Button、Select 和 Table 表面，但将原来的三步流程压缩为“选择文件 / 字段映射与预览”两步。选择页只显示文件选择、目标数据集和队列；映射页以“原始字段 / 样例值 / 映射到”表格替代横向箭头。多文件仍按文件逐个确认映射，取消时不保存浏览器内存中的临时上传。

文件表格新增单文件“移动”动作。它只列出当前项目的其他数据集，并在确认 Dialog 后更新文件的归属；文件 ID、原始内容、字段映射、统一记录和测试集的记录级来源均不修改。当前不支持批量移动、拖拽、跨项目移动、移动历史或撤销。

## 9. `v4` 测试集版本核对修订（已验收）

本次修订不移动 `7f3d56a` / `prototype/solo-workflow-v1`。它只补充每个指定测试集版本的可读摘要，不改变项目、数据集、记录选择、版本图、删除或下载的既有操作顺序。

首次创建测试集时，用户可选填一次“用途说明”；它属于测试集本身，后续版本只读继承，不新增审批、责任人、用途分类或每版本表单。版本浏览页显示当前选中版本的父版本、创建时间、记录总数、用途、资料来源和变更摘要，并明确告知已发布版本不会被覆盖，编辑只会创建新版本。

页面和溯源 CSV 同时显示轻量“数据核对”：对当前原型可浏览记录统计问题未填写、完全重复记录和来源已记录数。它借鉴 [`software-test-dataset-standards.md`](../research/software-test-dataset-standards.md) 中“用途可理解、版本可复现、来源可追溯、质量可见”的原则，但不声称符合任何标准、法律或独立测试集要求。该核对始终只提示，不阻止创建、迭代或下载，也不引入阈值、规则配置、自动修复、训练/验证集登记或治理中心。

验收覆盖：在创建测试集时填写用途说明，确认它在 `v1` 及其后续版本保持可见；切换任一历史或分支版本，确认摘要、记录表、来源与修改页和下载的两个 CSV 都对应当前节点；将问题留空或重复一条记录后，确认核对计数变化但仍可创建版本和下载。
