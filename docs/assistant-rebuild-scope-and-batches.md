- 日期：2026-10-27；核对分支：`codex/assistant-rebuild`；代码及原型基线：`5911ead`。
- 本文是范围与实施顺序索引，不是新的产品合同或实施完成证明。正式票据已按 Owner 后续指令创建，见[实施 Spec](../.scratch/assistant-rebuild/spec.md)；原建议 R01～R10 对应 REBUILD-01～10，均尚未开发。本次只整理文档，不运行模型、Computer Use 或业务测试，不更新环境，不修改业务代码、数据及旧预算。

## 2. 四类范围与“完成”的含义

| 分类 | 范围 | 当前可以怎样使用 |
| --- | --- | --- |

| 已完成可复用：有限适配 | Deep Agents 工具循环、LangChain 模型/工具接入、LangGraph 检查点/中断；有界纠错、暂停恢复、来源链接、唯一回执、状态投影的具体实现和回归证据 | 以锁定依赖和真实业务闭环为起点，不重做通用 Harness；正式化仍需补齐后述缺口 |
| 已完成可复用：设计与测试材料 | 能力盘点、边界、ADR、受控 SDK 夹具、普通提示样本、静态原型布局和样式决定 | 复用合同、夹具及交互决定；不是可直接上线的完整代码或所有用例通过证明 |

| 后续批次：本次重建的必交范围 | R05～R09 补齐全部领域、原生动作桥、历史及生命周期；R10 收口、切换演练与另行授权的切换 | 这是完整重建的后续批次，**不是可无声删去的愿望清单**；全部接通前不能声称已覆盖 85 项 |

不将下列研究内容默认为已实现：assistant-ui、真实 token 流、公开推理文本展示、任意多交付、应用级长会话摘要后写入、全工具参数一致性、全权限/删除链及生产切换。

## 3. 核对出的遗漏与容易混淆的地方

以下是相对于“只把原型接入框架”的遗漏；部分已在既有边界或收口报告提出，本次明确落到建议票。不是新的全库安全审计，也不保证已穷尽所有未来缺陷。

| 编号 / 优先级 | 事实与缺口 | 最小完整处理及责任 |
| --- | --- | --- |
| G01 / P0 | 业务仍经旧 fence 调用新 guard；store/refine/review 仍导入旧背景、计划或规则。新 guard 仍关联验证 campaign | R01 把业务保护和纯规则放回中立边界，保留旧兼容适配；R03 接正式授权。不是删 guard，也不是让工具冒充人工绕过保护 |
| G02 / P0 | 验证宿主要求仅支持 clean/rewrite/generate、单份名称、count≤10，入口依赖 REBUILD_VALIDATION_CAMPAIGN_ID；不是正式通用助手 | R02 去掉正式入口对试验活动及统一处理小合同的依赖；R03 分开正式账本与验收外层限制；R07 补扩充、多交付与业务处理合同。旧测试记录保持原样，不批量改写限制 |
| G03 / P0 | 85 项不等于旧十五工具或验证工具集合；回收站 GET 仍检查 read，与管理员页面不一致 | R01 先统一共享读取权限；R05～R09 接全能力。角色/项目/撤权在业务边界校验，不能只隐藏按钮 |
| G04 / P0 | 应用操作回执与框架检查点不是同一事务；采用证据不能推广为所有写入都已防重 | R01/R03 统一持久操作身份和回执恢复；各领域票覆盖自身写入。业务提交成功、检查点失败时查原回执，不能换键重试 |
| G05 / P0 | 上传、密钥、勾选、未保存输入及明确确认依赖页面；只提供聊天 API 会丢范围或泄露敏感输入 | R04 定义受控动作桥，R05/R06/R09 接真实页面。选择带来源和修订，flush 失败停留；确认、凭据由用户完成 |
| G06 / P0 | 旧会话只读、新检查点清理、撤权及切换屏障尚未整体完成 | R08 覆盖新旧正文/引用/成果/账本的依赖边界；R10 做在途对账与切换。对数据的删除/撤权保护不能等上线后补 |
| G07 / P1 | answer_question 自由解释仍可能被误用于状态断言；正常 interrupt 仍记为 tool_error | R02/R03 统一展示事实和事件分类；普通问答可保留，执行成功/预算/确认结论必须有当前业务事实支持。不新增第二个意图模型或评审模型来遮补 |
| G08 / P1 | F07 只证明独立 Harness 摘要；未覆盖应用摘要→改要求→保存→摘要费用对账；普通继续与多交付未全面覆盖 | R02/R03/R07 用同一身份、有效要求、交付引用及账本贯穿。上下文压缩不得改变范围、目标或旧确认的有效性 |
| G09 / P1 | 最小宿主 invoke + streaming:false，验证页轮询；不能靠静态动画实现真实流式聊天 | R04 接受权流事件与持久快照，处理重连、重复事件、停止和最终落盘；R03 保证真实请求计量。思考展示仅限实际公开文本/摘要，无该字段则显示真实执行过程 |
| G10 / P1 | 验证页存在切会话旧轮询短暂回填；当前原型附件刷新修正只有语法检查，未完成最新整页 CU | R04 按项目/会话/执行身份丢弃迟到响应；补侧栏、附件、标签、确认、滚动与窄屏的针对性浏览器检查。不能把早期原型通过记录当最新完整通过 |
| G11 / P1 | 原 L02 有 Worker 配置介入；原 C1/C2 的同措辞/数量/时序证据仍不完整；没有与旧助手作同条件稳定率比较 | R10 在新授权活动中补与正式实现相关的缺口，不重签原结论、不重跑旧成功生成。不把“采用框架”宣传成已证明全面更稳定 |
| G12 / P1 | 原型中的模型切换、附件、保存和导出均为示例；依赖兼容、供应方公开推理支持及许可证接入未落地 | R04 做组件适配门槛，R09 使用真实模型配置权限。原型不能偷偷引入普通用户可任意换模型/端点的能力；只保留实际已支持控件 |

### 已确认的前端决定必须一起落实

- 保留现有项目导航及当前项目；助手是项目内独立页面。其内部为会话栏、消息/输入区和可折叠工作区，不另建脱离项目权限的聊天产品。
- 视觉与组件对齐 frontend-v1，正式实现进入 frontend-v3；桌面截图只参考空间组织，不能引入另一套暖灰皮肤或改其他业务页面。
- 工作区按实际打开的文档/成果身份显示标签；重复打开定位已有标签，收起保留，关闭不删除数据，最后一个关闭后收起。空面板按钮仍可打开可用内容入口/空态；不同会话不混用标签与附件。
- 普通方案和执行过程留在消息区，不恢复三个固定标签；真实多轮成果复用处理业务身份，不以原型单份样例设计覆盖正式数据结构。
- 优先小适配 assistant-ui ExternalStore 与已有 Radix/Resizable。若兼容成本不合适，可采用调研中的独立展示组件方案；二选一，不维护两套聊天权威状态、不引入新的云端会话库。
- 执行过程、公开推理内容和最终答复分开；不暴露系统提示、原始调试堆栈或完整 checkpoint。来源和保存链接由可信对象/回执生成。
- 原型未完整实现会话删除、历史管理、预算授权等，不能因此从 A 组删掉。固定确认卡可以打开对应内容，但不发展独立“方案审批工作台”。

| A05 | 删除背景 | R08 | R05 文档接口、R03 失效保护 |

| A09～A10 | 确认/拒绝、停止/查询/继续、执行/重试 | R03 | R04 可操作入口，各领域票接固定授权 |
| A11 | 历史任务查看与指定恢复 | R08 | R03 同运行时恢复；旧运行时承接遵循架构 §7，不自动转换 |
| A12 | 额度查询及有上限追加授权 | R03 | R04 用户确认；正式任务账本与验收限额分开 |
| A13 | 执行记录、诊断、成果与工作区 | R04 | R03 权威事件/回执，各领域提供真实链接 |

| U11～U12 | 实例模型配置、密钥更新、测试连接 | R09 | 原生密钥输入、修订/权限；测试请求按现有边界计量 |

“支持”须有实际入口、明确输入/返回、服务端校验及可观察完成事实。对于应由工具执行的业务，只有一个跳转到原页面的链接不等于完成接入；原生文件/凭据/确认等则应明确由页面协作完成。暂缺的能力按编号公开记录，不用万能工具或伪按钮填满覆盖表。

## 7. 防止再次漏项的完成检查

1. **能力覆盖闭合。** 按 §4 的 85 个编号分别登记实际共用业务操作/前端桥/原生步骤、公开入口、角色与证据位置；同一个测试可支持多个编号。无入口或仅有 Mock 必须标未完成。
2. **参数链完整。** 每个新增领域命令核对业务 Schema→模型声明→SDK 解析→服务校验→持久操作/回执→恢复→UI 展示；共用校验不复制测试。传输截断、语义拒绝、业务冲突、正常等待、超时/未知结果分别处理。
3. **证据分层。** 真实 SDK + 可控 HTTP/数据库用于确定性错误/竞争测试；Computer Use + 普通提示检查真实页面闭环。记录首错、自动纠正、必要业务澄清与人工技术干预，不能用 helper 通过替代用户流程。
4. **预算不成为短会话限制。** 单次输出/上下文、请求时限、图步数、任务授权和验收总额分开；有进展且有授权可自动分段，无进展有界暂停。应用级摘要后改要求与保存必须计入同一账本。
5. **新证据不覆盖旧证据。** 每次真实验收另记范围和合理上限，不重置旧账、不重跑已完成部分；改变共享机制导致已有自动回归证据失效时，仅重跑受影响定向回归，不能据此重做旧业务生成。补 L02 等缺口采用新授权记录。
6. **状态及产品表述准确。** “已生成”“待确认”“已保存”“已发布”分别来自业务事实；简单用户提示不需要内部字段。总体完成条件是覆盖与机制证据闭合，不是模型永不出错，也不是一定优于旧助手的未经对照结论。
7. **收口检查不增加新平台。** 不引入可视化工作流、通用插件系统、默认多智能体、向量库、第二个判断模型、任意电脑/网页操控、云会话服务或双引擎自动回落。长会话使用已采用框架和真实业务状态；生成质量继续人工审核，不借重建恢复 400 条质量门槛。

暂不纳入当前承诺：现有正式页面未开放的项目/集合删除改名、已确认原始文件删除、版本合并/改挂、账号密码等新增管理功能；语音、聊天分支、侧边第二助手、嵌入浏览器/终端等截图附带能力。详见[能力清单 §6](assistant-rebuild-capabilities.md#6-不从历史接口自动扩大的范围)。如日后需要，单独定义产品合同。
