## 1. 实现边界

1. 统一现有历史列表和正式助手页面：旧 AI SDK 会话以 `legacy:` 引用只读适配，旧 Deep Agents 会话保持原运行时归属。旧消息、失败、要求、关联处理成果、成功回执与数字用量可查；管理本人会话支持改名和明确删除，浏览不调模型、不唤醒旧执行器。
2. 同运行时暂停/继续沿原会话、任务和授权；跨运行时只接收用户核对后的剩余目标及明确的新预算授权，建立关联的新会话。重复承接返回同一目标，不搬运旧消息、检查点、工具历史、确认卡或余额，不自动执行。
3. 新会话删除、背景移除、来源失效、项目成员降级/移除和全局管理员降级接入共享清理。清理消息、要求、流式正文、纠错快照、附件正文/对象引用及所有图检查点命名空间；撤销执行令牌、过期未提交确认、停止未完成处理，保留累计账和必要无正文审计。
4. 依赖登记覆盖现有资料读取、要求中的来源与处理轮次。未来领域票使用相同登记/失效接点，不另建历史后端或恢复状态机。沿用现有对象清理队列，并保护仍被其他附件/独立成果引用的对象。
5. 保留独立保存的草稿、处理文件和提交回执；清除处理上下文后，原处理来源详情不再从已清理输入重建。草稿记录正文、期望输出、Metadata、记录标识与修订不变，独立成果入口继续可读。
6. 前端用同一失效信号清理消息、工作区、输入和附件缓存，以内容代次拒绝迟到文档、结果和上传响应；公开正文读取在返回前复核权限与修订。普通修订竞争等待下次快照，不误报撤权。

背景与来源属于整个会话上下文：移除会清理该会话正文并终止其恢复，而非只隐藏一张附件卡。删除确认已说明这一范围，独立成果及累计账不级联删除。

## 4. 首次失败、审阅与补修

- 初始 3 项新回归先失败：旧会话管理缺失、附件仅标记移除而正文/检查点仍在、旧 AI SDK 历史没有统一读取/承接入口；随后实现对应能力。
- 页面测试暴露 legacy 路由重复编码，以及旧会话改名提交仍被只读按钮禁用；修复后，真实页面改名与新授权承接通过。
- 一次全文件运行的 8 项失败来自新夹具在原有零草稿断言前创建了草稿；移动到新用例内后，原断言保持不变。原“旧运行时禁止全部管理”断言按本票已批准的改名/删除合同更新，继续禁止旧执行写工具。
- 保存成果检查最初把清理后的来源展示也要求完全相等；现分别断言独立记录不变，以及已清理处理来源不再返回正文，而非保留失效处理链接。
- Standards 审阅发现 2 项 P1：事件插入与清理未串行、迟到预览/上传回执可能复活缓存。Spec 审阅发现 3 项 P1：legacy 失效字段不统一、同一迟到预览缺口、正式文档/历史分页缺少最终读取屏障（预览问题重叠）。均已修复，双轴针对性复核未发现新增 P1。
- 双连接事件红例确认：删除持锁期间到来的事件原先会在删除提交后带正文提交；现触发器先锁会话再判断失效。两个读取屏障和两个迟到预览均有受控竞争回归。
- 共用旧背景清理时额外复现了旧触发器将成功 receipt 置空、删除较老 checkpoint 预算的问题。现在统一使用清理函数，先标记失效以防递归，保留成功事实和各历史预算字段；补齐 owner 角色降级排序。对应红例和最后定向验证均保留。
