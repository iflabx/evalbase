## 3. 共用实施约束

1. **一份事实与输入合同。** 业务 Schema 同源生成工具声明，身份/权限/令牌/幂等键由服务端绑定。当前要求、交付、来源范围、保存目标分别有真实身份，展示是只读投影；不恢复多份 steps/stage/nextAction 共同驱动。
2. **有界纠正与可靠结果。** 只做无损协议归一；参数反馈、业务冲突、传输错误和正常中断分开。暂停/查询/继续使用同一持久任务与账本，未知写入先查原回执。模型口头成功不替代事务回执。
3. **覆盖人工能力但不绕过用户。** 原生文件、密码/key、确认和下载由受控页面协作；其他业务动作须有真实工具操作，不能用链接跳转冒充接入。简单明确操作不增加审批层。
4. **必要结构调整允许。** 以真实调用者和根因选修改范围；抽取共享业务合同、移出旧反向依赖、替代旧重复机制均在范围内。不为每个按钮建工具或多层包装。
5. **保留与退出分开。** 旧执行/计划/纠错/续步退出新路径；旧会话、成果、账本及删除保护保留。处理 Worker 内部 AI SDK 可继续使用。新旧执行器不共同推进同一任务，不失败自动回落。
6. **验证材料与业务数据隔离。** 只读核验既有验收数据/旧预算及关闭时间；新写入、删除和故障测试使用独立合成对象/隔离库。新迁移增量实施，不能为测试重建或清空验收数据库/对象卷。
7. **授权和部署。** 按明确开发/验收授权覆盖的步骤与进度表执行，不另加流程性审批。新增真实活动在执行前登记上限；超出范围或上限不能自动追加。更新 4217、正式部署、合并、推送仍按实际授权范围处理。
8. **文档与检查适度。** 各票只读受影响合同，复用未改变的证据；定向检查和一次适用关闭审阅按 AGENTS.md，不机械重跑全库。不引入多智能体平台、工作流编辑器、向量库、额外判断模型、任意网络/电脑操作或第二套会话后端。

### 3.1 消息提交防重与会话并发

<a id="message-submission"></a>

- **提交身份。** 一次用户发送携带稳定提交标识，作用域绑定当前认证用户、项目和会话；服务端保存消息正文、固定选择/附件引用及预期修订等执行相关载荷的摘要。同标识同载荷返回原消息/执行受理结果，同标识不同载荷拒绝。新标识即新请求，不能仅按相同文字去重，以免吞掉用户真实的再次操作；该标识不由模型生成，也不替代业务操作 ID。
- **原子受理。** 用户消息、防重记录和可恢复的待执行引用在同一事务中受理；绑定 REBUILD-03 的唯一执行身份后沿用原业务操作键。未提交则三者均不生效，提交后即使 HTTP 响应丢失或进程在派发前退出，也能查原受理结果、沿同一执行身份恢复，且最多一个活动执行者。受理回执只证明已收到，不表示生成/保存完成；不得靠检查点已经写成功来假定消息已受理。
- **并发与重放次序。** 每次访问先复检当前权限；已知同标识重发先核对原载荷/结果，不因原请求已使会话忙碌或修订前移而错误拒绝。不同提交使用当前会话/任务修订及独占受理检查，冲突者不得追加一条看似已接受的用户消息、启动第二个执行或静默排队；返回可理解的忙碌/修订冲突，保留输入。暂停控制仍优先，受控只读进度查询不启动业务执行。
- **前端交接。** 发送后保持未确认提交的标识与固定载荷，网络超时、重连、刷新后的核对/重发均复用它；旧请求的迟到响应不能清空后来输入。仅服务端确认为未受理后，才可按当前修订明确重新提交；未知结果不换标识猜重试。只保留必要的待确认提交信封，不新增离线消息队列或第二套消息权威。
- **责任与证据。** 02 验收同标识重放/载荷冲突及双标签并发受理，03 验收受理后派发前崩溃恢复与唯一执行，04 验收真实发送/刷新和输入保留，10 复核端到端关联。受控 SDK/HTTP/数据库与浏览器故障注入不占新增真实模型预算；重复 HTTP 受理不重复调用模型，任何实际发生的模型 HTTP 尝试仍如实计量。

### 3.1.1 交付创建、修改与当前执行合同

- 新增与修改使用明确命令：`create_requirements`只创建，`update_requirements`只修改或取消既有交付；服务端不以缺少交付ID解释为新增。修改未给ID时只允许绑定当前唯一活动交付；零份、多份或未知ID不得猜测。一个批次不能重复修改同一目标。
- 方案模式可保存不完整或多交付安排；切换执行前按唯一当前执行合同原子校验操作、固定输入、数量、字段、目标和加工规则依赖。投影、工具提交和页面使用同一就绪结果。明确取消最后交付转为非执行状态，保留取消身份并失效旧确认。
- 语义修复携带服务端已解析目标及有效领域字段快照，按显式交付ID匹配；补回该ID或同值继承字段不构成改变意图，其他ID及实际改变的受保护字段仍拒绝。每次业务校验重新固定当前可纠正字段，已修好的字段不能因旧路径残留被再次修改。同轮提交成功后的部分纠正重放只能核对原已提交事实并返回原回执，不产生第二次要求写入。
- 工具合同改变固定运行时版本。当前新会话为`deepagents-v2`；首批`deepagents-v1`会话/检查点保留只读及原成果入口，不用新工具重解释或唤醒旧检查点，不变更旧预算。完整历史管理/承接仍归REBUILD-08。

### 3.2 有效进展与无进展暂停

<a id="progress-contract"></a>

- **有效进展来自事实。** 同一目标内首次取得与目标相关的可信资料/新覆盖范围、分页游标实际推进、用户真实修改后的要求生效、新业务回执或作业终态均可计为进展。相同对象/修订/范围的重复读取、相同工具入参和等价结果、重复失败、仅换措辞/工具调用 ID/时间戳或增加事件序号均不算；不能沿用“新增 tool_result 即有进展”的判据。框架检查点前移也须对应这些新事实，不能只看检查点编号。
- **有界观察。** 只观察同一目标的自动推进，不把用户独立发起的只读进度查询累计为循环。复用现有工具结果/业务事实，在宿主维护最小持久观察状态，不增设判断模型或第二套调度器。每次已结束的业务工具尝试是一个观察点；没有工具尝试结束且没有新事实的一段执行也记一个观察点，有工具观察的段尾不重复计数。默认连续 3 个观察点无有效进展即以 no_progress 暂停自动推进；被动等待 Worker/用户确认、暂停本身及重复通知不是观察点；模型主动反复查相同进度仍是无进展，不能借“等待”豁免。参数纠错、传输及预算原有更紧上限继续优先生效。
- **跨段不清零。** 观察计数和已见事实绑定原任务及有效要求，跨图分段、摘要、进程恢复、普通继续与追加预算保留。只有实际新进展或用户真实修改要求后才开启新观察窗口，同义要求/仅提高修订号不清零；历史尝试和已耗预算始终保留。无进展暂停后先核对事实，没有新依据不得靠自动新段或普通继续重复同一循环，显示具体原因和修改要求/核对来源等恢复入口。
- **责任与证据。** 03 用真实 SDK 受控链路验证同查询同结果、重复错误、跨分段/摘要/重启后继续均不能绕过；也验证正常分页、读取新范围和业务终态能推进，不能误伤只读任务。02 只提供已有框架事件/当前事实，04 展示 03 的状态，不各自判定进展。10 复核证据，不为观察循环额外进行真实模型长聊。
