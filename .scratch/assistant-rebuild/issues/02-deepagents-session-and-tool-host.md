## 问题与目标

验证宿主绑定 campaign，并用单份、最多 10 条的处理要求合同驱动全部操作，不能承载正式通用助手和多领域任务。

目标是交付本票列明的真实行为，允许解决共同责任冲突所需的结构调整。不能用局部提示词补丁、原型按钮或 Helper 单测代替业务闭环，也不借本票扩张未批准功能。

## 修改范围

1. 保留已验证 createDeepAgent、LangChain 适配和 PostgreSQL 检查点，整理正式会话/消息/工具注册接口，脱离 REBUILD_VALIDATION_CAMPAIGN_ID。必要增量 DDL 纳入仓库迁移，不改写旧验证表或旧活动。
2. 工具声明从 REBUILD-01 的业务 Schema 产生，必要协议投影有一致性检查；对象引用取真实可见目录。只做无损格式归一，保持一条有限参数反馈路径，保留原调用与纠正关联。
3. 简单读取/编辑不强制填计划；只要方案时仅保存会话要求，不创建草稿/作业。复杂任务保留唯一有效要求与服务端稳定交付身份，名称、来源、数量、分类、保存目标分开，不编译旧 steps。
4. 要求修改具有修订，覆盖实际变更并失效受影响确认；相同要求只核对，不另起执行。多交付领域生成在 REBUILD-07，不能用数组序号或模型另造 ID 改写交付。
5. 复用框架摘要/上下文管理，保留当前要求、业务引用、停止/确认事实；摘要不成为第二份权威。加入模型调用计量钩子，正式授权与持久恢复归 REBUILD-03。
6. 明确工具允许清单及当前阶段开放能力；普通解释与可核对业务状态分开输出。状态断言交给 REBUILD-03 的事实投影，不另加意图分类模型或旧正则规划链。
7. 实现[Spec 消息提交合同](../spec.md#message-submission)：稳定提交标识/载荷摘要、原子消息及待执行引用、同标识结果重放、不同提交的修订/独占受理。持久受理先于启动执行；本票用受控执行器验证接口，03 接实际宿主恢复，04 接客户端重发，不新增依赖或独立消息队列。

8. 按[Spec 职责边界](../spec.md#runtime-responsibilities)补强模型创建与单次调用上下文，将具体模型组装移出宿主的执行协调逻辑；使用现有 BaseChatModel/ChatOpenAI、流式与传输钩子，不新建平行模型接口。每次模型调用/纠错准备读取当前要求、范围和可见引用；执行前仍复检权限/修订/令牌。计量只接03的既有账本，工具只走权威 Schema 与同一反馈路径。
