## 问题与目标

有限适配已证明部分暂停和保存场景，但正式任务账本、所有写入的未知结果恢复、可靠终态唤醒及准确事件分类尚未闭合。

目标是交付本票列明的真实行为，允许解决共同责任冲突所需的结构调整。不能用局部提示词补丁、原型按钮或 Helper 单测代替业务闭环，也不借本票扩张未批准功能。

## 修改范围

1. 复用 LangGraph 检查点/interrupt/Command 和既有 Worker，持久绑定执行、操作、job/run 与终态。提交后等待不轮询模型；丢失或重复通知可从业务终态核对且只推进一次。
2. 停止入口优先于忙碌消息，事务失效令牌；保留已提交回执，拒绝未提交迟到写入。查询只读，继续恢复同一任务未完成范围；单次请求时限不累计人暂停时间，原已耗次数不退还。
3. 固定确认绑定用户/项目/动作/范围/目标/修订/有效期/操作 ID。采用、发布、删除、管理与额度仍由用户批准；改要求/撤权/修订变化使旧卡失效。
4. 业务成功与回执同事务；框架检查点丢失或确认响应未知时查原操作回执，不重分配键。成功回执不能被后续模型总结失败覆盖，过期卡不能回填为本次成功。
5. 正式任务授权、追加授权和累计消耗与验收 campaign 分开；在模型 HTTP 边界计入正文、摘要、纠错、Provider 重试及未知结果。区分输出/上下文容量、单请求时限、图步数、任务预算与验收上限。
6. 按[Spec 进展合同](../spec.md#progress-contract)持久记录有效进展与连续无进展观察；有授权且有进展可分段自动继续，无进展与额度耗尽分别暂停。退出现有“tool_result 序号增加即有进展”的判据，普通继续/摘要/重启不能清空观察。新授权使用明确 offer，普通继续不清零。统一状态投影与事件类型，正常等待/interrupt 不计参数失败；任意解释性回复不能越过权威保存/预算结论。
7. 接 02 已原子受理的消息与待执行引用，绑定同一执行/业务操作身份；进程在受理后派发前退出时可恢复领取，不重新插入消息或新建任务。消息防重与业务回执防重各守其边界，共用既有数据库/检查点，不增加另一执行队列。

8. 按[Spec 职责边界](../spec.md#runtime-responsibilities)分离自动派发/定时恢复/进程关闭与单次执行协调；调度只调用既有 ExecutionStore，租约、令牌、预算、确认和恢复状态不另存副本。所有领取、唤醒、扫描恢复与确认恢复入口使用同一受支持运行时版本合同；旧版本不被唤醒。诊断日志保留安全的身份/错误分类，不吞掉后台异常，不输出正文或凭据。

## 验收标准

- [x] **R03-1** 业务已提交但检查点/HTTP响应丢失，恢复查同一操作仅出现一次实际写入及一份回执；不同参数不能重用旧键。以真实采用服务证明，其他写能力由领域票接线。
- [x] **R03-2** job 提交后宿主重启、终态通知重复/丢失、要求更改或暂停竞争：结果归正确执行，只推进一次，等待期间助手模型请求数不增加。
- [x] **R03-3** 执行中暂停→只读查询→超出旧单次时限后继续可恢复；停止令牌生效后旧写入拒绝，完成批次不重跑，任务/预算身份不变。
- [x] **R03-4** 双击、失效确认、撤权、改范围和提交中响应丢失均核对真实回执；模型不能通过任何普通工具自行确认或追加额度。
- [x] **R03-5** 跨执行分段、摘要后修改保存、限额耗尽、新 offer 追加、超时/未知请求都能对账；追加不改变旧消耗，等待和仅浏览历史不产生模型费用。
- [x] **R03-6** “已生成/待确认/已保存/已发布”、停止中与已暂停由业务事实生成；answer_question 误路由也不能伪证保存。事件区分正常生命周期、参数失败、业务冲突与传输错误。
- [x] **R03-7** 按 Spec 默认连续3个无进展观察点暂停；重复读取/失败及仅事件编号前移不能续命，跨分段、摘要、重启和普通继续保留计数。正常分页/新范围/真实业务终态能推进，等待不计无进展；旧预算和实际请求计数保持。
- [x] **R03-8** 已受理但尚未派发时崩溃恢复，以及同消息重发与恢复并发，只启动一个执行；原消息、业务操作键、账本与回执可关联核对。受理重复不产生第二轮模型调用；实际已发请求包括未知结果仍入账。

## 定向验证

1. 真实 SDK/HTTP/数据库受控故障：在消息受理后派发前、业务提交与检查点间、终态通知前后及令牌失效位置注入中断；验证消息重发与恢复竞争的唯一执行。
2. 用可控时钟/小阈值验证长会话、多段和预算边界；无进展回归同时覆盖重复查询/重复失败的负例与正常分页/新事实的正例，明确跨摘要/重启继承。不能用真实长聊烧额度；执行中暂停要记录实际在途时间。
3. 复用适配已有 R/F 证据，仅重跑受改动影响的回归；真实普通提示在 C02 和 C07，不重新消费旧活动。

4. 追加验收沿[真实入口合同](../spec.md#real-entry-validation)补自动派发、竞争领取、租约过期、版本隔离及暂停组合。使用受控 HTTP 模型和隔离数据库，先通过公开入口证明“自动开始”，再断言恢复和唯一业务结果；不得用手工调用执行函数掩盖未派发。既有C01/C02证据保留。
