## 问题与目标

原工具和小样本适配未覆盖完整 task/run/round、已保存成果再处理、从零多交付及所有保存目标；这些不能由换 Harness 自动获得。

目标是交付本票列明的真实行为，允许解决共同责任冲突所需的结构调整。不能用局部提示词补丁、原型按钮或 Helper 单测代替业务闭环，也不借本票扩张未批准功能。

## 修改范围

1. 接处理任务列表、固定输入范围、清洗/改写/扩充及当前/历史结果、Metadata、来源和结构核对；复用现有 Worker、字段保护和场景分配。
2. 接结果筛选/选择、精确去重排除与恢复、选中成果继续、冻结输入重跑、失败部分重试、实际缺额补齐及已保存草稿继续处理。明确各模式，未选成果保留，成功部分不得借重试重复执行。
3. 接背景驱动从零生成，不伪造种子或强要原始记录。以 REBUILD-02 的稳定交付身份处理多份目标、分类/配额、改数量、改名、另存和取消；总数从当前明细计算，旧同义数量不参与执行。
4. 保存回原草稿、另存原始数据/新草稿/已有草稿均使用固定目标与确认；清洗改写更新对应行，扩充追加，未知保存查原回执，冲突不换目标。
5. 保留批次参考与逐条来源的真实差别；按任务/轮次输出真实保存名称、对象、链接。复用结构检查与人工内容审核，不增设模型语义质量门禁或另一轮次状态机。

## 主要修改位置

- src/processing/ 任务、轮次、生成、候选、采用与来源服务。
- src/assistant-rebuild/ 的处理/生成工具与当前交付引用。
- frontend-v3 处理结果、候选审核、来源与保存卡片的复用接入。

以上为实际调用点导向，不是强制目录设计；已有清晰函数直接复用。未列出的受影响调用者可一并调整并在验证记录说明，不增加无真实调用者的通用层。

## 验收标准

- [ ] **R07-1** W01～W16 全部模式逐项接线；继续所选、重跑原输入、失败重试、补缺和已保存继续在正确 task/run/round 内执行，历史只读，未选保持。
- [ ] **R07-2** 清洗/改写一对一与扩充新增语义正确，受保护字段保持；重复组排除/恢复不删原件，跨批数量按净有效结果报告。
- [ ] **R07-3** 普通提示两份交付、2＋2 改为 3＋2、取消第二份、改名另存：身份/要求/分类/数量/保存目标一致；同名歧义才澄清，不索要内部 ID。
- [ ] **R07-4** 后台等待、局部失败和模型超时保留已完成成果；只能在当前授权内处理未完成范围，无限补缺、换任务清账或重复生成不得发生。
- [ ] **R07-5** 保存回原草稿及各另存目标经真实事务验证，未知结果恢复不重复追加；名称、对象、来源与链接一致。
- [ ] **R07-6** 完成[Spec C05](../spec.md#verification)：普通提示先规划两份分类交付及一份混合练习，随后取消混合练习并将剩余两份改为3＋2，再执行并分别确认保存；后续扩充2条保存回原草稿。取消项无作业/生成/保存/可执行确认，刷新后不复活，剩余交付继续正常。取消的真实 Computer Use 证据是 RB13 必需项，受控 SDK 不能替代。

## 定向验证

1. 真实 SDK、实际 Worker/处理服务的模式矩阵与多交付增量/取消/恢复回归；取消第二份、取消与执行竞争及其他轮次/失败组合仍由受控链路覆盖，与 C05 普通提示取消相互补充，不直接重跑旧业务成果。
2. 来源文档/输入、字段修订、当前成果及保存回执逐项对应；内容仅小样本人工检查，结构正确不声称语义合格。
3. C05 记录取消前后交付身份、要求/确认状态与剩余成果；只有两份保留目标生成/保存一次，后续处理限定所选。取消并入原修改轮次，不增加真实会话或生成量；超过外层额度保留结果并停止，不跳过取消或更换会话救场。

预算与执行边界：Spec C05：最多 24 次实际请求、32 处理行次、12 新增生成槽位、25 分钟；计入第二批共享上限。补强后仍计划生成3＋2＋2＝7条，第三份只规划后取消，规划/取消模型请求如实计量；上限不增加，具体核算见 Spec。 普通提示、逐项上限、停止条件和证据口径以[Spec 验证安排](../spec.md#verification)为准。此处记录未来执行约束，不表示已创建活动或批准本次运行。
