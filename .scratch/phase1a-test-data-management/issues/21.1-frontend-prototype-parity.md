## Acceptance criteria

1. `/` presents the frozen project-list geometry: page header, search, table fields, row density, 10-row pagination, name and `查看` actions; it does not use an external-link affordance.
2. Inside a project, the sidebar presents the current project and its `数据集` / `测试集` children in the frozen hierarchy, and its switcher can choose another project or start the existing new-project dialog. Before Ticket 23, `测试集` is a clearly inactive staged item, not a fake route or a new page.
3. The Dataset index matches the frozen control order, table columns, badges, status colours, pagination placement, and create/upload actions. It has no right information panel, rename, deletion, or prototype-external action.
4. New-project and new-dataset dialogs match the frozen simple-dialog structure: title, explanation, name, optional description, close control, and donor-based footer actions. Creating a project still explains that it creates `未整理`.
5. Confirmed upload remains exactly two steps: select files and target Dataset, then per-file source-field/sample/mapping table plus real unified-record preview before one batch confirmation. It does not add parser configuration, governance fields, original-content browsing, or file browsing.
6. `frontend-v1/` remains unchanged. Donor decorative animation/transition may remain only when it adds no operation, page, state, or workflow and respects reduced motion.
7. No backend request, response, database schema, storage behavior, or public API is widened by this Ticket.
