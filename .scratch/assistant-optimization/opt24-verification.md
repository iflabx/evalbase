## 实现与边界

独立地址为 `/projects/:projectId/assistant` 和 `/:sessionId`；侧栏、顶部和原始文件/草稿/版本入口导航到页面。首页恢复最后可用的个人会话；记忆项不在首分页时单独复检，而不是当作不存在。失效记忆回落列表或空态，显式失效深链接保留不可访问提示；刷新和导航不创建空会话或运行。

桌面保留会话栏，无成果时以对话为主；审核态对话/工作区按约 35/65 分栏。工作区提供“结果”和“资料与要求”，支持展开结果。内容宽度小于 1100px 时收起会话栏，切换对话/工作区；输入、候选选择和页签滚动保留，表格内部滚动。现有背景、要求、方案、停止/恢复、候选来源/差异及服务端确认卡复用原组件；会话重命名/删除沿用原个人权限和资源规则。

未发送文字与未确认提交保存在当前浏览器标签内，按账号/项目/会话隔离。失败重试沿用同一消息、参数和幂等键，旧响应不清除后来输入。示例只填入；运行中可编辑文字，不新增并行发送队列。“按方案执行”沿既有 turns 接口携带当前 task 修订，服务端在原会话锁内核对；旧修订 409，不执行旧方案。对象导航/选择不修改现有任务。

安全 Markdown 使用 React 文本节点渲染段落、列表、代码和简单表格；原始 HTML 仅作文本，链接/图片不建立执行或外部嵌入。真实操作卡只来自服务端提案。提示版本 v4、工具合同仍为 v3；底层权限、固定范围、事务和确认规则不改变。

现有 sessions GET 支持个人名称搜索和分页；单会话 GET 增加可选 `view=status|messages`，消息使用稳定 before 游标，默认每页 20。无参数仍兼容旧完整响应。状态投影不返回历史正文，去除执行输入 ID 数组和内部任务诊断；消息只读取当前页。完整来源/历史依赖的访问检查继续执行，个人隔离、角色变化和内容修订复检不因分页降低。背景正文和候选按需读取；活跃阶段轮询，隐藏页暂停、待确认/终态停止，前台恢复核对。

## Owner 简短检查

1. 进入侧栏“项目助手”，核对原个人会话、历史和背景附件；刷新/返回不新增会话。
2. 在同一会话打开“资料与要求”和“结果”，输入但不发送一段文字；切换页签、收窄窗口，确认输入和勾选仍保留。
3. 用少量资料先“只设计方案”，核对未执行，再点击“按方案执行”；候选和确认仍采用既有范围和权限规则。
