## 实现与兼容性

批量读取列表摘要、完整轮次的来源访问依据和最新批次事实。来源批量与单项检查共用原可用性规则，个人背景仍按所属用户校验。权限过滤后仍按更新时间取最近 100 项，再搜索、状态筛选和分页。

已同步的稳定任务不加任务写锁、不读取结果正文；变化任务仍使用原锁内汇总。当前页成果引用与任务修订一起核对，发生并发变更最多重新读取一次。采用回执当前页查询一次，旧回执按未解决身份及祖先关系读取必要运行，同请求复用结果。

## 定向回归和审阅

- 公开列表的原始 RED 复现稳定列表逐项取得四个任务写锁；优化后约束为零写锁、零正文读取、一次回执查询及 ≤15 次 SQL。
- 两个受影响集成文件 `processing-task-rounds.test.ts`、`processing-runs.test.ts` 的 32 个不同用例分批验证通过：首次组合执行 31 个通过、1 个新用例的夹具失败；修正夹具为真实部分继续处理及历史采用返回 201 后，最终相关两项和 >100 项回归通过。未声称在一个最终全量命令中通过 32 项。
- 覆盖真实公开 HTTP/执行器、独立测试库及对象桶：当前成果替换/追加/重做、部分完成、旧配方、采用/幂等、并发保存与新增轮次、来源清理、权限、私人背景、最近 100 项及五类筛选。104 项隔离样本用确定性清洗构建，无真实模型造数。
- Standards / Spec 同一基线的独立审阅发现一个 P1：批量输入中仍有第二轮记录时，旧第二轮回执可能被跳过，漏算第三轮记录的保存状态。修复为按未解决身份和祖先链判断必要旧回执；部分继续处理的三轮混合成果回归先失败（已保存 1，预期 2），后通过（2/3 已保存）。必要旧对象各回读一次。
- 该修复仅作定向复核，无剩余 P0/P1。稳定新回执及无关旧回执均不读取正文；保存统计测试和扩大样本测试在修复后再次通过。
- `npm run typecheck`、受影响四个 TS 源文件及集成测试的 `eslint`、`npx tsc -p tsconfig.server.json`、`git diff --check` 和固定代码 Docker 构建通过。
