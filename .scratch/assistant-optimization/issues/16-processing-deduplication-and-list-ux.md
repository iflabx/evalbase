## 1. 去重与有界补齐

### 统一规则与范围

- 完全重复按问题、期望输出、Metadata 的实际内容确定；忽略记录 ID、来源、系统时间，Metadata 键值相同但排列不同按同内容处理。比较不修改原值，不额外做大小写、标点或语义归一化；清洗明确授权的空白整理先按原规则执行。
- 问题相同但期望输出或 Metadata 不同，只提示“问题相同，其他字段不同”，供用户核对，不自动合并。意思相近不自动删；Metadata 合法空值保留，空问题/结构缺失分别报告。
- 服务端复用同一确定规则完成生成、结果核对和保存前检查，按整次有效结果计算，不受分页、搜索和批次边界影响。扩写同时排除与固定输入完全相同的新候选；目标草稿已确定时，比对其授权范围内的当前记录。更新已有行时排除自身映射，不把自身认作重复。
- 保留顺序稳定：既有目标记录优先保留，新增候选按原结果顺序每组保留第一条。只在当前任务/明确选择范围内排除或移除；不跨项目扫描、不合并来源身份，不顺带清理目标草稿中的其他重复行。

### 扩写

- 新扩写默认按“有效且不重复的新增数量”达到目标：如目标 100 条、去掉 10 条多余重复行后保留 90 条，仅补缺少的 10 条，再做整任务核对；输入数量与新增目标分别显示。
- 复用已有 Worker、分批、缺失恢复和配方机制。一次任务最多追加两轮补齐，每轮仍按既有批次/请求容量拆分，并受既有尝试、耗时及模型预算约束，任一上限先到即停止；预算不因补齐或自动恢复重置，不叠加另一套无界重试。
- 补齐沿用原范围、要求、字段保护和分类配额；发送已接受结果的必要去重摘要和真实缺额，完整请求仍受原输入上限限制。保留成功候选的身份、内容和来源，只增加缺失的新候选。
- 正在补齐时显示实际进度；结束不足则显示“已获得 96 / 100 条有效结果”，提供“补齐剩余 4 条”或“采用现有 96 条”。前者由用户发起下一次有界续做，复用 OPT-13 关系和已有成果；后者明确为部分采用，不标记完整目标已达成。停止、刷新和重试不重复纳入成功结果。
- 自动去重仅调整候选有效集合，不自动采用、发布或删除已保存数据。历史成功运行不后台改写；用户可通过下述结果操作处理其未保存候选。

### 结果页与清洗

- 在现有结果工具栏增加“去重”；有完全重复时可用，无重复时隐藏。作用于当前完整已选集合，预览明确“检查 X 条，每组保留一条，排除 Y 条”，跨页/筛选外已选范围仍清楚。沿用列表展示重复标记和“只看重复”入口，不增加常驻说明卡。
- 去重后重复候选退出本次采用集合，可“恢复排除”回到操作前选择；底层原始资料及历史结果保留。部分已保存结果通过真实保存目标继续处理，不能借此抹掉旧采用回执。
- 扩写结果去重后可补齐原目标；清洗/改写去重后只减少重复，不调用模型补造记录，不因用户主动去重而误报执行缺失。无需用户用长提示词描述去重规则。
- 保存回来源草稿时，单纯不选某个结果不等于删除原行。只有明确选择去重时，才形成可核对的重复行移除清单；在现有保存确认中集中显示目标及“更新 X 条、新增 Y 条、移除 Z 条重复记录”，无需逐行再确认。移除仅限本次明确范围和可追溯的草稿行。
- 沿用事务、权限、草稿/字段修订、容量及幂等保护，更新/追加/移除同次原子提交。目标变化或来源失效时保留候选和选择，要求核对；不能静默覆盖、扩大删除或在保存时偷偷再调用模型。另存新草稿/原始数据只保存选定结果，不删除来源草稿。
- 手动处理与项目助手共用结果和保存规则；助手的有效数量、已有候选和确认范围保持一致，不另加规划器或独立去重工具链。

## 2. 来源准确表达与收纳

- 生成行沿用简短摘要，如“模型扩写 · 参考 100个问题_new.csv”；详情明确为模型生成内容。将“实际参考资料/参考位置”的逐条强归因改为“任务参考资料/任务参考范围”，不把整次输入或模型返回 sourceId 当成逐条引用证明。
- 默认按文件汇总，一行显示文件名及真实可核实的参考数量；“查看任务参考范围”默认折叠，展开后分页或限制滚动高度，保留可访问记录链接。不能把截取的前 10 条说成全部，也不为每个结果默认铺开同样十条蓝色链接。
- 范围说明仅在详情中保留一句：“以下为任务参考范围，未记录本条内容与具体参考记录的一一对应关系。”已有历史信息不够时明确未记录，不推断批次或逐条引用，不为了此展示新增细粒度引用系统。
- 处理过程保留真实顺序，保存位置保留真实成果入口，中间文件继续折叠。手动页、草稿来源和助手复用同一展示；权限、回收/删除约束继续生效，不通过文件名、数量或记录链接泄漏不可访问来源。

## 3. 三个列表的间距与分页

适用原始数据列表、测试集列表、数据处理任务列表及其直接共用组件，不扩展为全站重排。

- 工具栏到表格、表格到分页统一使用 frontend-v1 对应的 12–16px 间距；分页紧跟表格并对齐左右边缘，左侧数量、右侧翻页，不固定在视口底部。
- 已加载和空态按实际内容高度排布，移除正常态持续保留的 344px 最小高度、无内容的反馈占位和空分页容器。加载/切页期间才复用必要骨架或前次尺寸，结束后释放；保留 OPT-14 的缓存、请求减量、旧响应保护和轻量过渡。
- 刷新提示放在工具栏附近，关键错误与恢复操作仍直接可见。一个页面只有一页时只显示总数，隐藏“第 1/1 页”和无效的上一页/下一页；零结果隐藏分页，表格区域保留紧凑空态和适用的清除搜索/创建/上传入口。
- 筛选或搜索仍回第 1 页；数据减少使当前页越界时回到有效页。不得因布局调整丢选择、输入、滚动位置或短暂闪出错误空态。

## 4. 执行状态筛选收敛

筛选名称使用“全部状态”，选项固定为五项；每行状态仍表达实际进度，不修改后台原始执行状态机。

| 筛选项 | 覆盖状态 |
| --- | --- |
| 全部状态 | 当前授权查询范围内全部任务 |
| 进行中 | 排队、处理中、自动等待重试、正在取消 |
| 已完成 | 执行完整结束；结果质量与保存状态另行表达 |
| 需处理 | 失败、部分执行完成或停止补齐后仍未达到目标，需要用户处理 |
| 已取消 | 已确认取消；正在取消不提前归入此项 |

搜索、分组过滤、统计、分页使用同一集合，在服务端分页前完成分类；保留当前最近 100 项的查询边界及可发现说明，不只过滤浏览器当前页。不把重复质量提示或“未保存”一概归为执行失败；等待自动重试与等待用户操作分别归类。

## 最小实施边界

- 只调整以上行为及直接调用方，复用现有去重比较、处理运行/有效结果、确认回执、来源详情、列表外壳与 donor 组件；必要的持久状态优先复用已有运行/产物结构。新任务采用版本化配方，旧运行的输入、成功批次、身份及恢复语义不被新代码静默改写。
- 不新增依赖、向量库、语义查重、跨项目查重、工作流平台、模型逐条引用体系、批量历史清理或新的设计系统；不提高模型并发、输入容量和预算，不为本张重构整个助手。
- 去重规则与补齐会改变处理/保存行为，不能作为纯文案改动跳过事务与恢复检查；间距/文案按展示修改做定向验证即可。无需每个小步骤再次请求 Owner 开工或验收。
- 后续获授权实施时沿用同一 4217、现有项目与管理员/编辑账号，保留用户数据，临时边界夹具在隔离测试中使用。一个 Ticket、一次集中 checkpoint；合并、推送、tag、正式部署不包含在本张授权中。

## 验收标准

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| R16-1 | 相同三字段、不同来源/ID、Metadata 顺序及合法空值；同问题不同输出/Metadata | 完全重复判定前后一致；无关身份和键值排列不制造不同内容；合法空值保留，其他差异只提示，不误删 |
| R16-2 | 100 条扩写含跨批重复及与固定输入/目标草稿重复 | 排除多余行，按完整有效集合仅补缺额；成功身份保留，最终统计、分类配额、助手与采用一致 |
| R16-3 | 补齐再次重复、到达预算/次数上限、取消/恢复 | 自动补齐最多两轮且不突破既有预算；部分成果保留，真实显示不足，续做不重复已有成果，部分采用不冒充达标 |
| R16-4 | 结果跨页选择、只看重复、去重/恢复、清洗及历史结果 | 作用范围明确，保留代表稳定，可恢复选择；清洗不补造；未选中和已保存历史内容不被自动删除 |
| R16-5 | 去重后保存回原草稿、另存、重复提交、并发修改/撤权 | 确认包含增改删数量；仅明确范围内可追溯行可移除；事务幂等，冲突保留候选；另存不删原草稿，无权限不能写 |
| R16-6 | 多文件/多参考生成结果、连续处理、历史缺失和不可访问来源 | 默认文件汇总、参考范围折叠、数量真实，未伪造逐条引用；处理顺序及保存入口保留，不泄漏来源 |
| R16-7 | 三列表零条、两条、多页、搜索无结果、刷新/错误、桌面/窄窗口 | 工具栏/表格/分页间距紧凑；单页无无效按钮、零条无分页；加载不闪错空态，输入和选择保留，无整页横向溢出 |
| R16-8 | 五种分组、各内部状态、部分完成、质量提示、未保存与翻页 | 分组和数量覆盖完整查询范围，搜索后分页正确；具体进度仍可见，取消中/已取消及执行/质量/保存互不混淆 |
| R16-9 | 受影响页面 donor 对照、键盘操作 | 直接复用 frontend-v1 样式；新增操作少而明确，详情折叠与筛选可键盘使用；关键异常和保存后果不藏进帮助 |

## 验证与交付

- 实施时用可控模型响应定向验证跨批去重、有限补齐、字段/配额保护与恢复；用已有数据库/HTTP 夹具验证保存删除清单、修订冲突、幂等、权限和来源生命周期。复用现有用例，避免为比较函数和 UI 同义包装重复造测试。
- 浏览器集中检查去重/恢复/保存、来源详情、三列表短表/空态和状态筛选，含一组桌面与窄窗口 donor 对照；真实模型仅做必要的小样本连通与补齐验证，不用反复生成 100/200 条证明确定性去重。
- 按实际影响运行类型、lint、必要构建和上述定向回归；不默认做全仓测试、压力测试或长时间稳定性测试。仅重建实际改动服务，并在同一 checkpoint 记录固定代码与健康状态；没有实际执行的验证保持 pending。
- 实施时更新受影响架构/测试计划的最小差异，详细证据集中一份并互链。当前仅检查本 Ticket、Spec 索引和 PRD 引用的 Markdown 及一次 `npm run docs:check`，不运行应用测试或构建。
