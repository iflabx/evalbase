# OPT-20 项目助手失败诊断与短请求测试基线

Status: ready-for-agent
Implementation: completed
Blocked by: none

优先级：P1。2026-10-14 Owner 已单独授权本张开发。依赖现有 OPT-19 后的实现，不等待旧 Ticket 人工验收。完整范围以 [总方案 §4、§9](../../../docs/assistant-workspace-reliability-plan.md) 为准；产品继承 [PRD §7](../../../docs/PRD-data-selection-and-assistant.md#7-ai-04-项目助手)。

## 目标

用户能知道失败发生在哪一步、保留了什么以及如何处理；开发人员能区分模型服务、参数、业务约束和应用故障。用现有设施建立可比较的短请求基线，先量化当前问题。

## 实施范围

- 在现有模型请求/Agent 终结边界归类传输、限流、服务异常、配置拒绝、输出协议/结构、参数校验、领域冲突、权限/来源、应用内部错误和预算暂停。优先复用现有处理层分类，不能将所有未知异常归到模型故障。
- 为一次任务/回合关联现有 ID、代码/模型配置/提示及工具契约版本、步骤、HTTP 状态、finish reason、耗时、请求尝试次数和已保留成果数量。字段可空时如实标明未知；不推断旧记录诊断。
- 统一反馈最小形状：原因、当前步骤、已保留结果、允许的下一动作及诊断编号。副作用确定性来自可信校验/回执；异常文本不能证明未执行。普通页面显示可行动的简短提示，详情按需展开。
- 复用现有 HTTP 假模型、数据库/对象存储测试与真实模型脚本，整理总方案 A1–A10 为同一可按案例运行的轻量脚本和结果文件。模型/工具契约配置与输入版本固定；无新监控或评测平台。
- 记录修复前小样本基线，包括助手自己修正、用户澄清、人工语义纠错；不要求先把问题全部修好才完成本张。敏感业务正文和密钥不进入诊断文件；测试仅使用隔离样例。

## 不做与落点

本张不改变重试预算、工具开放范围、要求失效逻辑或页面导航；后三者由后续 Ticket 承接。主要涉及 `src/assistant/agent.ts`、模型请求边界、现有诊断/错误呈现及测试入口；只有直接共用需要才提取函数，不预先拆整个 agent 模块。

UI 复用 frontend-v1 的现有错误区、按钮和折叠明细；不新增常驻诊断卡或开发者工作台。正常运行时不多显示一屏技术文案。

## 验收与定向验证

| 编号 | 验收 |
| --- | --- |
| R20-1 | 假模型分别返回 429、5xx、401、畸形输出及网络失败，分类可区分，正常结果与既有回执语义不变。未知应用异常不得冒称模型输出错误。 |
| R20-2 | 领域失败保留具体字段/范围和已有成果；数据已写入而汇报失败时显示真实成果，错误区不建议全量重做。 |
| R20-3 | 日志/接口不含凭据、完整提示或业务正文；查看角色、其他账号和项目不能读未授权诊断/成果。 |
| R20-4 | A1–A10 可单独选择运行并输出固定版本、目标是否完成、恢复及人工介入；真实基线报告样本数和未完成原因，不填虚构成功率。 |
| R20-5 | UI 只有真实失败时显示原因与可用动作，展开详情不改变任务；旧无诊断会话正常读取，明确“无详细诊断”而不杜撰原因。 |

先针对现有笼统模型错误建立定向回归；只运行受影响错误/权限/输出路径和必要静态检查。记录一次修复前基线供后续复用。未来实施/检查点依 [总方案 §10](../../../docs/assistant-workspace-reliability-plan.md#10-tickets依赖与交付)，保留 4217 数据。

## 受影响 UI 对齐

沿用项目助手原消息/错误区、frontend-v1 的文字颜色与间距、现有原生折叠明细。失败消息显示简短原因和下一动作；“诊断详情”按需展开步骤、保留数量及编号。旧无诊断回合显示无详细诊断说明；正常消息、卡片顺序、确认按钮和页面入口保持既有布局。桌面与 860px 浏览器检查通过；详细命令与限制统一见验证记录。
