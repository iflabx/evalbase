# OPT-01 可靠结果与可恢复执行

Status: ready-for-human
Implementation: completed
Blocked by: none

[Spec](../spec.md)、[合同](../../../docs/assistant-optimization.md#1-可靠结果与失败恢复)。Owner 已授权整体目标；既有基础依赖已实现。

## AC

1. 清洗/改写/局部调整缺失输出显示未完成，保留成功候选，有限自动补回或明确恢复缺失；重试不改已有成功候选及身份。
2. 按实际完整结果核对目标数量、Metadata/期望输出分类及明确配额，不把模型声明当证明；语义仍待内容审核。
3. 助手能从明确用户请求与固定选取中解析处理范围，不要求用户提供 recordIds。未知或歧义来源不擅自扩大。

## 公共接口与首个反馈循环

- reused：processing-runs 提交、读取、status、retry；助手回合/计划/read_processing/retry_processing；候选局部调整。
- narrowed：完成/重试的解释只符合真实缺失范围；公开操作和权限不扩大。
- retired：无。
- 第一个 red：真实模型执行两条改写只返回一条；公开 HTTP retry 仍返回 succeeded，而不是恢复缺失，后续没有补回。
- green：已成功候选不变、失败批有效结果保留，重试只送缺失的输入；公开完整结果两条，数量核对准确。

## 前端对照

| 位置              | 控件与顺序                            | 状态与边界                                                                                                                  |
| ----------------- | ------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| 处理结果/助手任务 | donor 当前进度、已有结果表、重试/停止 | 显示服务端实际缺失数量；旧任务虽为 succeeded 但缺失时也保留重试入口；有效结果保留；仅缺失重试，不添加假成功                 |
| 候选核对          | 原数量及分类呈现，追加分类/配额差额   | 全量统计，数量正确但分类或配额不符时明确显示实际/要求；空问题与完全重复不能标记完整；语义待审核；后续宽工作区由 OPT-04 负责 |
