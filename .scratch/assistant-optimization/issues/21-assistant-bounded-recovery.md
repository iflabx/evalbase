# OPT-21 项目助手模型请求与执行有界恢复

Status: ready-for-agent
Implementation: not-started
Blocked by: OPT-20

优先级：P1。2026-10-14 仅授权方案与 Tickets。详细合同见 [总方案 §4](../../../docs/assistant-workspace-reliability-plan.md#4-失败如何恢复)，技术边界继承 [现有架构 §9](../../../docs/architecture/data-selection-and-assistant.md#9-方案执行与预算续做) 和 [ADR 0014](../../../docs/adr/0014-project-agent-and-processing-runtime.md)。

## 目标与范围

- 429、明确临时 5xx 与短暂网络错误在对话请求层有限恢复。单请求最多额外 2 次、单回合合计最多 2 次传输重试；沿用同一 80 秒等待截止信号，遵守 Retry-After 和总预算。只有一个重试层，不能重放整个 Agent 工作流。
- 401/403、确定性配置/协议不兼容、领域约束、权限和草稿冲突不走无差别重试。参数纠错继承既有有界回合和连续同错停止规则；各阶段统一使用 OPT-20 的反馈和诊断。
- 停止、撤权及截止时间取消后不再发新请求；旧执行令牌不能提交数据。所有等待计入原总时间，不提高模型步数、工具数、续做、executor、会话或 Worker 限额。
- 在现有恢复入口统一核对未知写入，沿用原操作键及参数；查到回执继续后续工作，尚无法核实时保留未知状态，不用重建计划或换键强行执行。
- 处理已完成而模型总结失败时按真实回执结束该处理步骤并保留其他未完成工作。失败的说明不触发第二个处理运行。
- 复用现有进展/循环守卫，恢复只能推动未完成工作；不把反复读同一结果、重复计划或重复报错当新进展。与 Worker 的恢复次数、补齐和手工重试预算不叠加重置。

## 边界

不加外部队列、调度服务、critic、自动换模型或降级到不同语义的模型；不通过加长超时掩盖故障。保持历史 processing recipe 与成功产物。本张先修现有对话调用及恢复边界，避免重写全部调度器。

页面只用现有反馈区显示正在恢复、暂停和真实成果，按钮能力来自服务端。沿用 frontend-v1 样式，不引入新的轮询/动画体系。

## 验收

| 编号 | 验收 |
| --- | --- |
| R21-1 | 429 后成功、一次 5xx 后成功、持续临时失败均按单请求与单回合预算执行；两个不同模型步骤不能各获得新重试额度。记录尝试和退避。 |
| R21-2 | Retry-After 超出剩余时间、总超时、用户停止和撤权均停止发请求；401/403 不重复请求；原步骤/工具/租约限额不被绕过。 |
| R21-3 | 副作用提交成功后丢响应、恢复途中再次失败及连续点击恢复，均只存在一份业务结果和正确原操作回执。结果未知时无重复提交。 |
| R21-4 | Worker 部分成功/补齐/失败后由助手继续时，保留成功候选且累计恢复额度不重置；重复计划/重复只读不无限续做。 |
| R21-5 | 最后总结失败仍能查看并审核有效成果；权限冲突显示准确恢复条件，不返回“重新全部处理”。旧已提交任务可读取。 |

使用现有假模型故障注入验证时序和请求计数，不对真实模型服务制造限流，不重启服务器。重跑 A9、A10 及受影响短请求；无需每张重跑真实 200 条。交付遵循 [总方案 §10](../../../docs/assistant-workspace-reliability-plan.md#10-tickets依赖与交付)。
