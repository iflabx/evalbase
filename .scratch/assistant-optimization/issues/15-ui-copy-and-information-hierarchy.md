## 目标与依据

减少常驻说明、重复统计和技术化表达，让用户优先看到数据、当前状态与下一步操作。UI 继续严格对齐 frontend-v1；删除说明后自然收紧空白，不重做页面布局或另建视觉体系。

继承 [当前 PRD](../../../docs/PRD-data-selection-and-assistant.md)、[领域词汇](../../../CONTEXT.md)、[现有架构](../../../docs/architecture/data-selection-and-assistant.md)及[前端复用约定](../../../docs/architecture/phase1a-frontend-reuse.md)。本张集中记录本次 Owner 确认的展示修订，覆盖早期原型/文档中对应说明的常驻位置，不改变其业务含义。冻结原型保持只读。

### 文案和展示原则

- 优先删除同义说明，其次缩短，只有用户确实需要进一步解释时才提供帮助入口；不把每句话都替换为问号图标，不增加引导弹窗、教程系统、首次访问持久状态或全局文案配置层。
- 关键决策信息直接展示：保存到哪个对象、所选数量、更新还是追加、操作是否成功、是否仍有未保存内容、自动检查不等于内容正确。详情补充背景，不能替代这些信息。
- “来源未记录”“状态尚未确认”等表示真实缺失/不确定性；可以缩短和降低视觉权重，不得用空白或成功标签掩盖。未知写入不能改成“失败，请重新创建”，仍提供现有同次操作核对入口。
- 错误文案用“发生什么 + 可以怎么做”表达。保留当前输入、恢复操作、权限不足/冲突/断线提示及必要的操作限制，不能为简洁把它们移入默认折叠区域。
- 只调整系统界面文案及展示位置。用户填写的名称、用途、处理要求、背景原文、数据内容，以及模型回复和历史消息不删改；不通过修改模型提示词、摘要算法或执行流程实现界面精简。
- 使用现有 Button、Tooltip/Popover、折叠区、表格和状态组件及 donor token；帮助可通过键盘和点击访问，不能只支持鼠标悬停。删除可见说明时同步检查标签与描述关联，不留下失效的 `aria-describedby`。

## 实施边界

1. 正式界面仅修改 frontend-v3 的受影响页面/共享展示组件及已有相关断言；frontend-v1、frontend-v2 和冻结原型只读。原始数据列表已经相对简洁，不为了统一而新增说明或重排。
2. 不改变接口、权限、数据表、处理算法、Agent/Worker、模型调用、保存/发布/删除确认、字段保护、来源身份、选择范围、幂等与修订冲突机制；OPT-14 加载与缓存规则继续有效。
3. 不以本张顺带整理其他页面、旧数据或历史任务。正常使用仍只需原有操作；简化不能增加保存、选择、编辑的点击步骤。折叠仅用于辅助说明/历史，当前待处理内容和关键错误不折叠。
4. 后续获授权实施时复用当前分支、4217、既有项目和管理员/编辑账号，保留用户数据。一个 Ticket、一次集中展示验收，不逐页设置人工 checkpoint；不自动合并、推送、打 tag 或正式部署。

## 验收标准

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| R15-1 | 处理列表、新建入口、处理配置正常态与空态 | 有内容时没有重复流程介绍；空态仍能找到下一步；选择数量集中且正确，清洗规则和不可用操作的原因可理解 |
| R15-2 | 跨页/筛选后仍有已选记录，切换处理方式 | 用户能区分匹配数量、总已选和提交范围，筛选外选择不被隐藏；字段授权规则及实际提交范围保持原行为 |
| R15-3 | 处理结果、保存回原草稿、另存及历史未知信息 | 处理完成、检查问题、内容审核和实际保存互不混淆；确认前可直接看见目标、数量和更新/追加含义；成功有真实成果入口，未知状态不冒充成功或确定失败 |
| R15-4 | 测试集列表、草稿未选中/选中记录、已保存/未保存 | 重复标题/统计减少，分页信息集中；编辑入口、来源、修改者和真实保存状态保留，原自动保存及离开保护不变 |
| R15-5 | 个人资料、成员邀请和角色选择 | 标签足够清楚；重复说明移除；权限解释可查看，待处理邀请直接可见，历史数量及展开内容正确 |
| R15-6 | 助手空会话、已有任务、背景附件和候选审核 | 空态有引导，任务中突出当前事实和下一步；详细要求/步骤/操作记录可访问；附件限制可查，采用/发布仍走原确认，模型回复及历史不被截改 |
| R15-7 | 保存失败、冲突、断线、未知结果、权限不足 | 关键异常直接显示一次并有实际恢复入口，输入保留；不隐藏失败、不放开安全禁用、不触发额外写入 |
| R15-8 | 桌面与窄窗口、键盘使用、受影响页面截图对照 | 严格沿用 frontend-v1 风格；删文案后无残留空卡/大片占位、整页横向溢出或关键标签缺失；帮助/折叠内容可键盘访问，正常操作步骤不增加 |

## 验证与交付

- 先定向核对受影响文本及组件调用方，再按表完成同一轮浏览器对照；每页记录主要删减/保留点即可，不另建全站文案审计系统或重复平行文档。
- TS/TSX 修改运行前端类型检查；更新确实受文案/折叠影响的既有浏览器断言。条件显示、帮助或折叠若新增逻辑，只验证对应交互和可访问性；失败/冲突等用现有可控夹具，不实际破坏验收数据。
- 不为纯文案删除新增镜像测试，不默认跑全仓后端/集成测试，不做压力测试或真实模型重跑。实际 checkpoint Web 构建即作为本次构建检查；未改服务不重建。按根 AGENTS.md 比例规则决定其余直接相关检查，不因 Ticket 编号自动触发重度实施流程。
- 任务文档变更仅核对差异、Markdown 链接/表格/围栏并运行一次 `npm run docs:check`。后续交付提供受影响页面的简短验收路径、固定代码版本及实际检查结果；未实施前不宣称改善或验收通过。
