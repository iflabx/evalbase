## 目标与证据边界

让用户通过普通短句完成解释、规划、修改要求、执行和暂停，组合请求保留顺序与作用对象；明确按钮与文字操作最终受同一服务端约束。查询不误触发重试，修改先真实保存再执行，旧回调不能覆盖新决定。

当前代码已有意图判断：agent.ts 中的 requirementsOnly / planningIntent 正则、规划恢复与暂停分支、模型提示词、prepareStep 工具限制及固定执行短句。问题是决策分散，不是完全没有意图识别。本票来源于源码审查和已确认方案，不声称本轮复现了新的误执行；不以“增加分类节点”承诺消除全部模型或内容错误。

## 修改范围

### 1. 集中本轮操作决定，复用现有语义模型

- 在现有消息入口集中解析本轮决定，包含真实目标/选中范围、要求变更、操作方式及必要澄清。操作方式复用现有解释/查询、只规划、执行和暂停语义；“修改”可与规划或执行组合，不建一组互斥的技能分类标签。
- 明确 UI 操作沿已有控制/确认接口进入；若原按钮发送固定中文，改为原请求中最小的受限操作标记，绑定当前会话、任务及修订。服务端校验操作来源、权限和状态，模型输出或附件内容不能伪造用户点击。旧客户端请求保留必要兼容，不新开公开路由。
- 自然语言仍交给现有主模型，使用本条输入、必要历史、当前生效要求、待回答问题、当前交付及选中范围。优先复用 plan_task 和既有工具参数表达业务决定，只有缺少的控制语义才增加可选字段；纯查询可以直接读与回答，不强制建计划或保存新要求。
- 只对明确的结构化命令做确定性分派；自然语言的否定、引用、先后顺序、指代和组合请求不能继续靠扩充关键词列表裁决。新入口替代的同功能正则/分支应退出生效路径，保留真实旧任务所需兼容，不留两套互相覆盖的权威。
- 决定与当前回合/修订绑定，task仍为持久状态权威。仅在既有回合诊断中保留必要操作摘要、来源及原因码，不另存一份执行计划，不保存模型思维过程。

### 2. 组合请求与澄清

- “先给方案，别生成”：仅必要查询和方案保存，不创建处理任务或草稿来冒充规划完成。
- “每类改成20条，先不执行”：经原合同校验保存新要求，不执行；“每类改成20条，然后继续”：先更新并保存要求，再核对受影响步骤、范围和剩余额度，只执行获准未完成部分。不能只口头确认，或先按旧数量提交后再改摘要。
- “先暂停，再修改数量”：先落实暂停后续推进，再处理有效要求变更；后续参数校验失败仍保留已经生效的暂停。用户未要求恢复时，更新成功不解除暂停。复用现有有序步骤与更新入口，不新增动作脚本或通用工作流。
- “为什么失败”“解释执行流程”仅查询解释，不由本轮入队新处理、重试或后续执行步骤；此前独立获授权的后台运行不因此被自动取消，反馈真实运行状态。“不要继续生成，先解释”则持久暂停后续推进；取消运行中任务沿已有取消接口及回执，不谎称 Worker 已停止。
- “先解释方案，再开始执行”须保留用户明确顺序和执行要求，在原范围与预算内处理，不能因为出现“解释”就丢弃后半句。
- “继续”“好”“就这样”结合当前明确待答问题和既有授权解释。有唯一有效下一步时沿现有恢复；仅规划授权、多个可能目标或操作后果仍不明确时，问一个业务问题。明确执行请求不重复询问开工；任何文字都不替代采用/发布的固定确认。
- 附件引用、旧消息和模型输出不授予新权限。目标只从当前真实对象、选中记录或同交付回执解析；界面导航、同名对象或旧任务不能偷换范围。内容涉及GB或其他文档使用相同机制，不按文档名、分类编号写分支。

### 3. 共用执行守卫与恢复

- prepareStep 工具可见性、实际副作用工具调用及 advanceExecution 消费同一经校验决定；工具隐藏之外仍在实际提交处检查。未知/无效决定不能默认映射为执行。
- 普通回合、恢复与自动事件继续共用权限、taskRevision/执行令牌、固定范围、字段保护、预算和操作回执。自动事件只沿已有授权推进；暂停/只规划状态不因为后台完成、参数纠正或旧响应转为执行。
- 参数错误沿现有归一和有限纠错处理，不能换工具、重规划或借修复参数扩大意图范围。无法修正时保留输入与真实成果，给业务解释；用户不需要输入内部工具字段。
- 修改要求后按既有规则核对受影响成果和确认资格，保留已完成记录及历史证据。查询不会改写业务要求或给整个任务永久加上暂停；也不能为了纯查询绕过现有修订和旧响应防写检查。
- 继续前对账未知操作，复用成功回执，不重跑完成步骤。沿OPT-39冻结的事件额度及原调用/时间限制；刷新、恢复、改要求均不能清零计数、扩大预算或自动启动新任务绕开上限。

### 4. UI 与诊断范围

仅调整已有按钮请求、必要澄清及状态反馈，沿用frontend-v1组件和样式；不新增意图面板、置信度、分类配置页或常驻说明卡。用户看到实际已保存要求、已暂停/仍运行状态和可行下一步；内部参数错误放诊断详情，不能把已识别意图显示成操作已成功。

## 验收标准

| 编号 | 可验证结果 |
| --- | --- |
| R42-1 | 普通“先给方案，别生成”真实保存有效方案；查询、规划、后台完成等路径均零新生成/采用/发布。简单查询不强制建立方案，原业务数据与预算上限不变，实际模型消耗照常累计；允许正常消息/回合记账。 |
| R42-2 | “改成20条，先不执行”更新实际要求及摘要；“改成20条，然后继续”只在更新成功后使用新合同执行。更新失败时零旧参数提交；目标、字段和未受影响成果保持。 |
| R42-3 | “先暂停，再改数量”持久暂停且有效修改可保存；修改失败不撤回暂停。暂停后旧响应、后台事件、参数纠正和刷新均不能启动后续步骤；运行中取消状态取真实回执。 |
| R42-4 | “为什么失败”“解释执行流程”及引用“立即执行”只查询回答，不自行重试；“先解释，再开始执行”保留顺序与明确授权。查询不永久改变既有控制状态，未更改要求不伪造新内容合同。 |
| R42-5 | “继续/好”在明确待答问题、已有执行授权、仅规划、待确认和已耗尽预算等不同状态得到正确行为；有实质歧义只问一个业务问题，明确执行不重复确认，文字不能代替固定采用/发布确认。 |
| R42-6 | UI控制与等价自然语言受同一业务守卫；非法操作标记、跨用户/会话、过期修订、跨交付及失效选中记录被拒绝。“这两条改自然些”只作用明确选中范围，页面切换不扩大任务。 |
| R42-7 | 决定字段缺失/错误、未知动作及工具参数纠错均不能默认执行或越权；已知无副作用错误可在原预算内纠正，未知写入先核对。既有回执只收口一次，完成步骤不重跑。 |
| R42-8 | 无决定新字段的旧会话可按真实任务状态读取与恢复；不批量迁移聊天、不改旧成果/预算。多交付继续采用OPT-39的归属与计数；40/41尚未实现时本票定向验证可独立完成，不伪造内容核对通过。 |
| R42-9 | 完成下述有限真实短提示和Computer Use检查，逐条核对持久要求、实际工具/Worker调用及界面状态；保留失败与内部纠错次数。不能仅凭回复正确、提示词包含规则或Mock通过宣布真实意图理解通过。 |
| R42-10 | 明确按钮控制不新增意图模型请求；自然语言无强制额外分类服务。记录定向流程的请求数/耗时及新增决定造成的额外回合；采用/发布仍固定确认，界面保持frontend-v1。 |

## 定向验证与完成口径

以下为原定验证合同；本轮实际执行结果及未完成部分以[验证记录](../opt42-verification.md)为准，不能把原计划当作已通过。

1. 先复用现有公共消息、控制及业务入口，以约20个表驱动状态组合覆盖R42-1–8：否定与正向、引用与真实命令、修改与继续、暂停竞态、明确选中、旧任务、参数失败、未知回执和预算边界。验证真实持久状态与调用次数；语义输出可用可控响应，避免为每个异常分支调用真实模型。受影响旧回归复用，仅重跑失效范围。
2. 一次隔离新会话使用简短非GB规范，按普通提示测试“先规划2条 → 改为1条但不执行 → 询问当前状态 → 改回2条并执行 → 暂停并解释 → 根据实际待办继续”。提前固定输入及预期，不中途改成内部工具参数提示来凑通过。最多新增2条候选，不采用、不发布，不操作原验收会话。
3. 上述真实验证共享最多12次实际模型请求、累计模型活动时间5分钟的上限；所有规划、生成、审核、参数/传输重试及自动续步均计入，并服从原运行更严的限额。达到任一上限停止并记录未完成，不换会话或重置预算继续。上限是后续验证计划，不是本轮调用授权，也不占用或重置OPT-41及旧验收预算。
4. 同一次Computer Use核对按钮反馈、澄清、要求与实际状态；服务端日志/持久事实补证后台边界。已有相同输入、固定代码下仍有效的证据直接复用，不另开大批生成或重复基线实测。
5. 通过仅表示本票固定场景和执行边界有效，不承诺任意自然语言零错误。失败、存疑、预算未完成和Owner pending如实记录；后续部署仅在相应授权范围内复用4217及现有数据。

## 复杂度与排除范围

保留AI SDK和现有数据库/Worker；优先在agent、任务入口和既有控制请求中收口，仅在多处确需复用时提取小函数。无需新表、公开路由、独立意图模型、训练语料系统、规则引擎、向量库或多智能体；不重做所有历史状态，不增加每轮必跑的分类调用。

40的生成质量/同题去重、41的审核证据/预算分配、39的自动额度算法各自保持归属。源数据、已保存成果、248条及400条验收事实和旧预算保持，保留约束见 [OPT-31衔接](31-rewrite-effectiveness-and-quality.md#本次修复衔接与既有验收保护)。本票文档完成不代表任何旧验收通过，不合并、推送或部署。
