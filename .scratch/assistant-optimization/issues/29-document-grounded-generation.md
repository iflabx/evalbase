# OPT-29 依据背景文档从零生成与能力预检

Status: ready-for-agent
Implementation: completed
Blocked by: none

优先级：P1。第二批。依赖 [OPT-26](26-tool-contract-and-error-feedback.md)、[OPT-27](27-intent-and-plan-continuation.md)、[OPT-28](28-result-scope-and-goal-count.md) 的相关自动验证通过。已按后续 Owner 单张授权完成开发，Owner 人工验收 pending；实施和验证见 [OPT-29 记录](../opt29-verification.md)，完整边界见 [三批修复方案](../../../docs/assistant-generation-repair-batches.md)。

## 问题与目标

当前处理必须提供真实输入记录，缺少“用背景要求从零生成”路径；计划没有识别能力缺口，导致创建空草稿后反复提交失败。补齐一个实际可执行的生成能力，不再要求用户手工创造种子或把 PDF 假装成原始数据。

## 修改范围

- 在现有处理服务增加明确的无记录生成模式/命令，冻结当前用户要求、数量、允许生成的输出字段、背景版本/哈希及必要页段。与 assets/draft/version 的记录处理合同区分；不把允许空数组扩散到清洗、改写或现有基于记录扩充。
- 沿用现有队列、Worker、分批执行、预算、取消、恢复和候选存储。新候选身份由服务端分配，不要求模型编造 `sourceRecordId`；无源记录时不套用“继承未修改输入字段”，期望输出和 Metadata 按已确认生成要求校验。
- 背景引用由服务端解析，只能使用当前用户有权读取的会话资料；权限、撤权及删除清理延续现有规则。处理配方冻结实际依据；来源显示“依据背景文档生成”及真实页段，不列虚构参考记录，也不向其他成员泄漏私人原文。
- 在规划和执行前做轻量能力/前置条件检查：区分文档可读、记录已选、从零生成等情况。必要模型、背景或目标缺失时在副作用前说明缺少什么，不能写出实际无法执行的步骤后靠盲重试推进。
- 助手工具、计划和后台执行共同支持此模式；从现有独立助手页面发起，结果复用当前审核、局部处理、采用和发布。依据文档创建多个测试集时，复用现有步骤/交付状态保存类别、目标和成果引用，逐类推进，不做并行编排平台。
- 来源类型和生成配方只做必要兼容扩展；现有三类记录来源及旧冻结任务恢复不变。先更新受影响的接口/配方说明再落实现有服务，不新增第二套生成页面。

## 非目标

不加知识库、RAG、向量检索、OCR、自动联网搜集或 GB 专用分类器；不绕过采用/发布确认，不把单纯声明“支持生成”作为交付，不使用人工种子作为从零生成成功证据。

## 验收标准

| 编号 | 验收 |
| --- | --- |
| R29-1 | 新会话上传有权访问的 PDF 后，普通短请求“按文档生成，先给方案”只读取和规划；无草稿、处理任务或候选写入，方案能正确说明执行条件。 |
| R29-2 | “按方案执行”可从零产生候选；不读取任何原始记录，不需人工种子/字段纠错，服务端身份稳定且三字段结构符合要求。先验证 5–10 条，再验证第一类 50 条。 |
| R29-3 | 空输入清洗/改写和旧扩充仍按原合同拒绝；缺背景、无权限、模型未配置在副作用前可理解地失败，不把背景 ID 当资产 ID。 |
| R29-4 | 中断、取消、刷新、有限重试和未知写入恢复后保留候选及真实回执，不重复创建同一草稿；预算不会通过新模式绕过。 |
| R29-5 | 八个各 50 的方案在同会话保存独立交付项，首类不会生成 400；已完成类别不重复，后续类别能按既有授权继续；本张不要求真实完成全部八类。 |
| R29-6 | 核对后沿现有固定确认保存/发布；来源真实，私人附件正文不向无权用户公开，旧记录来源和旧配方定向回归通过。 |
| R29-7 | UI 仅补必要模式/来源/进度信息，复用 frontend-v1 组件风格；结构成功与内容待审核分别表达，不标记尚未完成的八类交付为完成。 |
