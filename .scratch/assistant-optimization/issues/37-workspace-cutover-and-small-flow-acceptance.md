# OPT-37 工作区接入、旧任务兼容与小规模闭环

Status: ready-for-agent
Implementation: completed
Blocked by: none

优先级：P1。依赖 [OPT-36](36-execution-receipts-and-recovery.md)，传递依赖 OPT-34/35；使用这些票的定向证据，不重复跑完整套件。治理入口：[整改方案 §8](../../../docs/assistant-remediation-plan.md#8-2026-10-18-业务编排收敛整改)。2026-10-19 用户已单独授权开发、定向验证及更新同一 4217；实施与全部失败见 [验证记录](../opt37-verification.md)。Owner 人工验收 pending，内容质量与 OPT-31 原八类验收未代签。

## 目标

把新的目标与执行合同接入当前独立项目助手，使用户通过普通短请求、现有审核和确认完成小型任务；保留旧会话、成果与验收数据。此票包含必要接入、兼容和旧路径退出，不单独建立样式或测试项目。

## 修改范围

- 在现有助手页面及服务端读取/控制入口接入 OPT-35 的生效交付目标和 OPT-36 的执行事实。显示各交付目标、实际进度、保留成果和当前需要用户处理的事项；成功摘要来自真实保存/执行回执，历史工具诊断折叠。
- 继续、重试、后台完成与确认采用都沿同一执行合同；真正缺少用户业务决定才提示澄清。正常用户不需要输入工具名、内部 ID、JSON 或技术纠错提示。沿用现有固定采用/发布确认，不自动采用，不增加重复开工确认。
- 正式 UI 修改在 `frontend-v3/`，复用现有助手、结果和确认组件。字体、token、图标、间距、密度及适用组件严格对齐 `frontend-v1`；不新建工作台、不扩展导航、不改冻结原型。
- 新建任务使用新合同。按持久任务的可选合同版本区分旧任务，不能只按会话新旧或部署时刻猜测；正在执行的旧运行继续使用其冻结配方，不中途更换解释方式。旧会话保持可读，恢复只依据真实引用与回执；无法可靠补齐时保留成果并说明业务缺口，不批量解析历史聊天或重建全部数据。
- 清点已被替代的模型参数入口、推进分支和派生状态写入，删除无消费者部分。保留必需且集中的旧任务兼容边界；记录其消费者/退出条件，不长期维持两套供新任务选择的控制器。
- 获得本票开发与 checkpoint 更新授权后，才在保留数据的同一 4217 更新受影响服务；固定应用代码提交并核对版本、健康、就绪和真实前后端请求。本票已按用户后续授权实施该切换，数据保护与版本证据见验证记录。

| R37-4 | 规划/生成/等待/待审核/失败/部分保存有明确状态和实际成果入口；已恢复错误不继续压在当前成功结果上，未完成事项也不被隐藏。业务目标与可见数量一致，桌面和窄窗口可操作。 |

## 最小验证规模与判定

- 本批真实模型集中在 R37-1/2 两条同会话流程：初始目标共 16 条，R37-3 仅调整其中 2 条。提示、文档及预期结果在运行前固定；保留首次失败及每次有明确修复原因的定向复测，不重复跑到碰巧成功。
- 用 Computer Use 或既有浏览器流程执行上传、方案、执行、审核和确认；后台只读核验可作为证据，不能绕过页面写入或通过直接改库修通。允许业务澄清和现有固定确认；内部参数修正、手工种子和开发者代写长提示均记为干预，不算无干预闭环。
- 16 条结构全查并逐条复核内容是否符合要求；明确区分模型原生合格、自动修复、人工修改及存疑。框架闭环、内容核对、人工采用分别记录；不能以条数齐全或模型自评为全部可用证明。真实质量未通过时如实保留 OPT-31 的待解决项，不据此新增模型或扩大本票算法范围。
- 本批以两条无技术干预的业务闭环及关键故障回归作为合入新路径的门槛；它不等于所有文档/模型零错误保证。若存在内容不合格，明确报告其范围，不能将整个助手验收标为通过。
- 不新增 400 条生成、5/10 人压测、两小时稳定试验或验收服务器重启；OPT-31 已有八类失败及后续内容验收继续保留，不由本票缩小数量代签通过。后续大规模复验按单独明确范围执行。
