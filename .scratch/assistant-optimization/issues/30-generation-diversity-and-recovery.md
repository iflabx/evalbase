# OPT-30 生成场景分配与有界重复补齐

Status: ready-for-agent
Implementation: not-started
Blocked by: OPT-29

优先级：P1。第三批。依赖 [OPT-29](29-document-grounded-generation.md)，复用 OPT-28 目标与成果合同。本次仅文档，开发待后续授权；证据及共同边界见 [三批修复方案](../../../docs/assistant-generation-repair-batches.md)。

## 问题与目标

已有去重、批次偏移和重试仍出现 92 条中 72 条完全重复。目标是让生成批次承担明确不同的场景任务，只补实际缺额；预算耗尽真实报告部分成果。不能仅提高温度或加一句“不要重复”就声称解决。

## 修改范围

- 复用 `src/processing/protocol.ts`、`execute.ts` 和现有配方：按用户要求形成简短、可持久的场景分配与每批生成范围，涵盖不同使用情境、问法和必要分类；每批获得自己的目标及已使用场景摘要，避免反复生成同一小组变体。
- 场景分配复用已有方案/模型上下文和批次机制，不额外建立策划智能体。用户不必填写场景矩阵；不预先生成完整 400 条塞进提示词，也不硬编码 GB 或金融主题。
- 保留已有确定性完全重复检查，并将新候选与当前有效成果比较；将已接受内容的有界摘要、明确重复原因和剩余场景传回后续请求。跨批、补齐和局部处理都沿同一目标/有效集合计算缺额。
- 同问题不同期望输出识别为需核对的碰撞，不能无条件当作完全重复删除；近似表达不引入向量相似度或自动语义判死。所需内容审核与自动去重边界在 OPT-31 展示。
- 格式错误、超时、内容重复、数量不足分类计入已有共享额度；有效候选保留，补齐只请求缺额。达到总预算停止并给出剩余量；显式继续也不能把故障重试伪装成新任务重置原额度。
- 配方与必要采样参数变更记录版本，旧任务按原版本恢复。参数调整须通过同输入的小样本证据判断，不武断归因于温度或某个模型。

## 验收标准

| 编号 | 验收 |
| --- | --- |
| R30-1 | 可控模型返回跨批完全重复、空问题、有效内容混合时，只计有效成果；目标 50，已有 20/48 时剩余 30/2，补齐不扩大目标或删除原成功结果。 |
| R30-2 | 本批、跨批及与当前任务成果的完全重复被正确处理；同问题不同答案作为碰撞待审核，合法对照样本不会被无条件删除。 |
| R30-3 | 连续重复或超时耗尽共享预算后终止，保留有效数量、原因及可恢复范围；换自动回合/重试入口不绕过额度，既有停止和撤权仍有效。 |
| R30-4 | 真实第一类 50 条采用明确场景分配，记录请求数、完全重复数、有效数、耗时和内容审核结果；相同基础要求下与审查基线比较，未达 50 不记为成功。 |
