## 目标与依据

用户可以对处理后的结果继续清洗、改写或扩写，不必为每个中间步骤先创建原始文件或草稿；也可以明确使用上一轮原始输入重新运行。每轮结果可回看，最终满意后再保存。

产品合同见 [PRD §6.5](../../../docs/PRD-data-selection-and-assistant.md#65-处理结果再次处理增补2026-10-12)。继承 [CONTEXT](../../../CONTEXT.md)、[处理架构](../../../docs/architecture/data-selection-and-assistant.md)、[ADR 0014](../../../docs/adr/0014-project-agent-and-processing-runtime.md)、[前端复用约定](../../../docs/architecture/phase1a-frontend-reuse.md)和[批次约定](../spec.md#整改批次执行约定)。本张定义新手动入口，不改变已有“候选局部调整”的领域含义。

### 已核对的现状

- 代码基线 `c097969f4861b153e9e83d4ea93c8fe5b31f13d1`，4217 最近前端样式提交为 `d7a22fc`；实施前再次核对实际 HEAD 和环境。
- 成功且无缺失输出的任务没有继续处理入口；“重试未完成批次”仅恢复失败或缺失批次。新建处理只支持原始文件、版本、草稿。
- `src/processing/refine.ts` 已支持对指定未采用候选建立改写运行，并保留未选候选、最初采用身份及草稿基线；`src/server/modules/processing.ts` 注册 refinements 接口，项目助手是现行调用方。该能力目前固定为 rewrite，不能直接当成三种处理方式的通用入口。
- 已有保存回执及原始数据/草稿入口可以复用；新任务不得以保存为前置步骤。

## 修改范围

### 1. 三种操作明确区分

| 操作 | 输入范围 | 结果与入口 |
| --- | --- | --- |
| 继续处理所选 N 条 | 当前任务处理后的、明确选中的可用且未保存结果 | 结果表工具栏，与“保存所选 N 条”并列；新建后续任务 |
| 重新运行 | 所选历史任务提交时的完整输入快照和记录范围 | 任务摘要的更多菜单；进入配置供调整，提交才新建任务 |
| 重试未完成批次 | 原任务真正失败或缺失的部分 | 保留原恢复入口及协议，不重跑已成功部分 |

任务已经终止且有可用结果时允许继续处理，包括失败/取消任务留下的成功结果；不能把局部成果继续处理说成原任务已全部完成。运行中不开放继续处理或重新运行，避免输入范围仍在变化。零条可用结果时说明原因，并保留适用的原重试入口。

### 2. 继续处理当前结果

- 沿用跨页勾选、搜索/筛选及隐藏选择提示；数量针对完整已选集合，不限当前页。未选时禁用，并提示先选择记录。
- 点击后进入已有配置页的继续处理状态，显示“来自上一次处理结果”、来源名、处理方式、时间、所选数量及返回上次结果入口；内部运行 ID 不作为主要标题。
- 输入只包括选中的结果，问题、期望输出和 Metadata 均取上一轮实际结果，不能偷偷改为原始记录。未选结果留在原任务，本轮结果表和数量不混入它们。配置内可缩小范围，不能隐式扩大到原任务全部记录。
- 复用清洗/改写/扩充（扩写）配置及完整三字段预览。下一轮要求由用户填写，上一轮要求可折叠查看，不直接作为新指令自动提交；默认字段保护按既有规则，切换方式不扩大授权。扩写明确“参考输入 N 条、预计新增 M 条”，结果只包含本轮新增内容。
- 点击开始前不创建后台任务、不调用模型。取消返回原结果页，保留原搜索、页码和勾选；查看来源、前进后退及未提交配置保留沿用 OPT-12，按账号/项目/父任务及输入集合隔离。
- 提交后生成新运行，原运行及结果保持不变；新结果可继续同样操作。清洗不填语义要求时沿用确定性规则，不能为了串联而一律调用模型。

### 3. 重新运行原始输入

- 更多菜单使用“重新运行”，配置页明确“使用上次提交的输入重新处理”，预填原方式、要求、允许字段及扩充数量，允许调整。这里的原始输入指**该任务自己的输入快照**：若它本身来自上一轮结果，不回溯到链条最初的文件。
- 复用当时固定的记录范围、内容和解析视图；不重新抽样、不读取最新草稿替换旧快照，也不因原任务结果页勾选改变范围。用户若要处理来源当前内容，使用“查看来源”后已有的新建处理入口。
- 原快照缺失、来源失效或当前无权访问时明确拒绝并给出适用的返回入口，不推测历史、不扩大范围；不能借旧快照恢复被删除内容或绕过个人背景权限。
- 明确提交视为一次新的处理意图，不复用旧运行的完成状态；同一次提交的重复点击、超时和重试仍必须返回同一新运行。模型调用使用当前可用且获准的连接及受支持配方，并记录实际配置，不承诺复现旧模型输出。

### 4. 保存、历史与来源

- 已保存记录通过真实回执标明，提供“打开已保存数据/草稿”入口；从保存后的对象再发起处理，以该对象当前内容作为新的输入。历史任务已保存不等于禁止查看或明确重新运行其原始输入。
- “继续处理”不接受已保存候选。混合勾选时说明已保存数量、提供移除这些选择的操作，由用户调整后继续；不能静默跳过或伪造未保存身份。提交时再次复核并发保存，旧页面不能绕过限制；历史无法可靠判定时明确提示核对，不猜测。
- 后续任务保留父任务链接；任务列表增加紧凑的“继续处理自…”或“重新运行自…”信息，新结果提供返回上一轮入口。不新增任务流程图或多级向导。
- 沿用原始文件/原始位置、实际处理链及最终保存回执。清洗、改写保留记录对应关系；扩写为新生成身份并保留真实参考来源，不冒充原文记录。不能把所有来源名称替换成处理任务编号。
- 多轮改写后保存到来源草稿仍核对最初字段基线和实际累计改动；不会因新运行而获得覆盖他人修改的权限。扩写后再清洗/改写仍是新增记录的后续处理，保存时不能变成更新原始参考记录。
- 原任务与后续任务分开查看，不能在单次结果页自动合并、重复计数或自动保存。保存、发布仍由用户明确确认；沿用稳定候选身份、幂等和 CAS，跨轮重复保存及并发冲突不能通过换运行 ID 绕过。

## UI 严格对齐 frontend-v1

**正式实现仅修改 frontend-v3，字体、字号、颜色 token、间距、圆角、阴影、图标、按钮、表单、表格、菜单、卡片及反馈直接复用 frontend-v1 的样式和适用组件。** 延续当前“原始数据”“测试集”及已补修数据处理页面的紧凑层级；frontend-v1、frontend-v2 和冻结原型保持只读。新交互以本张 Owner 决策及 PRD §6.5 为依据，不另创一套视觉语言。

| 位置 | 控件顺序与层级 | 空态、错误与键盘要求 |
| --- | --- | --- |
| 结果工具栏 | 选择范围/数量 → 继续处理所选 N 条（次要按钮）→ 保存所选 N 条（主要按钮） | 无选择、运行中、含已保存结果分别解释；沿用 donor 等高按钮 |
| 任务摘要 | 原状态/要求 → 返回上轮轻链接 → 更多菜单中的重新运行 | 不堆叠另一张常驻说明卡；未完成恢复入口保持清楚 |
| 继续/重新运行配置 | 返回链接及输入摘要 → 三字段输入表；原紧凑处理设置区 | 两种输入含义明确；保护字段、容量和连接失败原地提示 |
| 任务列表 | 原表格与筛选分页 → 行内简短关联说明 | 长名截断但可查看，不能靠内部 ID 区分 |
| 已保存成果 | 原保存回执和成果入口 | 缺失或无权目标不泄漏内容；不显示假链接 |

桌面沿用 OPT-12 双栏比例和密度，窄窗口上下排列，横向滚动仅在必要的表格内部。按钮、菜单和返回入口可用键盘操作，焦点可恢复；失败保留已选范围和要求，不用原生 confirm 代替 donor 反馈。

## 实施边界

1. 复用 processing 的冻结输入、运行、Worker、结果读取、来源、采用回执和已有配置/核对组件。实施前盘点真实 HTTP 与助手调用方，再决定现有接口必要扩展；不预设新表、迁移、依赖或外部工作流平台。
2. **手动继续只处理所选集合；助手局部调整仍保留未选候选。** 不直接把现有 refinement 的全量保留行为套在新页面，也不为手动入口破坏助手多批有效成果、稳定身份、固定确认或自动续做。必要适配限定在处理业务边界，禁止顺带重写 Agent 架构。
3. 所选身份、快照及摘要由服务端核对；正文分页读取，不将全量正文提交到浏览器再回传。继承 5 资产、10,000 条及原有字节/请求预算、模型并发与批处理上限；多轮不得绕过这些边界。普通查看不调用模型，不增加高频轮询。
4. 继续和重新运行均复检权限、项目、来源/背景生命周期和目标修订。未知提交结果用同一请求及键对账；失败保留输入和已完成结果，不能无限自动重试。
5. 只补连续处理需要的导航和关联，不建设可视化流程编排、自动串联无限任务、结果合并平台、模型选型平台或候选内联编辑器。不修改服务器其他项目。
6. 实施时同步受影响的架构及测试计划；若需要新增领域词条只补本张明确语义。当前 Ticket 和 PRD 增补只表示已确认待开发范围，不作为功能已交付证据。
