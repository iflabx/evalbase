# OPT-03 背景文档与持久依据

Status: ready-for-human
Implementation: completed

Owner 已授权完整优化目标。以 [优化合同](../../../docs/assistant-optimization.md) 为准；复用现有个人会话、任务修订和处理 Worker，不引入检索平台。

## 公开边界与实现选择

- 新增个人会话的背景文档上传、定位读取、移除 HTTP 路由；沿用项目访问、账号隔离和 CSRF。上传只保存有位置的提取文本、原文件哈希与提取版本；背景不是原始数据资产，不提供原件下载，不占草稿五来源名额。
- PostgreSQL 保存受限文本；单会话最多五份、原文件合计 10 MiB、提取文字合计 500,000 字符。PDF 最多 200 页，UTF-8 TXT/MD 最多 10,000 行。缺少可提取文字、无效编码和超额明确拒绝。
- PDF 使用固定 unpdf 版本，在有内存上限的 Node worker thread 中逐页提取；30 秒终止实际 Worker，不能用不停止工作的超时 Promise 冒充限时。
  - 固定 unpdf@1.8.1 + 同版本 pdfjs-dist@5.6.205 字符映射/字体资源；库默认 file URL 读取不适配 serverless PDF.js 时，通过受限 Node 文件读取器读取包内资源，拒绝文档提供的路径。
- 会话读取仅返回文档目录。read_background 工具按真实片段读取，回传物理页号或原文件行号；选用摘录持久保存。plan_task 记录可纠正要求；后台处理输入冻结当时的要求、文档哈希和选用摘录。
- 删除背景清除其提取正文及会话相关副本，旧确认失效；引用该背景的未采用处理正文按既有 durable cleanup 清除，已采用的数据内容保持不可变。数据来源永久删除也清理该会话背景正文。撤权与跨账号均不能读取。

## 验证与顺序

1. 公开提取 seam：UTF-8 文档保留真实行位置，PDF 保留真实物理页号；无效文件明确拒绝。
2. 真实隔离 HTTP：上传、刷新、引用读取、重复上传与容量；跨账号/撤权和删除。
3. SDK→Worker：短请求读取文档、持久要求纠正，处理模型实际请求包含冻结依据，不能仅存在聊天日志中。
4. Donor 前端工作区中的附件、来源和删除操作；桌面/窄窗口。该界面与 OPT-04 合并完成，不让当前后台步骤冒充已交付 UI。

## 当前证据

`background-text-green.log`、`background-pdf-green.log` 验证公开提取；`background-http-green.log` 验证刷新、重复和移除；`background-worker-green.log` 验证 SDK 读取引用→持久用户补充→真实 Worker 模型请求携带依据，并在移除后处理正文不可读。`background-gb-complete-risk-refs.log` 验证真实 GB PDF 中文、31 物理页、附录 A 五类及全部 31 项；`background-private-run-green.log` 验证其他成员不能通过处理页读取个人背景运行。整合中发现无附件任务的空背景字段不能参与 canonical JSON，修复后助手 43 项回归通过（`background-no-document-compatibility.log`）。前端附件上传、刷新、定位、移除及桌面/窄窗口已通过浏览器回归；最终真实模型 200 条仍待验证。
