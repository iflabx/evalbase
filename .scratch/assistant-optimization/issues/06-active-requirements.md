# OPT-06 目标理解与生效要求管理

Status: ready-for-agent
Implementation: not-started
Blocked by: none

## 目标与范围

用户用简短请求和可选背景文档表达目标，助手查看资料、选择合适方法，并在同一会话准确保留、更正或撤销要求。页面展示的要求与实际执行一致。

依据 [PRD §7.1–7.2](../../../docs/PRD-data-selection-and-assistant.md#7-ai-04-项目助手)、[架构 §9.1](../../../docs/architecture/data-selection-and-assistant.md#91-单一生效要求) 和 [整改方案](../../../docs/assistant-remediation-plan.md)。基础为已有 OPT-01–05 代码；不等待 OPT-05 历史验收。批次、授权与交付规则见 [Spec](../spec.md#整改批次执行约定)。

本张负责请求理解、背景/当前对象的选择、生效要求写入与兼容读取、规则反馈及要求摘要。后台推进、旧成果复用和候选审核分别由 OPT-07、OPT-08 承接。

## 实施切片

1. 沿现有查询/背景工具取得真实依据；简单任务直接处理必要参数，复杂任务保存业务步骤；只要求方案时不提交数据处理。保持模型选择方法的能力，不要求用户按工具顺序发指令。
2. 在现有写入处统一要求的保留、替换和明确撤销。区分期望输出允许值与 Metadata 分类，服务端计算数量/配额；旧规则显式归属，矛盾不静默放宽。
3. 将当前生效要求回显到现有任务区域；更正后旧要求进入历史。反馈具体字段、实际合计、差额或必要业务选择；模型格式错误由助手纠正。

| R06-2 | 期望输出规则和不同 Metadata 键互不串用；替换、撤销、省略更新含义明确；规则及保护字段冲突在处理提交前拒绝，旧有效状态不损坏 | REM-RULE |
| R06-3 | 只给方案不提交处理；明确要求执行的简单任务不增加开工确认；步骤可在获得资料后确定，用户不必事先列全参数 | REM-MODES |
| R06-4 | 要求摘要、数量与实际执行参数一致，刷新仍一致；更正后不累加已撤销约束；错误保留输入和已有成果 | REM-RULE、REM-FEEDBACK |

## 公开测试入口与首个验证

- 复用会话 `POST .../assistant/sessions/:sessionId/turns` 与 `GET .../assistant/sessions/:sessionId`，背景入口和现有业务工具；均为 `reused`。真实模型通过同一注册工具执行，不新建外部“规则管理”接口。
- 首个 red：通过公开会话/SDK 设置期望输出允许值和 Metadata 类别，再仅替换后者；若旧类别残留、跨字段污染或页面摘要与处理核对不一致，应失败。green：当前状态、刷新读取与下游核对使用同一有效要求；补保留/撤销/冲突对照。
- 查找起点：[agent.ts](../../../src/assistant/agent.ts)、[context.ts](../../../src/assistant/context.ts)、[review.ts](../../../src/assistant/review.ts)、[任务接口](../../../src/server/modules/assistant.ts)、[工作区](../../../frontend-v3/src/components/project-assistant.tsx)。这些是定位入口，不要求全部改动。

| 区域 | 本张修改 | 保留与异常 |
| --- | --- | --- |

## 验证与交付

运行受影响 HTTP/SDK 回归、类型检查、lint，以及要求摘要的浏览器检查；如前端变化则验证构建。假模型验证参数边界，小量真实模型核对短请求与必要澄清；不重跑万条分类。通过后记录实际命令、SHA、结果和限制，按 Spec 解锁 OPT-07；本张不单独占用人工 checkpoint。
