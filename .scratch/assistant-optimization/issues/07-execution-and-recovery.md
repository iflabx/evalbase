# OPT-07 可靠执行与成果恢复

Status: ready-for-agent
Implementation: not-started
Blocked by: none

[OPT-06](06-active-requirements.md) 已实施完成；本张尚未获得开发授权。

## 目标与范围

助手按当前目标实际执行，能依据中间结果调整后续方法；等待、失败或用户更正后保留已有成果，继续正确的未完成工作。每一步的完成有真实对象、范围和回执依据。

依据 [PRD §7.2–7.4](../../../docs/PRD-data-selection-and-assistant.md#7-ai-04-项目助手)、[架构 §9.2–9.5](../../../docs/architecture/data-selection-and-assistant.md#92-可执行步骤) 与 [整改方案](../../../docs/assistant-remediation-plan.md)。依赖 OPT-06 的生效要求与校验结果；批次和授权见 [Spec](../spec.md#整改批次执行约定)。

本张负责有序步骤、后台衔接、结果核对与恢复，以及工作区对真实阶段的必要展示。复用 processing run、现有 Worker 和确认事务；OPT-08 负责完整候选审核体验与最终通用验证。

## 实施切片

1. 当前步骤执行前取得必要对象、范围、参数、修订和结果引用；后续步骤可根据实际结果补齐。业务动作有自己的完成检查，错误来源、一页样例和入队回执不能冒充目标完成。
2. 在现有调度器内推进已确定的工作；读取状态、计数和已固定查询翻页使用程序，方法选择及语义处理使用模型。后台事件与预算续做保持有界、幂等和无进展退出。
3. 用户更正后核对成果兼容性，撤销受影响步骤及确认的执行资格。回包丢失先查回执；部分缺失只恢复缺失范围；无法可靠恢复的旧计划具体说明缺失，保留其成果。
4. 删除被替代的重复状态写入和提示词补丁。task、run、确认回执各负责自己的事实；不增加通用 DAG、完成条件语言或第二套调度器。

## 公开测试入口与首个验证

- `reused`：助手回合/读取/stop/retry、确认接口；`processing-runs` 的提交、status、读取、refinements、retry 和 accept。工具与页面继续共享有权限的业务函数；实现时记录实际受影响路由，不能恢复退役的宽接口。
- 首个 red：公开 SDK/HTTP 对来源 A 的计划返回来源 B 的同名工具成功回执，步骤不得推进；另有正确范围的对照。green 后补一页/全量区别、后台终态及确认回执绑定。私有函数测试不能单独作为此项完成证据。
- 查找起点：[plan.ts](../../../src/assistant/plan.ts)、[tasks.ts](../../../src/assistant/tasks.ts)、[agent.ts](../../../src/assistant/agent.ts)、[处理执行](../../../src/processing/execute.ts)、[采用](../../../src/processing/accept.ts)。修改按实际调用关系收敛。
