# OPT-28 当前成果范围与目标数量一致性修复

Status: ready-for-agent
Implementation: completed
Blocked by: none

优先级：P1。第一批，可独立修复；合批验证使用 OPT-26/27 的合同。已按后续 Owner 单张授权实施，人工验收 pending。共同边界见 [三批修复方案](../../../docs/assistant-generation-repair-batches.md)。

## 问题与目标

读取 50 条当前候选后，条件改写却只读取初始运行的 20 条；目标未持久保留时按运行请求量计算出 82 条。目标是让查看、选取、修改、核对和采用使用同一份当前成果，业务目标不随补齐次数变化。

## 修改范围

- 统一 `src/assistant/agent.ts` 的 `read_processing`、候选筛选/局部修改与 `candidates.ts` 的当前有效集合解析；配合 processing 现有 task-state/refine 服务。历史 run 详情保留只读追溯，不作为“当前全部”的隐式回落。
- 明确三种范围：用户明确当前全部、当前筛选匹配结果、固定 UI 勾选。没有勾选不能解释为全选；明确“这批全部”也不能强迫先勾 UI。空字符串条件不作为选择全部的捷径。真正业务歧义才询问范围。
- 各入口冻结同一集合修订、稳定身份和实际运行引用；局部替换不重复计数，未选候选保留。集合失效重新核对，不能悄悄改到旧运行或其他任务。
- 修复 `src/assistant/review.ts`、要求及计划持久化中的目标数量来源：每个交付目标的数量独立于 `outputCount` 和重试次数；保留已确认目标，只有用户变更才更新。八类各 50 的总体与当前类别数量分别表达。
- 旧任务缺目标时，仅从可核实的生效要求或无歧义原始生成目标恢复；无法确定时请求业务澄清，禁止累加补齐请求量或用当前实有数量反推已达标。
- 核对、摘要与确认卡使用同一目标/实际成果统计；不另建候选副本表或跨会话合并器。
