# OPT-23 项目助手长会话上下文与背景引用复用

Status: ready-for-agent
Implementation: completed
Blocked by: none

优先级：P1。Owner 已于 2026-10-14 单张授权开发，Implementation completed、Owner pending。范围以 [总方案 §5](../../../docs/assistant-workspace-reliability-plan.md#5-长会话与背景文档) 为准，继承 [背景合同](../../../docs/assistant-optimization.md#3-背景文档与短请求) 与 [架构 §9.5](../../../docs/architecture/data-selection-and-assistant.md#95-旧任务兼容与验证)。

## 目标与范围

- 每轮从现有 task、固定选择、合法对象和回执构建当前事实摘要，包含有效要求、当前成果和待解决事项；近期聊天作参考，不能取代当前状态。
- 工具结果改为有界摘要与可重新读取的稳定引用，大正文继续按需分页。保留合法 tool-call/tool-result 配对；不扩大消息容量以解决截断，不新增模型摘要调用链。
- 明确选中的记录范围、已否定/替换要求进入已有结构化状态；长期恢复不依赖“最近六轮里恰好还看得见”。“这几条”有唯一有效引用才解析，不确定时澄清，禁止扩大为全量。
- 已验证背景定义可返回稳定会话内引用，绑定附件、页/行、提取版本、原文/内容哈希；后续由服务端解析回原文并复用当前校验及运行冻结。
- 首次语义定位、编号与定义对应、用户自定义兜底依据继续检查。引用仅减少重复抄写，不能降低依据真实性或把背景内指令升级成用户授权。
- 旧 definitions/引用按需兼容；背景撤销、来源删除、哈希变化和权限改变时不接受过期引用。只写已有 task/规则 JSON 的必要字段，不另存一套长期记忆。

## 非目标

不做 RAG、向量数据库、跨会话自动记忆、文档全文 OCR、任意 URL 抓取或通用文档分类引擎。不要解析全部历史聊天批量推断/迁移旧计划；旧任务无法可靠恢复时明确指出缺失项。

## 验收

| 编号 | 验收 |
| --- | --- |
| R23-1 | 超过六轮后重开/刷新，会话仍使用当前来源、目标数量、字段保护和已确认选择；已撤销要求不重新生效，旧用户原文仍保留在历史。 |
| R23-2 | 长工具结果摘要没有孤立调用/回执，摘要引用能重读真实内容；总上下文有界，因预算省略不把部分读取当全量已读。 |
| R23-3 | “这两条”只作用于有效固定选择；候选替换/选择失效/存在多个指代时不能静默全选或使用旧下标。 |
| R23-4 | 附件定义首次验证后可通过引用复用，运行冻结的原文/哈希与先前完整定义相同；错误类别引用、伪造引用、跨账号、移除附件和篡改版本均被拒绝。 |
| R23-5 | 用户兜底标签有真实用户依据；旧定义可恢复且不新增无依据标签。当前背景容量和删除/清理规则不变。 |
