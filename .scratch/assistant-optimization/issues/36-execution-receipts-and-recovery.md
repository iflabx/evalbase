# OPT-36 确定性执行、回执与恢复统一

Status: ready-for-agent
Implementation: not-started
Blocked by: OPT-35

优先级：P1。依赖 [OPT-35](35-delivery-goals-and-plan-contract.md) 的持久目标与步骤绑定；OPT-34 为传递依赖。治理入口：[整改方案 §8](../../../docs/assistant-remediation-plan.md#8-2026-10-18-业务编排收敛整改)。仅文档，尚未授权开发或部署。

## 目标与问题

当前控制器既让模型重写计划参数，又在多个回调推进固定步骤；已恢复的早期错误可能覆盖真实成功。目标是在保留 AI SDK 的前提下，让已确定工作由一个现有业务推进入口负责，按真实执行结果恢复，而非靠聊天总结或全局失败标记。

## 修改范围

- 主要落点为 `src/assistant/agent.ts`、`plan.ts`、执行/回执相关模块及其调度调用方。先追踪普通回合、明确执行、后台终态、采用回执和重试路径，把已确定步骤汇入同一业务推进函数；复用现有有序步骤和 Worker，不另建调度器。
- 已保存的对象、范围、定义、目标、场景和修订由服务端绑定。生成下一交付、核对和准备确认沿已保存事实推进；需要新的语义选择才调用模型。禁止每次“继续”重新生成整套已确定参数，也禁止已知参数静默变化后命中旧回执。
- 模型工具循环由 AI SDK 正式能力承担；复用 OPT-32 的调用前校验及有限修复。传输重试、模型纠错与业务续做各沿既有责任和同一累计预算，不新增绕过额度的外层循环。后台等待使用事件/作业事实，不持续调用模型询问进度。
- 同一操作以任务、步骤身份、修订及固定输入关联实际回执。校验未执行可局部修正；已提交等待、结果未知、已完成及真正失败分别处理。未知写入先查原回执，未确定效果时不能换操作键重做。
- 当前完成/失败由仍需执行的事项及真实回执导出。相同动作的早期参数错误已由合法执行替代时，不再阻断该动作；另一动作仍失败、只有部分交付或新要求未保存时仍须明确未完成。历史诊断保留，不能简单“最后成功覆盖全部失败”。
- 停止、撤权、要求修改和草稿修订变化继续在实际提交前检查；旧异步结果不能覆盖新状态。用户更正只撤销受影响执行资格，保留产物和既有采用/发布事实。
- 删除本票已替代的推进分支、重复参数重建和全局错误优先级；仍需旧任务兼容的代码明确标注消费者及退出条件，不以文件拆分数量作为目标。

## 不包含

不更换 AI SDK，不接入 DeepSeek/Codex 运行时，不增加事件溯源平台或业务状态总框架；不重写模型生成/内容审核算法，不增加新确认层级。内容一致性继续由现有 OPT-31 能力与人工核对负责。

## 验收标准

| 编号 | 可验证结果 |
| --- | --- |
| R36-1 | 对已保存的两份交付执行、后台完成并确认采用后，下一份使用其原定义、场景与数量；固定步骤不再要求模型重写参数，不重建已存在草稿或处理运行。 |
| R36-2 | 同一动作先参数错误、后合法提交成功时，回合与任务能准确反映成功/等待；历史错误仍可追溯。另有未保存要求、失败步骤或欠交付时，不因该成功误标全任务完成。 |
| R36-3 | 数据提交后响应丢失，用隔离持久化夹具模拟结果未知；重试查询同一业务回执，写入计数保持一次。重复后台事件、重复确认及重试点击也不重复派发。 |
| R36-4 | 服务 503、取消、连续无进展或预算耗尽时有界停止并保留成果；请求次数、修复次数、补齐和自动续做计入原预算，不能靠新回合或运行重新获得额度。 |
| R36-5 | 等待后台时无轮询模型请求；从持久检查点重新读取后继续未完成步骤，固定内容与成功回执不变。此项在隔离测试中模拟，不重启 4217 或宿主服务器。 |
| R36-6 | 停止/撤权/修改要求与旧后台响应竞争时，旧执行不能新增写入或覆盖新修订；有效历史产物保留。确认仍绑定当前用户、项目、内容和目标，文字回复不代替采用/发布。 |

## 验证与交付

复用现有公共助手/处理接口和数据库回执测试，增加针对上述原失败路径的最小回归；故障注入不调用真实模型。受控“下一次给正确参数”只证明协议和状态处理，不能当真实模型纠错成功率。真实全流程及页面反馈由 OPT-37 集中验证。

向 OPT-37 提供同一业务推进路径、明确的结果/恢复状态和固定回执，既有页面无需知道底层框架或工具参数。定向核验所有受影响调用入口，避免只修聊天路径而遗漏后台和确认续做。
