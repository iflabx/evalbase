## 目标与依据

让用户容易完成“确认来源和范围 → 设置处理要求 → 查看进度 → 核对变化 → 保存结果”，重点减少翻页勾选、重复阅读及对内部术语的理解成本。

产品行为以 [PRD §6](../../../docs/PRD-data-selection-and-assistant.md#6-ai-03-清洗改写扩充) 为准，本 Ticket 将本次确认的交互细化为布局与验收要求。继续遵守 [CONTEXT](../../../CONTEXT.md)、[处理架构](../../../docs/architecture/data-selection-and-assistant.md)、[ADR 0014](../../../docs/adr/0014-project-agent-and-processing-runtime.md)、[前端复用约定](../../../docs/architecture/phase1a-frontend-reuse.md)及[批次约定](../spec.md#整改批次执行约定)。

## 修改范围与页面合同

### 1. 来源、导航和任务追溯

- 配置页标题显示“处理 + 来源名称”，副标题显示来源类型、版本标签（适用时）、总记录数和已选数量；多个来源显示可展开的文件名清单，不使用内部 ID 代替名称。
- 来源链接回到对应原始文件、版本或草稿；返回处理任务使用轻量导航。页头不固定提供与来源无关的“返回测试集”主按钮。
- 任务列表以“来源名称 + 清洗/改写/扩充”识别任务，显示数量、状态、发起人及创建时间；结果页保留可展开的实际处理要求、允许修改字段和时间。显示提交时的真实要求，不用后来修改的要求重写历史。
- 保存后显示实际数量和目标入口，刷新仍可从真实回执定位成果；不能仅凭任务完成或浏览器临时状态标记“已保存”。旧任务缺少信息时显示“未记录”，不可推测填充。

### 2. 记录选择

- 复用现有记录搜索与固定 Metadata 筛选样式、比较规则。增加“只看已选”，展示“匹配 N 条／已选 M 条”；搜索或筛选改变回到第一页，不清除其他页面已选记录。
- 将“仅选择本页”改为“勾选本页”，与已有选择取并集；取消单条只移除该条。“选择全部”明确标为“选择全部匹配记录”，仅添加当前搜索和筛选范围内记录；没有条件时为当前来源全部记录。
- 显示隐藏在当前筛选之外的已选数量；提交明确使用完整已选集合，不能把当前页或当前筛选悄悄当成提交范围。“清空选择”明确清除全部选择。只看已选模式下取消记录、空结果、清除筛选均有可恢复入口。
- 问题、期望输出、Metadata 摘要在表内直接可见；完整记录可原处查看。空 Metadata 值与缺少 Metadata 项区别保留。来源发生变化或失效时保留可恢复输入并提示重新核对，不静默扩大选取范围。

### 3. 处理配置

- 紧凑设置区按“要做什么 → 修改哪些内容 → 具体要求”排序；分别显示清洗、改写、扩充的简短说明和对应示例。
- 清洗明确：不填要求时整理首尾空白并提示空值/重复，不承诺自动删除重复记录；填写语义要求会调用模型。改写说明保留原意、按要求改变表达；扩充说明参考选中数据生成新记录，并显式区分输入数量与新增数量。
- 保留问题、期望输出、Metadata 三字段保护选择，默认保护期望输出及 Metadata。提示清晰说明哪些内容可改、哪些保持原值，不因切换处理方式而静默扩大字段授权。
- 清洗示例不再使用改写文案。输入不足、未选字段、数量非法等情况在相关控件附近解释，按钮禁用不能没有原因。提交中防止重复提交，失败保留选择和要求。
- 复用现有小样本选择能力，不另建强制试运行流程、模板管理或多步向导。右侧设置和开始按钮在桌面滚动时容易找到，窄窗口按顺序上下排列。

### 4. 进度与结果核对

- 顶部用一条紧凑摘要显示真实运行状态、已完成/目标数量、可查看结果数量和需核对数量；正常处理中、等待、部分成功、失败、取消和待审核明确区分。没有依据时不估计剩余时间、不伪造进度。
- 失败提示包含简短原因、已保留的结果及恢复动作。只重试未完成部分；失败或状态读取中断不能抹掉成功结果、用户选择，也不能把旧数据当成仍在正常运行。
- 结果采用紧凑列表，显示问题摘要、期望输出、Metadata 摘要、变化字段和可定位的校验问题。点击行或键盘打开右侧只读详情，对照完整原文与结果；勾选框独立操作。窄窗口使用同内容的全宽详情，关闭回到原记录位置。
- 增加“全部／有变化／需核对”筛选；变化以真实原文和结果逐字段比较，Metadata 按有序键值项展示新增、修改、删除和空值，不把来源不同的同文记录合并。差异同时用文字/标记表达，不仅靠颜色。
- 列表优先突出实际变化，例如只新增 `gbRisk` 时明确显示新增项，避免默认重复铺开两份未改变的长正文。完整问题、期望输出和 Metadata 仍可查看；扩充标记“新增记录”，原始输入只作为参考来源，不伪装为对原记录的覆盖。
- “需核对”按实际可定位的问题标记；没有记录定位的失败/缺失显示为任务级提示，不能伪造问题行或计数。筛选统计覆盖完整授权结果而非当前页。
- 按钮改为“勾选本页／选择全部匹配结果”，保持跨页选择，清楚显示本次保存数量。将“有效结果”从按钮文案移除；结构检查通过不代表内容正确，人工内容审核仍需保留。没有采用资格的结果不可因文字简化变成可保存。

### 5. 保存结果与项目助手衔接

- 主操作改为“保存处理结果”，确认时明确选中数量和目标。目标使用“保存为原始数据”“新建测试集草稿”“加入已有草稿”；从草稿处理时保留“更新来源草稿”的适用入口。
- 确认文案根据动作明确“追加 X 条”或“更新 X 条的指定字段”；仅改写 Metadata 时不能暗示整行覆盖。底层继续保存独立派生文件并记录真实来源，原件与正式版本不可覆盖。
- 提交失败、同字段冲突或响应未知时保留选择、要求和确认目标；复用既有回执与幂等规则恢复，不自动重复追加。保存成功提供打开原始数据或草稿的入口。
- 手动处理与项目助手复用一致的结果列表、差异详情和核对文案。助手结果入口可打开对应运行或任务的有效成果，并能返回原会话，当前用户选择及待确认状态不应无故丢失。
- 复用展示不改变业务作用域：助手多批成果仍读取该任务当前有效候选，保留局部调整的替代关系及固定确认；不能只打开最后一次运行、混入历史失效候选，或绕过助手的任务修订、背景、范围及采用确认检查。

### 6. 草稿与处理成果的来源展示

- 草稿、处理结果及“来源与修改”页面统一显示“原始依据 + 处理类型”；独立派生资产、真实处理回执与来源身份继续保留，系统生成的结果文件名放在来源详情中，不作为列表唯一的来源说明。

| 真实关系 | 来源栏示例 |
| --- | --- |
| 原文件直接选入 | `100个问题_new.csv · 第 22 条` |
| 原记录清洗或改写 | `100个问题_new.csv · 第 22 条`，附“已清洗”或“已改写”标记 |
| 模型扩写生成新记录 | `模型扩写 · 参考 100个问题_new.csv` |
| 扩写确实参考多个文件 | `模型扩写 · 参考 3 份资料`，可展开真实文件清单 |

- 清洗/改写仅在逐条关系可证时展示最初文件及原始记录位置；来源序号采用现有解析位置，不使用处理结果的新序号冒充。扩写的参考文件或记录只表达生成依据，不能标成“原文件第 N 条”的直接摘录；多文件参考按该记录实际保留的依据计算，不能把任务所有输入冒称为每条记录的确定来源。
- 来源详情按真实先后显示原始依据、清洗/改写/扩写过程、当前产物及处理任务入口。连续处理保留最初可证来源；先扩写再清洗仍标明模型生成及参考关系，不因最后操作是清洗而伪装为原文记录。手工新增仍显示真实手工来源。
- 旧数据关系不完整时显示可证的直接来源及“原始来源未记录”，不得按文件名或正文相似度猜测。回收、删除及权限变化沿用现有访问规则，不能通过溯源摘要、链接或缓存暴露已不可访问的名称和正文。
- 复用已有运行快照、记录 locator 和采用回执补齐必要展示，按页批量读取；不新建通用血缘图或遍历全部项目数据，也不把界面来源摘要写回资产身份、来源计数或容量判断。

## UI 对齐与状态要求

| 位置 | 本张布局/顺序 | 状态与样式约束 |
| --- | --- | --- |
| 配置页 | 来源摘要 → 搜索/筛选/已选 → 数据表；侧边紧凑处理设置及开始操作 | 直接复用 frontend-v1 的字体、颜色、图标、表单与表格样式；无数据、无匹配、加载失败分别显示。 |
| 任务列表 | 来源及操作 → 数量/状态 → 发起人/时间 → 查看 | 信息密度沿用项目现有列表；避免重复的大卡片和技术标识。 |
| 结果页 | 状态与数量 → 筛选/选择/保存 → 紧凑列表 → 按需完整对比 | 已选行、焦点、变化标记、问题提示可辨认；主要动作只有保存结果，运行期间为适用的任务控制。 |
| 保存确认 | 数量与目标 → 追加/更新说明 → 取消/确认保存 | 沿用 donor Dialog；提交、冲突、失败与成功反馈齐全。 |
| 助手入口 | 现有成果入口 → 相同核对体验 → 返回原会话 | 不新增第二套任务状态或模型执行框架，不削弱个人背景权限。 |
| 草稿及来源与修改 | 来源栏显示原始依据与处理标记 → 详情查看完整真实处理过程 | 沿用原有来源列与详情组件；结果文件名收纳于详情，扩写明确为参考关系。 |

所有页面减少重复说明和大面积空白；正文/次要信息有明确层级。长文本换行或摘要截断后可看全文，Metadata 不消失。列表滚动和详情布局不能导致整页横向溢出；工具栏在窄屏换行，固定区域不遮挡内容和键盘焦点。冻结原型及 `frontend-v1` 保持只读，本次差异以 PRD 的已确认增补为依据。

## 实施边界

- 优先修改正式 `frontend-v3`，复用既有 selection、processing、助手有效候选、字段冲突和确认服务。先盘点现有公开输入/结果/任务接口与两个调用方，逐项记 `reused` / 必要的窄扩展；新增过滤、全量统计、来源名称和真实回执读取若缺失，仅补页面必需字段。
- 搜索、筛选、问题归属、差异统计和全选范围必须针对同一授权集合计算并稳定分页；不得为方便前端筛选加载全部 10,000 条正文。普通浏览和核对不调用模型，不新增高频轮询、逐行请求或通用搜索平台。
- 保留来源身份、空 Metadata、字段保护、个人背景访问、项目权限、固定输入、有效候选关系、幂等和永久删除规则。旧任务读取按已有事实兼容，不批量重写用户历史。
- 不新增处理策略、模型框架、可编辑候选表、自动语义通过、任务命名管理或数据库表；确需改变持久化/公开接口时先写明最小差异，不借 UI 调整扩展系统。
- 本张改善数据处理及对应助手核对入口，并统一草稿和“来源与修改”的处理来源展示；不重做整站、修改冻结原型或修复其他服务器项目。
