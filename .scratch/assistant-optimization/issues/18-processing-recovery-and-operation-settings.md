# OPT-18 数据处理失败恢复与清洗、扩写配置优化

Status: ready-for-agent
Implementation: in-progress
Blocked by: none

优先级：P1（无效重试与错误原因丢失）；配置和状态展示随同交付。2026-10-13 Owner 授权将失败诊断及此前清洗、扩写的配置建议合为一张 Ticket；2026-10-13 Owner 已授权开发。依赖 OPT-16/17 已有实现，不等待其最终人工验收；保留历史实施与验收记录。

## 目标、依据与范围

让用户按清洗、改写、扩写的实际目的配置处理；失败时能看懂已完成多少、为什么停止、下一步能做什么。恢复只处理未完成范围，保留成功结果、字段保护和已有调用预算。UI 严格对齐 frontend-v1，流程精简，不新增通用配置或工作流平台。

继承 [PRD §6](../../../docs/PRD-data-selection-and-assistant.md#6-ai-03-清洗改写扩充)、[CONTEXT](../../../CONTEXT.md)、[处理架构](../../../docs/architecture/data-selection-and-assistant.md#4-上传和处理任务)、[ADR 0014](../../../docs/adr/0014-project-agent-and-processing-runtime.md)、[前端复用约定](../../../docs/architecture/phase1a-frontend-reuse.md)、[OPT-16](16-processing-deduplication-and-list-ux.md) 和 [OPT-17](17-processing-task-rounds.md)。本张细化操作配置、失败分类和恢复入口，覆盖原统一“允许修改的字段”常驻区及无条件重试展示；原始数据不可变、来源、采用/发布确认、修订和权限约束继续有效。

### 已核实的问题

- 审查基线：工作区 `43ecd9c`，4217 运行代码 `6c1dafe`。10 月 13 日 09:55 的扩写要求新增 12 条，保留 11 条，批次已调用模型 3 次，最终记为失败；外层两次自动重试耗时约 61/63 毫秒，没有再次调用模型。10:04 用户显式补齐剩余 1 条成功，后台约 1.9 秒。
- 现有批次最多 3 次模型调用，共用从首次调用起计的 60 秒预算；外层任务重试及手动重试没有充分识别预算已耗尽。次数限制本身保留，修复无效领取、错误入口及停止说明。
- 当前处理器直接解析整段模型 JSON；首次输出解析或接口调用异常且无有效结果时退出批次，无法在本次循环内按具体原因纠正。截断、接口临时异常等被归并为 `processing_batch_failed`，缺少结束原因和分类统计。
- 扩写剔除完全重复后，没有把被拒绝内容的必要避重信息用于补生成，也未保留明确剔除计数；最终只能看到缺额。
- 当前清洗、改写、扩写复用“允许修改的字段”，容易让用户把生成新记录理解为修改原记录。默认保护期望输出和 Metadata 是现有合同，不能因隐藏勾选框而取消。
- 前述恢复、截断/临时接口异常、超时预算和重复反馈路径经 5 个隔离模拟场景复现。未调用真实模型增加测试数据；最近缺失的 1 条没有足够历史诊断确认具体原因，不能写成已证实的重复或模型错误。旧运行混有开发测试、取消和来源删除，不据此声称整体失败率。

问题代码集中于 `src/processing/execute.ts`、`protocol.ts`、`store.ts`、`src/worker/main.ts` 和正式处理页。手动页面直接调用处理服务，不经过项目助手规划循环；助手调用同一服务时应获得一致结果与恢复语义，本张不重构助手规划器。

## 1. 按操作目的展示配置

保留现有三种处理入口和左右工作区，只调整右侧配置，不新增向导步骤或额外确认弹窗。

| 操作 | 常驻内容 | 按需设置与默认行为 |
| --- | --- | --- |
| 清洗 | 基础规则简述、补充要求（选填）、开始清洗 | 移除常驻“允许修改的字段”；“高级设置 → 清洗范围”可调整字段。默认沿用问题首尾空白整理，期望输出和 Metadata 保持；空值/完全重复按现有规则检查，不冒充已修复或已删除 |
| 改写 | “改写哪些内容”、具体要求、开始改写 | 保留明确字段选择，默认问题；期望输出和 Metadata 需要明确选择才允许修改 |
| 扩写 | 生成要求、新增记录数量、开始扩写 | 移除“允许修改的字段”；默认生成新问题，期望输出和 Metadata 沿用对应参考记录。在“生成设置”内分别选择“沿用参考值／由模型生成” |

- 基础清洗未填写补充要求时继续使用确定性规则，不调用模型；高级范围仅对所选字段执行既有清洗能力，不新增自动修补答案、语义去重或静默删除。去重排除与保存移除沿用 OPT-16。
- 扩写始终追加新候选，不改原记录。沿用值取自模型返回并经服务端核实的对应 `sourceId`，不能从任意参考记录复制；由模型生成只影响本次新候选的获准字段。后台继续使用既有字段保护校验，无需引入第二套权限协议。
- 默认设置折叠时用一行简短摘要显示实际行为，例如“生成问题 · 期望输出和 Metadata 沿用参考值”；高级配置有改动时同步摘要。对具体答案型期望输出，在生成设置中提示可选择随新问题生成；类别标签可沿用。系统不自动猜测字段含义或暗中放开权限。
- 操作切换保留各自未提交配置，不能把上一种操作的字段勾选无提示地带入另一种。恢复旧配置/旧运行时以其真实选项展示，不用新默认覆盖旧字段范围。只有明确提交才产生运行或 OPT-17 新轮次。
- 收起设置不重置选择，不额外调用模型推断权限；服务端冻结最终要求和字段选项。助手沿用现有生效要求和字段授权，不因手动页简化而扩大其范围。

## 2. 可解释的失败与数量反馈

- 在现有批次记录/作业日志内保留最小结构化诊断：错误类别、批次、实际调用次数、耗时、模型结束原因（可得时）、生成/通过校验/重复剔除/其他无效/最终缺失数量。按次计数与最终有效集合区分，避免重试累计出虚假产量。
- 至少区分：连接/网络及限流或临时服务错误、超时、输出被长度截断、JSON/结构错误、来源身份或字段校验错误、数量不足、预算耗尽。权限、来源失效、修订冲突等继续使用既有业务错误，不归为模型故障。
- 不记录密钥、请求头、完整提示词、背景文档或原始模型正文；外部错误字符串不直接展示给用户。仅保留白名单诊断及必要关联信息，支持后台定位。
- 页面默认只显示简短原因、已获得数量与恢复操作，详细分类按需展开。历史记录没有诊断时显示“历史任务未记录具体原因”，不回填猜测；诊断缺失不影响现有结果读取。

## 3. 统一有界恢复，停止无效重试

- 复用现有 Worker、批次和修订/租约机制；模型调用、格式纠正、补生成、自动恢复共享原运行持久预算，不叠加额外重试循环。保留现行每批最多 3 次调用、首次调用起 60 秒预算及输入/输出容量、模型并发上限；本张不以调大这些数值掩盖问题。
- 自动重试只处理可恢复且仍有预算的缺失范围。临时网络/限流/服务错误在剩余额度内有限重试；格式错误可携带简短准确的错误说明要求修正；截断不能伪装成空结果或完整输出。无法在预算内继续时停止并明确原因。
- 检查模型结束原因及输出结构后再纳入结果；有限兼容既有代码围栏，禁止从任意文本猜测来源 ID、忽略字段类型、执行输出或绕过保护字段来“提高成功率”。已通过校验的其他批次/记录不重跑、不丢失、不改变采用身份。
- 任务层领取/恢复前识别实际可继续的批次。无剩余调用或时间预算时直接终止自动恢复，不再显示“等待重试”、空跑若干次，或让助手无限重复同一工具。
- 手动“重试未完成部分”只在原运行确有可恢复范围和预算时可用，调用接口也必须校验，不能只禁用前端按钮。过期页面点击应返回当前原因和合法下一动作，不先入队再立即失败。
- 本轮预算耗尽后，用户显式续做才获得新一轮独立有界预算：扩写沿用“补齐剩余 N 条”；清洗/改写提供只处理尚未成功记录的“继续处理未完成部分”，沿用对应冻结输入、要求、字段范围及身份。两者均留在同一 OPT-17 任务，产生新用户轮次，保留已有成果；不默认重做全部成功记录，不自动借新轮重置预算。
- 幂等、未知请求对账、取消、失效 Worker、同任务单活动轮次和来源修订校验保持；双击或两人同时恢复只能形成一次合法动作。来源已不可用/无权限时先解决业务原因，不能用补齐绕过。

## 4. 让去重后的补生成具有有效反馈

- 服务端继续按 OPT-16 的完全重复规则检查完整固定范围。补生成发送真实缺额、已接受内容的必要摘要，以及本轮被拒绝重复的少量必要避重内容；不能只告知数量不足，让模型重复尝试同一条。
- 避重信息受原完整请求字节上限约束，不能把全部历史/全部原始资料塞进提示词；必要时裁减提示摘要，保留用户要求、字段保护、配额和来源。即使摘要被裁减，服务端仍对完整范围去重。
- 记录实际剔除原因及数量，补生成仅填缺口；次数/时间任一上限到达即停止。保留此前成功内容与身份，不重新生成已完成部分，不将少量结果冒充目标达成。
- 沿用原模型与提供方协议；结构化输出约束仅在当前接口经小样本确认支持时使用，不能为启用它迁移 SDK/引入新框架。服务端验证始终保留。不承诺模型绝不重复、绝不超时或一次达到数量。

## 5. 部分完成与下一动作

- 有有效结果且仍有执行缺口时显示“部分完成 · 已获得 11/12 条，还缺 1 条”等真实状态；全部未产出才显示相应失败，取消保留取消事实。区分本轮新增/处理成功数量与任务当前总数。
- 继续可查看并显式采用已有有效结果；未成功改写的记录保留此前值并标明未完成，不能计作本轮成功。质量提示、执行缺口、未保存分别表达，完全重复提示不能一概变成执行失败。
- 依据真实能力呈现一个主要恢复入口：原轮仍可重试则重试；预算耗尽则显式补齐/继续未完成部分。技术原因放入可展开详情，不堆叠常驻状态卡或多个含义重叠按钮。
- 同一服务的页面与助手结果保持一致；助手可以报告已完成部分，但不将“后台入队”“得到部分结果”说成全部完成，不绕过人工采用/发布确认，不新增自动批准。
- 沿用 OPT-17 当前成果、轮次历史、保存回原草稿及已保存身份规则；旧成功结果不可被过期重试覆盖，已保存部分不能再次追加。

## 验收标准

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| R18-1 | 默认清洗、展开范围、带补充要求清洗 | 无常驻通用字段勾选；默认确定性清洗不调用模型；真实范围/保护摘要清楚，检测不冒充删除或修复 |
| R18-2 | 扩写继承标签/Metadata、明确生成具体答案；改写字段选择 | 配置名称符合用途；新问题生成，未授权字段由对应来源恢复；不更改原输入，不自动判断或放开字段 |
| R18-3 | 操作切换、返回/刷新恢复及旧运行配置 | 各操作配置与实际提交一致，旧范围不被默认覆盖；配置变化不提前生成运行或轮次 |
| R18-4 | 临时接口错误、无效 JSON、长度截断、无效来源/字段 | 可区分原因；只在原剩余预算内定向恢复，拒绝不合法输出，日志及界面无密钥或正文泄漏 |
| R18-5 | 12 条保留 11 条、调用耗尽；仅剩时间预算耗尽 | 不空跑自动重试；无效手动重试被服务端拒绝；显示实际缺额和合法续做入口 |
| R18-6 | 重复发生在输入/目标基线/前批结果，补生成再次重复 | 完整范围去重，反馈必要拒绝信息；诊断计数准确、提示不超限，成功结果不变，预算到达即停 |
| R18-7 | 部分结果后显式补齐或续做未成功改写 | 同任务新轮只做缺失范围；原预算不被自动重置，成果不重复，保留身份/来源/字段基线 |
| R18-8 | 部分采用、保存回原草稿、取消/恢复、未知响应与双账号竞争 | 真正成功记录可采用；未处理旧值不冒充成功，提交幂等、修订及单活动轮次有效 |
| R18-9 | 页面和助手读取同一失败/部分任务，旧数据无诊断 | 数量、状态、下一动作一致；历史原因不猜测，助手不循环空重试或误报完成 |
| R18-10 | 桌面、窄窗口、键盘及错误状态 | 字体、token、按钮、表格、折叠区、密度严格复用 frontend-v1；主操作易找，新增说明保持简短 |

## 实施与验证边界

- 不新增依赖、智能体框架、调度平台、语义去重、模型选择策略或通用诊断看板；不自动修改期望答案/Metadata 权限，不改原件、正式版本和历史成果。仅为可靠恢复与诊断补必要的持久字段/响应信息，兼容旧运行，不预设新状态表。
- 批次大小、token 上限及超时默认保持。先记录真实结束原因和耗时，若后续数据证明需调整，按具体证据再定；不把推测的模型性能瓶颈写成已修复或扩大本张。
- 用现有可控模型、HTTP/Worker 和隔离数据库夹具覆盖上述恢复边界，优先复用本次 5 条诊断路径；验证实际公开接口及持久预算，不仅测试提示词字符串。已有未受影响的 OPT-16/17 证据复用。
- 浏览器集中检查三种配置、一条部分完成恢复链和保护字段；真实模型最多必要的小样本连通/协议验证，禁止反复生成 100/200 条做可靠性证明，不做压力或长时稳定测试。
- 按改动运行受影响类型、lint、构建及定向回归；实施时更新架构和测试计划的最小差异，保留诊断证据和剩余限制。沿用当前分支及同一 4217、既有用户项目和账号；一个 Ticket 一次集中 checkpoint，不要求逐小步确认。
- 本轮实施按 Owner 授权完成开发并更新同一隔离验收环境；合并、推送、tag 和正式部署按各自授权执行。
