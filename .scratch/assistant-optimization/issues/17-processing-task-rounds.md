# OPT-17 单任务工作区与轻量处理轮次历史

Status: ready-for-agent
Implementation: not-started
Blocked by: OPT-16

优先级：P2。2026-10-13 Owner 确认将“一个处理任务、一个工作页面、多轮处理历史”整理为本张 Ticket，当前只授权文档，不开发、不切换运行环境。实施顺序为 OPT-16 → OPT-17，复用去重补齐、来源及列表规则；依赖代码与合同，不把 OPT-16 单独人工验收设为额外开工条件。后续开发仍须 Owner 授权。

## 目标与依据

连续清洗、改写、扩写在同一任务工作区完成，列表不再为每一轮重复创建可见任务行；用户查看当前有效结果，按需回看各轮事实，最后确认保存。采用轻量轮次历史，不复制测试集正式版本树。

继承 [PRD §6](../../../docs/PRD-data-selection-and-assistant.md#6-ai-03-清洗改写扩充)、[CONTEXT](../../../CONTEXT.md)、[处理架构](../../../docs/architecture/data-selection-and-assistant.md#4-上传和处理任务)、[ADR 0014](../../../docs/adr/0014-project-agent-and-processing-runtime.md)、[前端复用约定](../../../docs/architecture/phase1a-frontend-reuse.md)及 [OPT-16](16-processing-deduplication-and-list-ux.md)。当前问题依据为 `40b3356` 上的 OPT-13 合同/代码和 Owner 截图：继续处理已有父子运行关系，但每次运行单列一行，手动后续结果仅包含所选范围，尚无任务级当前结果汇总。

本张覆盖 [OPT-13](13-processing-result-continuation.md) 中“每轮独立任务行/页面、未选结果仅留上一运行、单次结果不汇总”的展示与工作区规则；底层每轮运行、真实来源、字段保护、采用身份、权限与修订约束继续保留。本文为待实施合同，不改写历史实现或 Owner 验收记录。

## 1. 任务、轮次与当前结果

| 概念 | 本张含义 |
| --- | --- |
| 处理任务 | 用户的一次连续处理工作，在列表中一行、拥有稳定工作区；来源主动发起独立处理才另建任务 |
| 处理轮次 | 用户明确提交的一次清洗、改写、扩写或重新运行，按“第 1 轮、第 2 轮”记录；后台可有多个批次 |
| 当前结果 | 首轮实际有效结果，加上后续成功变更形成的有效集合；按稳定记录身份替换/追加，不拼接全部历史输出 |

- 任务名称稳定，以原来源名生成可理解标题，如“邹豪 · 数据处理”，不随每轮方式改名，不以内部 ID 区分。暂不增加任务命名管理功能。
- 自动重试、Worker 恢复和 OPT-16 的自动补生成属于原轮次；用户点击补齐剩余、继续处理或重新运行才产生新轮次。配置尚未提交、双击或未知请求对账不能多建轮次。
- 最初从草稿只选 10 条，任务范围就是这 10 条及后续生成结果，不自动纳入草稿其他记录。首轮是扩写时，初始当前结果为其新增输出，不将参考输入自动计入成果。

## 2. 同一列表与工作页面

- 列表一项展示稳定任务名、当前结果数、最近一轮及方式、实际状态/保存情况、最近操作人/时间和“打开”。继续处理与重新运行不新增列表行；查询按任务聚合后搜索、排序、统计和分页，最近 100 项指 100 个处理任务，不先截取 100 条运行再在浏览器拼组。
- 默认打开当前结果；页头仅保留任务名、简短状态、“处理历史（N）”和保存主操作。结果工具栏沿用搜索、筛选、跨页选择及“继续处理所选 N 条”，不堆叠多轮结果/配置卡。
- 点击继续处理，在同一任务工作区切换为现有配置视图；显示输入范围，提交后展示该轮真实进度，终止后返回当前结果。取消配置返回原结果并保留搜索、页码和勾选。切换视图、前进后退、刷新本身不启动处理。
- 路由保留稳定任务身份和可定位的轮次，普通刷新/深链接可恢复正确页面；旧 run 链接仍能定位对应历史运行，不跳到同名其他任务。
- OPT-16 五类状态用于聚合任务：有活动轮次为进行中，最新轮失败/部分完成需处理时直接显示；历史曾失败但已经恢复的轮次不让整个任务永远异常。已取消只描述确已取消的最新执行，已有成果保留；执行、质量、保存状态仍分开。
- 首轮未产出结果时显示真实空态/进度；后续运行中保留上一轮当前结果并说明本轮进度，不先清空。处理与保存互斥，查看历史不阻塞后台执行。

## 3. 多轮结果的合成规则

| 当前结果与操作 | 操作后的当前结果 |
| --- | --- |
| 100 条中选择 10 条清洗/改写 | 成功的对应记录替换，未选的 90 条保留，总量通常仍为 100 |
| 对所选参考扩写 20 条 | 保留当前集合，追加合格新增记录；去重/有效数量按 OPT-16 |
| 明确去重排除 10 条 | 按 OPT-16 的确认范围减少 10 条，来源草稿移除仍待保存确认 |
| 重试本轮未完成部分 | 成功记录保留，仅补缺失；不重复追加，不新建用户轮次 |

- 每轮固定其执行前集合、实际所选身份及内容、字段权限、要求与修订基线。当前集合持久可恢复；可复用结果引用/身份映射，不为展示复制所有历史正文。
- 运行中不随单批输出反复替换当前集合；该轮终止后按真实成功记录形成下一状态。部分失败/取消时，未成功的改写记录保留旧值并标明未完成，已有新生成成果保留；旧值不算本轮处理成功，部分结果不算整体目标达标。重试成功再按同一身份更新。
- 清洗/改写保留原更新/新增归属；扩写结果后来改写，仍作为新增内容保存，不覆盖参考原文。当前结果的来源、统计、去重、继续处理及保存使用同一有效集合。
- “重新运行本轮”留在更多菜单，只针对最新轮的固定输入；配置说明将重做该轮，形成新轮次，以该轮执行前集合为基准替代其效果。旧结果可回看，不把同一轮旧新增与重做新增累加。已保存内容不以重跑旧候选覆盖，使用下节的已保存对象入口。
- 普通手动页与助手共用领域结果和保存服务，助手既有局部调整/多批任务范围保持。一个助手任务可能关联多个处理任务，不强行合并为同一个处理任务，也不把无关手动轮次自动加入助手成果。

## 4. 轻量处理历史

- 使用现有 donor 弹窗/侧栏及紧凑列表，按轮次倒序展示方式、要求、操作人/时间、实际输入/输出数量、执行与保存状态，提供“查看本轮结果”和“返回当前结果”。
- 历史结果显示该轮当时的真实输出和操作范围；后续未选记录不会伪装成该轮处理产物。任务当前集合与单轮输出明确区分，历史查看不触发重新合成、模型调用或保存。
- 历史第一版只读，继续处理基于当前结果；不提供任意历史回滚、分叉编辑、分支合并、版本图或逐字段版本比较。原有单条原文/处理结果对比继续保留。
- 历史按需分页读取正文，保留真实处理链和来源权限；不因轮次增多在首页一次加载所有结果，不绕过现有容量与来源生命周期约束。

## 5. 保存当前成果与继续工作

- 从草稿发起时，默认“保存回原草稿”；确认基于当前有效集合中实际待保存的选择，显示目标、更新/新增/移除数量和未保存范围。默认可保存完整当前成果，用户明确选择部分时只保存该部分，不只取最后一轮，也不累计历史副本。
- 跨轮累计改动仍核对最初尚未保存字段的修订基线，保留未授权字段、未选记录和他人修改。沿用事务、幂等和真实保存回执，自动处理/查看历史不等于保存或发布。
- 当前成果全部保存到同一草稿且回执明确时，在同一工作区提供“基于已保存草稿继续”。读取该草稿中实际保存范围的当前内容及新修订，明确显示目标/数量后提交下一轮；不默认扩展至整份草稿，也不沿用已采用候选身份冒充未保存。
- 部分保存或多个保存目标时，逐项保留真实保存状态和入口；未保存部分可继续处理，已保存部分通过真实目标入口处理，不自动拼接不同目标或覆盖回执。未确认保存结果先沿用原请求核对，禁止借新轮次绕开未知提交状态。
- 来源草稿暂停、发布、删除或权限失效时按现有规则阻止写入，保留仍有权查看的结果并说明原因；不偷偷另建替代草稿或自动切换保存目标。

## 6. 并发、兼容与最小实现

- 同一任务最多一个活动轮次；服务端按当前任务修订/执行状态原子校验，同键重复提交返回同轮，两个用户同时提交只有一个生效。过期配置、过期保存和过期 Worker 结果不能覆盖新的当前集合；无需新增通用协作锁平台。
- 复用已有父任务关联、processing 运行/批次、Worker、结果身份和回执；只补持久任务归属、轮次顺序及有效集合需要的最小状态/读取接口。具体存储依实际代码确定，不预设一套通用版本仓库或第二状态机。
- 旧记录只按真实父子关系归组，不按同名/同来源/时间猜测。可证明的单链能汇总，分叉或缺失关系不能任意选一条、混合互斥结果；保留可访问的独立历史入口并如实标明，不改写旧输入、正文、回执及身份。旧深链接继续有效。
- 任务归组不扩大权限。每轮和当前集合按原项目、来源及个人背景权限校验；无权历史不泄漏名称、内容和数量，不展示不完整授权集合为“完整结果”。回收/删除继续使用实际依赖，历史页面不能恢复已永久删除的独占内容。
- UI 严格复用 frontend-v1 字体、token、图标、按钮、表格、菜单、弹层和密度；frontend-v3 正式实施，冻结原型及 frontend-v1 只读。窄屏、键盘和错误反馈沿用现有组件。
- 不新增依赖、流程编排、版本树、通用快照系统、任务模板、调度平台或无界自动处理；不提高模型并发/预算，不顺带重构助手。本张需要正确的集合/保存逻辑，不能仅把多行任务在前端隐藏。

## 验收标准

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| R17-1 | 同一任务连续清洗、改写、扩写；另从来源发起独立任务 | 连续处理只占一行、一个稳定工作区，独立发起才新增；名称、当前数量与最近轮次正确 |
| R17-2 | 100 条选 10 条改写，再扩写 20 条、去重 | 未选 90 条保留，变更按身份替换，扩写追加，去重/补齐遵守 OPT-16；所有操作使用同一当前集合 |
| R17-3 | 首轮扩写/部分范围，运行中、部分失败、取消与恢复 | 不把参考输入或未选草稿记录纳入成果；上一状态及成功结果保留，旧值不冒充新成功，恢复不重复输出 |
| R17-4 | 自动重试/补生成、手动补齐、重新运行最新轮 | 自动过程不增用户轮次；明确手动提交才增轮；重做替代原轮效果，历史新增不重复累计 |
| R17-5 | 多轮累计修改/新增/去重后全量或部分保存 | 确认范围及增改删准确，保存当前成果而非最后一轮/全部历史；未选和未授权内容保留，幂等与冲突有效 |
| R17-6 | 全量保存后基于同一草稿继续；部分/多目标保存、未知回执 | 新基线来自实际保存范围的当前内容；范围不扩大、已采用身份不复用；部分/多目标不自动拼接，未知先对账 |
| R17-7 | 两账号同时提交、提交与保存并发、旧响应/失效 Worker | 同任务只有一轮生效，冲突有恢复提示，过期状态不覆盖，不重复创建或保存 |
| R17-8 | 查看历史、刷新/前进后退/旧链接；单链、分叉、缺失关联 | 正确定位轮次与当前集合，历史只读；归组不靠名称猜测、不合并分叉、不丢旧入口 |
| R17-9 | 分组搜索/排序/分页、最近 100 项及五类状态 | 按完整任务聚合统计，轮次不占额外任务名额，旧祖先不因列表窗口消失；当前执行/质量/保存真实 |
| R17-10 | 来源权限/删除、助手多批与局部调整、桌面/窄屏/键盘 | 不扩大授权或泄漏历史；助手范围/确认不退化；严格沿用 donor，配置/历史返回保留位置与选择 |

## 验证、交付与授权

- 使用现有可控模型/数据库/HTTP 夹具验证集合替换、追加、去重、部分失败与恢复，以及保存修订、幂等和双账号竞争；复用 OPT-16 已通过且未被改动失效的证据，不重复跑等价检查。
- 集中浏览器检查一条小样本多轮链、历史回看、保存后继续，以及列表/错误/窄屏交互；完整数量边界交由可控夹具，不反复调用真实模型生成大批数据，不做额外压力或长时稳定测试。
- 按实际影响运行类型、lint、必要构建及定向回归；实施时更新受影响架构、领域词条和测试计划的最小差异，证据集中记录。需要持久状态升级时验证历史兼容与来源清理，不扩大为无关全仓改造。
- 后续获授权实施时复用当前分支、同一 4217、既有项目和管理员/编辑账号，保留用户数据；一个 Ticket 一次集中 checkpoint，不逐轮、逐页面人工验收。只重建改动服务；合并、推送、tag 和正式部署另按授权。
- 当前只新增本 Ticket 和必要的 Spec/PRD 索引，检查 Markdown 与一次 `npm run docs:check`；Implementation not-started，不运行应用测试、不重建环境，不把文档状态当成交付完成。
