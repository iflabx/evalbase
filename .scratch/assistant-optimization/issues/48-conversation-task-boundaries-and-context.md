# OPT-48 长会话任务边界与有界上下文

Status: ready-for-agent
Implementation: not-started
Validation: not-run
Blocked by: OPT-46


- 优先级：P1。范围：同一会话内顺序任务与长历史；当前一个session.task长期累积预算、100条turn限制混合自动事件和用户对话。
- 前置：[OPT-46](46-compact-plan-amendment-and-recovery.md)提供首次规划/修改/核对的紧凑合同；不依赖OPT-47的业务处理实现。
- 依据：[共同合同§10.2–10.3](../../../docs/assistant-mechanism-consolidation-2026-10-22.md#task-scope)、[领域词汇](../../../CONTEXT.md)、[ADR 0014](../../../docs/adr/0014-project-agent-and-processing-runtime.md)。

## 目标

聊天历史变长不使新目标继承旧目标的耗尽额度；同一目标的修改/继续仍保留原预算与真实进度。模型请求使用当前权威事实和必要历史，避免越聊越长导致输入膨胀、旧约束复活或参数截断。

## 修改范围

1. 引入稳定的助手任务身份及版本化任务边界，和sessionId、turnId、处理task/run区分。一个会话同一时刻仅一个当前可执行任务；旧终结/暂停任务有可定位的要求、回执和预算快照。
2. 同一任务的继续、补充、改数量、改名、主题局部替换沿原身份；不能因失败、预算耗尽或新turn建立“新任务”。当前任务已终结且用户明确发起独立目标才建新任务。未终结时明确切换才保存旧检查点并切换，歧义仅问是否另开目标，不能仅靠“当前有goal”永久绑死。
3. 明确切换使旧执行令牌失效，旧Worker迟到回执仍归属原任务且不推进新任务。恢复历史任务须先核对当前任务状态和用户意图；沿用其原预算/授权，不形成同时执行的两个任务。采用/发布仍绑定原任务、成果及修订。
4. 优先复用现有session/turn与task JSON存当前身份及终结快照引用，按需增加版本字段/索引；不把全部旧任务快照塞进每次响应和当前JSON，不复制候选正文。选定存储结构需说明写入事务、索引、恢复/回滚及旧格式读取；若涉及不可逆选择按现有ADR规则记录，不增加新的任务平台。
5. 统一模型上下文投影：当前目标、有效要求、待修改意图、授权、必要回执、相关背景片段及有限近期消息。使用OPT-46操作模式裁Schema与交付范围；旧失败参数与已撤销要求仅作历史，不能重新成为生效限制。
6. 请求前按模型配置的输入容量预留Schema/输出；工具正文、重复附件和历史优先裁剪，必要事实超限则按相关交付/步骤分段读取，不静默丢规则。仅有字节估算时标明估算并使用保守界限，不能冒称精确token。无需新增模型摘要请求或向量索引。
7. 新合同不以累计100条turn拒绝正常继续，历史按现有接口分页且单次返回有上限，自动事件/用户消息分别统计。存储容量与当前输入窗口分开；不得为解除容量而清除旧预算/原始消息。旧合同按版本兼容，旧关闭验收会话保持原状。

### 全链路复审增补

8. 当前任务执行依赖与历史展示权限分开。独立新目标不继承整个会话的失效来源或旧写权限，但受限历史仍须按原权限脱敏/拒绝；不能通过裁掉历史检查泄露私密内容。按任务批量读取当前必要依赖，避免每次消息/状态读取遍历全部历史依赖。
9. 在实际请求边界核算system、工具Schema、当前事实、历史、引用及输出预留的总量；首次、增量、纠错和恢复共用投影。背景按相关交付读取，旧错误正文不能挤掉有效约束。工具/响应本身原容量保护保持，不因上下文裁剪取消。
10. 关键词仅作为可证明的快速识别；未识别普通表达进入已有结构化意图/必要澄清路径。否定、引用别人的话、同义改写和复合句不能仅因命中某个词触发新任务、扩大执行或误用完整规划。复用现有意图机制，避免新增独立意图服务。

证据：[全链路审查F06–F07、F12](../../../docs/assistant-full-review-2026-10-23.md)；共同职责：[方案§11](../../../docs/assistant-mechanism-consolidation-2026-10-22.md#full-agent-contracts)。

## 接入与边界

直接调用方包括消息提交、任务控制、会话读取、模型输入构造、自动派发和回执归属。它们共用当前任务解析；移除“task.goal存在→所有未来消息永远同任务”及原始全历史投影路径。新任务初始预算仍走现有默认限制，本票不提供追加额度；细分账本及续接在OPT-49实现。

前端只做保持现有读取/链接可用的兼容适配，完整新任务/续接状态由OPT-50接入。后台不能依赖未来UI来保证不重置预算；当前消息入口的任务边界必须完整校验。

## 验收标准

| 编号 | 场景与通过标准 |
| --- | --- |
| R48-1 | 同会话任务A终结后明确新目标B：身份、初始额度、要求和执行对象分离；A的回执/已耗不变，B不会继承A已耗或旧限制；A成果仍可读取 |
| R48-2 | A失败后“继续”、改名、数量修改、重述目标及刷新均保留原任务与消耗；预算耗尽时不能由模型new-task提议绕过；未终结任务切换不明确时只问一次边界问题 |
| R48-3 | A→明确暂停切换B→再明确恢复A：仅一个活动任务，A使用原账本和未完成位置；迟到A响应不能覆盖B，旧确认不会变成B权限 |
| R48-4 | 使用至少120条混合用户/自动turn、3个顺序任务的隔离合成历史：公开读取正确分页，当前消息可受理；旧消息、回执和预算完整，不发120次真实请求 |
| R48-5 | 同一长历史中旧约束已撤销、最新修改待保存：捕获模型真实请求，只有有效合同与必要证据生效，待修改/权限/来源修订不丢；输入受配置窗口约束，不携带全历史失败正文 |
| R48-6 | 单份附件/全部必要事实超窗口：受限读取或具体容量提示，不能虚称已完整读取、生成新分类或静默放宽；跨用户/跨项目背景仍不可见 |
| R48-7 | 旧格式会话只读、旧预算耗尽、旧成果链接和旧处理中任务：无读取迁移写入、无预算重算、无历史自动重跑；新增身份与终结快照原子保存、并发切换最多生效一次 |
| R48-8 | 旧目标来源失效或用户降权后，对独立可访问的新目标按当前权限受理；旧受限历史不能出现在页面、工具响应或模型请求中。未明确换目标的原请求仍受原依赖约束 |
| R48-9 | 捕获首次/增量/纠错/恢复的实际出站载荷，所有组成加输出预留受同一容量限制；必要事实放不下具体说明/分段，不能丢有效限制或按坏id过滤掉恢复事实 |
| R48-10 | 同义普通问法、否定、引述和多分句经公开消息入口得到一致业务边界；不因关键词误建任务或升级执行授权。当前依赖批量读取，历史分页与权限查询不退化为逐turn全量读取 |

## 定向验证与完成口径

在现有HTTP/持久化入口用合成历史、可控模型、并发和迟到回执测试；验证实际请求大小、身份、快照/账本前后值及任务受理数。覆盖必要兼容字段和分页，复用未受影响测试。不做真实长对话压测、两小时运行或大批生成。

本票完成需任务边界和上下文实际接入全部直接调用方，不能只增加taskId字段或一个未使用的摘要helper。允许必要结构调整并记录被替代分支；不改旧OPT-43～45结果。保留全部现有验收数据、旧预算及已完成工作。
