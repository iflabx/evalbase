# OPT-35 交付目标与规划契约收敛

Status: ready-for-agent
Implementation: completed
Blocked by: none

优先级：P1。依赖 [OPT-34](34-document-evidence-and-output-contract.md) 的引用与输出约定定向验证；不等待旧票 Owner 验收。治理入口：[整改方案 §8](../../../docs/assistant-remediation-plan.md#8-2026-10-18-业务编排收敛整改)。2026-10-19 Owner 已单独授权本票开发及定向验证；实施与限制见 [验证记录](../opt35-verification.md)。Owner 验收 pending，本轮未授权部署。

## 目标与问题

对照中，一份 6 条测试集被规划成两份 3 条；分类参数被拒后，模型清空约束仍能保存并显示成功。目标是让模型提交明确的业务交付目标，服务端保存、校验并转换为现有可执行步骤；不再要求模型在多个入口同步维护整套嵌套工具参数。

## 修改范围

- 主要落点为 `src/assistant/requirements.ts`、`plan.ts`、当前工具 schema 与 `agent.ts` 中的规划入口。复用现有 task JSON 和有序 executionPlan；不为目标、计划和状态各建一份独立权威数据。
- 每项交付明确稳定身份、一个目标集合、目标数量及新增/最终数量含义、内部分类配额、输出约定和依据；整体数量由服务端计算。两个类别属于同一集合与分别建两个集合必须有可判定的结构，名称或步骤标题不能代替身份。
- 模型可见规划入口只提交当前业务决策及必要补充。服务端用已验证背景、真实对象与当前要求生成/更新现有执行步骤；明确的 draft/run/范围/修订无需模型再次抄写。保留查询、选择方法和根据中间结果调整的能力，不强制所有操作先生成完整计划。
- 规划提交和用户修改都经同一规范化、完整性校验及持久化入口。未提供的要求保持；撤销或更改需对应本轮用户实际意图。内部参数修复不能自动删类别、定义、配额、字段保护或缩减目标来通过校验；按 OPT-32 既有总预算局部纠正，不能增加无限补救循环。
- 输出约定消费 OPT-34 的结果，本票不再维护另一套关键词解释或文档定义解析。校验计划的交付数、各项数量、类别配额、必要依据与当前用户要求一致；单纯类型合法不算方案完整。
- 只有实际保存成功才返回“方案已保存”及从保存状态导出的摘要。只给方案不创建草稿或处理运行；自然语言修改数量不重复确认，不改动其他语义要求。必要时在现有 JSON 中添加一个可选合同版本标记，供 OPT-37 安全区分新旧任务；不建设通用版本协商系统。

## 不包含

不增加工作流 DSL、任意 DAG、规则表达式、模型自写脚本或新计划服务；不迁移所有历史自然语言计划。执行和回执归 OPT-36，工作区接入与旧任务切换归 OPT-37。

## 验收标准

| 编号 | 可验证结果 |
| --- | --- |
| R35-1 | 保存“GB A.1.a 和 A.1.b 各一份 5 条”时，形成两个独立交付，各自保留定义、数量、分类字段和配额；整体 10 条与当前 5 条分开，规划阶段无草稿/运行写入。 |
| R35-2 | 保存“一份客服意图测试集共 6 条，退款申请和物流查询各 3 条”时，只形成一个目标集合；内部两个配额各 3，整体为 6，不拆成两份也不合成一个模糊标签。 |
| R35-3 | 重放错误字段后的修复：正确调整字段位置可保存，直接清空分类、丢定义、缩小目标、只留第一项均不能被判为完整修复。用户明确取消或修改相应要求时则允许合法更新。 |
| R35-4 | “改为各 3 条”和“总共 6 条”等明确更新准确作用于对应交付；原文摘要与实际规则一致，未变要求及已完成事实保留，失效的确认按既有修订规则处理。 |
| R35-5 | 模型只口头确认、空计划、数量配额冲突、无效引用或保存失败均不显示方案成功；预算耗尽保留最新有效要求及具体未完成项。合法保存有真实回执，刷新后可读相同结果。 |
| R35-6 | 现有单次查询、已有输入的清洗/改写继续可用，不强制增加多份交付或额外开工确认；修改/执行仍通过同一权限、字段保护和容量守卫。 |

## 验证与交付

以本次两个真实规划轨迹及“删除约束后假成功”作为可控重放输入，检查服务端保存结构，不用模型文本作为断言。复用 OPT-28/32/33 中仍适用的数量、修复预算、要求保存用例，只跑受影响项。真实模型验证集中于 OPT-37。

向 OPT-36 交付单一生效交付目标、可执行步骤及修订/引用绑定合同。将被替代的模型可见参数入口和重复归一逻辑退出新路径；旧任务所需兼容保留在明确边界，记录剩余调用方，不并存两个新任务写入入口。
