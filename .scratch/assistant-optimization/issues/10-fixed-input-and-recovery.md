## 目标与依据

修复同一会话中“按背景选取 → 处理 → 核对 → 修正方案 → 提交审核”的连续流程。固定的输入不能在后续步骤被无意重新随机选取；同一批记录的后续处理不能变成新增候选；参数或步骤错误应能在原授权范围内恢复，用户无需提供内部 ID 或工具格式。

本张恢复既有产品合同，不增加智能体平台或新业务功能。依据：[助手 PRD §7](../../../docs/PRD-data-selection-and-assistant.md#7-ai-04-项目助手)、[CONTEXT](../../../CONTEXT.md)、[架构 §9](../../../docs/architecture/data-selection-and-assistant.md#9-方案执行与预算续做)、[ADR 0014](../../../docs/adr/0014-project-agent-and-processing-runtime.md)、[测试计划 §5](../../../docs/test-plan-data-selection-and-assistant.md#5-整改验收计划)及[批次约定](../spec.md#整改批次执行约定)。

## 最小修复范围

### 1. 固定输入贯穿连续步骤

- 区分选取范围与模型处理；不要用一次无必要的模型改写来“仅固定范围”。允许“选取后处理”或“首次处理时冻结选取”的合理路径，不硬编码唯一工具顺序。
- 后续声称处理“已固定记录”的步骤必须引用真实固定输入及其来源身份、内容版本；不能因携带重复的随机参数再次抽取。用户明确要求重新选样时才按新要求生成范围并核对后续资格。
- 固定步骤自动续做与模型即时工具调用使用同一检查，避免只修改提示词而持久方案继续错误执行。

### 2. 候选汇总反映真实处理关系

- 同批记录的后续分类、改写和局部修订按真实来源及处理关系替代对应有效候选；独立扩充和补足仍保留应有新增结果。保留历史运行与回执，不通过删除历史来修正计数。
- 不以问题文本去重代替候选身份，不把所有任务简化为“只取最新运行”，不将两次独立随机运行伪装成真实父子运行。
- 核对、预览、规则选取、采用确认与实际采用共享有效候选范围；数量、重复、字段保护与来源统计一致。旧会话恢复先辨认可复用结果，不能仅更新 requirements key 或盲选最后一批。

### 3. 背景、规则与计划保持一致

- 补读背景后协调当前证据、有效分类规则、执行方案及已有成果资格。区分补充相容证据与实际改变定义；不得只清除 review、保留过期执行状态，也不能无条件重跑全部成果。
- 处理前所用类别名称、编号、目标字段及定义来自实际选用的文档内容；发现保存规则与附件不符时先修正受影响规则和步骤。真正的业务歧义才询问用户，不要求用户修工具参数。
- 结构符合枚举与语义符合附件分别记录。尚未核对内容就明确显示待审核，不能用“分类与配额符合要求”暗示内容已验证；不新增承诺通用自动语义判定器。

### 4. 失败后能修正未执行方案

- 对齐 `plan_task` 的模型可见合同和实际校验：澄清问题与可执行动作保持合法组合；参数失败返回能纠正的具体字段原因。
- 在原用户授权范围内，允许修正未执行的步骤尾部，再调用匹配动作；完成步骤的真实回执保留，不能关闭步骤守卫绕过错误。遇到重复同类无进展错误应有界停止并说明原因，不能耗尽预算还只给笼统重试提示。
- 未产生副作用的校验失败可纠正；已提交、回包丢失或结果未知的写操作仍须先对账并复用幂等身份，防止恢复时重复处理、采用和发布。

### 5. 展示可理解的失败与恢复信息

- 在现有任务卡与操作记录中显示失败步骤、简短具体原因、已保留的成果及可用恢复动作；动作不匹配不冒充用户改变了来源范围。
- 保留输入与成功结果。沿用 `frontend-v3` 的 donor 样式，不新增页面；内部 ID、堆栈和工具 JSON 不作为用户必须理解的说明。
