## 目标

同一任务的“可以恢复”、实际能发起请求和页面能执行的动作使用同一份判断。失败修改能恢复原意图；阶段已结束时在原授权与剩余额度内续做，已完成步骤不重做，旧预算不重置。

## 修改范围

### 1. 统一恢复决策与执行前复检

- 会话读取、控制入口和执行前校验共用恢复决策，返回动作、原因、适用修订与有效期；将现有 canResume 等兼容字段从同一决策派生。
- 同段重试沿用原截止时间与尝试上限，必须满足实际请求相同的时间预留、权限和租约条件。“deadline 尚未到”不能单独决定允许重试。
- 已结束段只有具备真实待完成位置、原授权、有进展且累计额度允许时，才通过现有调度形成关联原轮次的新有界段；条件不足返回具体原因，不制造检查点。
- 控制请求不能信任先前页面能力；实际领取与请求发出前重新验证当前修订、权限、依据版本、时间和额度。只有执行阶段才允许按原授权生成，继续规划不能越权。

### 2. 继承预算与恢复身份

- 复用 OPT-43 的待修改意图、业务修改身份、修复计数和尝试记录；新 turnId 不重置同一修改的纠错/故障尝试额度。
- 同段沿用原时间；新段最多 80 秒且不超过任务剩余活跃额度。旧 startedAt/deadlineAt 保持原值，新段单独记录关联，避免用改写时间掩盖预算耗尽。
- 模型、工具、传输重试、修复、自动事件与活跃时长均从持久消耗继续计算。任务累计和每段硬上限沿[机制方案 §6](../../../docs/assistant-mechanism-consolidation-2026-10-22.md#6-恢复资格截止时间与累计预算)，更紧的冻结任务/验证额度优先。
- 活跃时长按实际执行区间结算，用户与后台等待不重复扣账；恢复领取、并发响应和重读不能重复结算同一次增量。新要求仍受同任务累计额度控制。
- 无进展或额度耗尽时停止；自动续段和用户“继续”不能绕过同一限制。旧任务缺关键状态时保留事实并返回限制，不清零或猜造历史消耗。

### 3. 回执、并发与失效

- 复用 session 锁、task revision、execution token 及幂等键；同一修订双击或双标签页恢复最多领取一次、发起一次续段。
- 未知写结果先查原 operation ID 的回执；已经保存/采用的成果不再提交。只执行未完成部分，并保留已有候选、采用记录及固定确认边界。
- 停止、撤权、新要求或依据版本变更使旧恢复失效；迟到模型响应不能保存旧要求或继续旧执行。依据变化按现有规则核对，不自动扩大来源。
- 诊断追加每次恢复及原轮次关联，分别呈现预算拒绝、实际模型超时与业务失败；不把请求未发出称为模型超时。

## 结构调整与接入边界

主要涉及 assistant/budget.ts、tasks.ts、现有控制/执行入口与会话能力读取。允许合并分散预算判断、调整恢复内部合同和兼容 DTO；沿用现有消息/控制路由、调度和存储，不另建恢复服务或通用状态机。

本阶段将服务端所有直接调用方切到共享决策并移除旧独立判断；既有前端字段保持可读。OPT-45 负责新动作的完整展示、失败刷新与页面联动，本票不能以“前端尚未接入”为由保留服务端错误恢复资格。开发记录列出调用方、旧分支退出和历史合同兼容方式。

## 验收标准

详细场景见[测试矩阵 §5.18](../../../docs/test-plan-data-selection-and-assistant.md#518-机制整理验证待实施)。

| R44-1 | MC-06 | 剩余 5 秒、恰好请求预留时间、段已过期、总预算不足时，读取/控制/执行前决策一致；不满足同段条件时额外模型请求为 0 |
| R44-2 | MC-06/07 | 同段重试保持原截止时间；满足新段条件才创建关联段，窗口受 80 秒及剩余额度限制；旧时间/计数不被改写，单有过期段不构成恢复授权 |
| R44-3 | MC-07 | 数量修改失败后普通“继续规划”恢复该待修改意图并正确保存；已授权执行则只续未完成步骤，规划授权不产生处理任务 |
| R44-4 | MC-05/07/11 | 跨段后修复、故障与自动事件额度不增加；耗尽/无进展停止并保留原因；模拟多次重读和续段后预算与实际增量一致，等待时间不重复计费 |
| R44-5 | MC-08 | 保存成功但响应丢失先返回原回执；双击/双标签页最多一次恢复和业务写入，同一次增量不双扣 |
| R44-6 | MC-09 | 新要求、停止、撤权、背景版本变化使旧恢复失效，迟到结果不能覆盖；未失效成果保持且读取仍受权限控制 |
| R44-7 | MC-11 | 同段重试/跨段继续都保留首次失败及关联，实际请求超时与预算拒绝分开；旧任务缺证据如实受限、不回填、不触发重跑 |
| R44-8 | 接入与兼容 | 三个服务端入口实际调用共享决策，旧分散资格/预算分支退出；现有成功回执、仅规划/执行边界、历史只读路径和兼容字段验证通过 |

## 定向验证与完成口径

采用可控时钟、模型故障注入、现有 HTTP/Worker 与隔离持久化验证恢复链。覆盖读取→控制→领取→执行→预算结算→再次读取，故障注入响应丢失、并发领取和迟到响应；不重启 4217、不用真实长等待或大批生成验证计数。

复用 OPT-43 未受影响的回归，只重跑本票改变的合同与调用方。记录实际预算前后值、请求/写入次数、旧数据保护证据和代码基线；保护性停止通过与交付完成分开。本票完成表示恢复机制与定向验证完成，五项 Computer Use 交付由 OPT-45 集中验证。

- 串行依赖：OPT-43 → 本票 → OPT-45；不新增对 OPT-31 旧内容质量验收的硬依赖，不改变旧票完成/未通过结论。
- 保留所有现有验收数据、旧预算和已完成步骤；旧 248/400 条任务不重跑，不重新开启其预算。
