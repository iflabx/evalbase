Status: ready-for-agent
Implementation: in-progress
Blocked by: OPT-28, OPT-30, OPT-32, OPT-33

优先级：P1。第三批质量修复与最终验收。依赖现有 [OPT-28](28-result-scope-and-goal-count.md)、[OPT-30](30-generation-diversity-and-recovery.md)，以及已实施的 [OPT-32](32-tool-argument-repair.md)、[OPT-33](33-document-classification-and-short-plan.md) 定向验证通过。顺序为 OPT-32 → OPT-33 → OPT-31，不按票号顺序执行；前置实施证据沿用各票记录。2026-10-16 已获本票开发及同一4217更新授权；最终业务场景、预算和一次集中验收见 [总方案](../../../docs/assistant-generation-repair-batches.md#5-验证与完成口径)。

## 问题与目标

改写完成后 50 条中有 47 条完全未变化，另有相同问题不同答案；助手却用标签种类数量说明内容足够多样。目标是区分“执行结束、确有修改、结构合格、内容合格、已经保存”，让用户得到真实进度和可操作结果。

2026-10-15 增补：OPT-30 的 50 条结果数量/结构达标，但存在普通知识咨询、翻译和正常讨论被标为 A.1.a，以及期望输出全部写成“安全行为”的情况。原本只要求真实质量反馈和人工逐条审核，本次明确补入按文档定义进行批量内容核对及有限局部修复。调用参数纠错归 OPT-32，编号/定义引用及要求解释归 OPT-33，本票消费它们验证后的要求和依据，不重复实现。

## 修改范围

- 在现有 `src/processing/refine.ts`、`review.ts` 及助手 `review.ts` 中，以本轮冻结的真实输入比较允许修改字段；不能错误地与最初原始文件或其他批次比较。记录实际修改、未变化及未处理数量，按当前有效集合汇总。
- 对明确要求改写的记录，完全未变化不宣称已完成改写目标；给出简短原因和仅处理未生效范围的恢复入口。复用既有有限恢复与累计预算，不无限重写、不覆盖未授权字段。
- 清洗无多余空白/无需规范化时保持原值属于合法结果，不套用改写失败判定。内容变化只能证明字段有变，不能证明语义质量；标点变化不能被总结成“问法已经自然”。
- 将结构问题、问题文本碰撞、改写未生效及待内容审核分别表达。自动完全重复去重与用户保留对照样本区分；不凭标签数量、工具成功或计数齐全自动宣称内容合格。
- 更新助手可见核对结果和总结依据，使用真实统计与明确限制。用户界面保留简短摘要、必要警示及现有结果详情；不增加满屏质量卡片、评分排行榜或新评审智能体。
- 完成原六票及 OPT-32/33 修复后的集成验证，复用现有脚本、可控模型、浏览器和处理服务；记录实际模型请求及人工干预，不建设新的评测平台。

### 内容一致性与有限修复

- 生成/改写配方使用 OPT-33 已验证的类别定义、实际背景片段、当前用户要求和场景；针对目标判定条件生成。涉及某个话题、包含某个关键词或标签配额满足，都不能证明问题属于该类别；正常咨询/翻译也不能仅凭主题标为风险。用户明确要求非拒答或正常样例时，依其真实目标判断，不能一律排除。
- 在现有处理/审核链路内，对当前有效候选分批检查类别含义、问法自然且语义完整、期望行为是否具体且与该题一致。复用现有模型连接和 Worker；输入只含获准背景、当前要求及本批候选，不每条独立发请求、不新建评审智能体。结构检查和可确定的空值/碰撞检查继续使用原规则。
- 内容核对按稳定记录身份和内容/要求修订绑定，得到符合、不符合或存疑以及简短理由；模型输出先做结构和身份校验，未知 ID、漏项、超时或解析失败的项保持待审核。模型核对通过仅表示本次未发现问题，不自动视为人工审核、采用或发布。
- 新生成且未采用的候选，若明确不符合已冻结要求，可在原授权范围自动局部重做一次，再核对一次；改写记录只修改获准字段，未选及已符合记录保持。存疑结果留待用户核对，不自动改类别掩盖问题，不为了凑数删题或降低目标。已采用内容的变化继续走原修订与确认，禁止自动覆盖草稿/正式版本。
- 内容初检、局部重做与复检均计入现有任务累计请求/时间预算；每项同一修订最多初检一次、自动重做一次、复检一次。相同输入和规则复用已保存的核对结果；刷新、后台续做或重复请求不重置额度。额度不足或停止/撤权时保留候选、未审核项与原因，不能启动新的无限补齐链。
- 恢复后的候选重新走数量、去重、字段保护和既有采用身份检查；内容/规则修订变化使受影响的内容结论和确认失效。结果正文与核对统计使用当前有效集合，历史轮次不重复计数。旧运行没有内容核对证据时显示未核对，不回填虚构结论或批量重写历史配方。
- 既有结果列表增加必要的问题提示和“只看需核对”范围，复用逐条查看、局部处理、固定确认；不新增保存/发布质量硬门槛。用户仍可明确选择结构合法的部分或存疑成果，须显示实际范围和未解决问题，不能将它汇总为全量内容合格。UI 严格对齐 frontend-v1，沿用字体、间距、组件和折叠明细。

| --- | --- |
| R31-1 | 可控 50 条改写仅 3 条变化、47 条原样时，报告 3 条变化/47 条未生效，不称全部改写成功；部分重做只触及授权范围且未选成果保留。 |
| R31-2 | 比较使用当前轮真实固定输入；保护字段不变。合法清洗无变化正常结束；仅标点改变不能被当成语义已通过，内容审核状态独立。 |
| R31-3 | 相同问题不同答案明确提示碰撞并允许按业务要求保留；标签种数、结构通过及模型声称完成不能自动解除内容审核。 |
| R31-4 | OPT-32/33 定向验证通过后，依总方案用一个新会话、一个上传文档和普通短提示词，先方案再逐类执行八个各 50 条；0 次用户内部参数纠错、0 条人工种子、0 次绕过助手 API 补造结果。复用前票证据，不每票重跑 400 条。 |
| R31-5 | 最终 400 条结构检查全覆盖；逐条审核自然问法、语义完整、分类和期望行为，并区分原生结果/自动恢复/人工修改。缺额、内容问题或只抽样时如实记录，不标全量可用。 |
| R31-6 | 八个成果经既有固定确认保存，发布按实际用户授权及既有确认执行；刷新可读且有真实回执。逐类数量、来源及交付状态准确，不因一个类别完成就结束全部任务。 |
| R31-7 | 有限失败保留当前成果，停止/续做不重复创建或采用；汇总 OPT-26–33 相关定向证据与唯一一次大批集成证据，4217 保留旧验收数据，UI 与 frontend-v1 对齐。 |
| R31-8 | 固定包含明确符合、普通相关话题误标和边界存疑的内容样本，依据原文定义先人工记录判据；真实批量核对逐项对照并报告漏报/误报，不以模型自评作为唯一真值。普通概念问答或正常翻译不因主题词自动成为 A.1.a；复用 OPT-33 的意图说明和无编号改写规范，分别验证标签含义及原事实保留/改写要求，不强行增加风险类别、编号或拒答预期。非 GB 两组各 3–5 条，按已有批量核对路径执行，不额外生成两批大测试集。 |
| R31-9 | 明确不符合项只在授权字段/范围局部重做一次并复检，未选和已符合项内容及稳定身份不变；复检仍不符、存疑、漏项或超时保留待审核。原要求若为按题写预期行为，不能全部“安全行为”就通过；用户明确要求固定标签时不误判。 |
| R31-10 | 生成、初检、局部修复、复检和网络重试按原累计预算记账；刷新/续做不重复核对相同修订或刷新额度。取消、撤权、规则变化及旧快照分别验证，旧结论不覆盖新内容或解除旧确认失效。 |
| R31-11 | 页面区分结构有效数、内容已核对/待核对/有问题数和保存数，统计分母与范围准确；模型核对与人工审核分开。用户选择部分或存疑成果仍可按原权限固定确认，回执与未完成提示一致，不自动发布或改写已采用内容。 |

## 实施与验证边界

先以隔离夹具验证当前轮差异、内容结论身份、字段保护、有限修复和预算；再以当前真实模型的小样本验证漏报/误报，最后才进行原约定的一次八类集成。400 条全部结构检查及逐条内容复核沿用 R31-5，模型自检不能替代该验收。保留所有失败尝试；缺额或内容不达标如实列出，不反复整批重跑到成功，也不通过新增平台、框架或无界模型调用解决。

非 GB 样例和判据复用 [OPT-33 通用文档矩阵](33-document-classification-and-short-plan.md#通用文档验收矩阵)；本票仅验证相应候选的内容核对及已有有界修复，不重复测试所有文档变体，不另建通用评分器。文档依据不足时保持存疑/待审核，不凭格式通过给出内容合格结论。

不改变原件、正式版本、权限、三字段格式和采用/发布确认。不新增通用评分体系、向量相似度、跨会话知识库；核对结果优先复用当前任务/结果元数据，仅在实施证明确有需要时做最小兼容增补。实施、部署及实际未通过项以验证记录为准；自动验证不代表 Owner 验收，合并/推送不在本轮授权内。
