# OPT-22 项目助手工具参数与计划稳定性简化

Status: ready-for-agent
Implementation: completed
Blocked by: none

优先级：P1。Owner 已于 2026-10-14 单张授权开发，Implementation completed、Owner pending。详细范围见 [总方案 §3.2](../../../docs/assistant-workspace-reliability-plan.md#32-轻量工具与要求合同)，继承 [PRD §7.1–7.3](../../../docs/PRD-data-selection-and-assistant.md#7-ai-04-项目助手) 的自主规划和真实步骤完成约束。

## 目标

让模型使用已有能力完成用户目标，减少重复参数和自相矛盾；相同要求重排不触发无意义的重新执行。简单请求不强制规划，复杂任务保留可调整的真实有序步骤。

## 实施范围

- 模型工具按查询/规划/执行/核对/待确认阶段及当前权限投影；基于持久事实判定，不用关键词分类器，不另建工具注册平台。补读与合法纠错通道在可用阶段保留。
- 收敛 `plan_task` 的模型可见参数：只提交变化的意图、缺失约束和当前动作必要参数；既有来源、固定选择、目标草稿、步骤修订、回执和完成数量由服务端绑定。沿用同一规范化入口，省略不等于清除，显式撤销才能删除要求。
- 步骤标题与说明不承担身份；稳定操作键继续绑定实际任务、步骤修订及固定参数。后续依赖仍引用前序真实成果，不接受模型虚构 ID。
- 修复独立要求列表仅重排导致 `planRequirementsKey` 变化的问题：在现有规范化路径做精确文本归一、完全相同项去重和稳定比较；有序步骤不排序，自由文本实质变化不忽略。
- 合法规则改变按当前依赖核对受影响步骤与待确认卡；不能证明可复用时保留实际成果并暂停相关资格。已发生业务操作是历史事实，不能因改标题/改计划解除未知写绑定。
- 提交前错误按具体字段和可用引用反馈；统一合同后删除受影响路径的重复提示词和模型参数兼容分支。旧存储结构在边界兼容读取，不批量改写旧任务。

## 不做

不做语义等价模型、通用 DAG、任意计划表达式、新任务数据库、14 个业务工具整体重写或所有模块重新分层。阶段能力不是安全边界，服务端权限和确认继续执行。不要只靠缩短 prompt 宣称完成。

## 验收

| 编号 | 验收 |
| --- | --- |
| R22-1 | 通过真实 requirements 规范化到 revisePlan 的路径，原要求、尾空格、相同项与独立项重排不重置已完成读取；真实改数量/字段/来源则使准确范围失效。有序步骤改变仍可被识别。 |
| R22-2 | “先给方案”没有业务写入；“按方案做”执行当前方案；简单清洗可直接提交。规则互斥返回具体字段，不把冲突的 plan_task 当作成功。 |
| R22-3 | 当前阶段只暴露合适工具，执行阶段仍可补读缺失背景或纠正合法参数；待确认不自动批准，后台等待不调用模型查状态。 |
| R22-4 | 模型不重复提供已固定 ID/记录集合也能完成同一任务；未提供保持、明确撤销清除，真实数量仍由服务端检查。旧完整参数记录可恢复。 |
| R22-5 | 重规划不能扩大来源、改变字段保护、重复采用或解除未知写入；直接越权调用仍被业务接口拒绝，原回执与候选保留。 |
