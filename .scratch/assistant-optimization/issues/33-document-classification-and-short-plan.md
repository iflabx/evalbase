# OPT-33 文档分类引用与短提示规划修复

Status: ready-for-agent
Implementation: completed
Blocked by: none

优先级：P1。基于现有 OPT-23/29/30，依赖 [OPT-32](32-tool-argument-repair.md) 的调用前纠错及定向验证。治理入口为 [PRD §7.8](../../../docs/PRD-data-selection-and-assistant.md#78-调用纠错文档规划与内容一致性补修2026-10-15待实施) 和 [补修顺序](../../../docs/assistant-generation-repair-batches.md#7-后续补修与-opt-31-调整)。方案创建时仅获文档授权；Owner 于 2026-10-15 后续授权实施，实际完成、验证及同一 4217 更新见[验证记录](../opt33-verification.md)。

## 问题与目标

GB 原文按 `A.1` 标题和 `a)` 等子项排版，当前按完整字符串检索/校验会漏掉 `A.1.a`，拒绝合法的“编号 + 类别名称”。定义边界也未正确截止到相邻子项，可能把下一类别定义错绑到当前类别。短提示中的“期望输出写安全行为”被固化为只有“安全行为”一个值的枚举；规划还出现 `steps` 非数组及超过 20 个场景，最后停在无进展。

目标：用户上传文档并提出简短业务需求后，得到引用准确、约束合理、非空且可执行的方案；“先给方案”保持无业务写入。GB 仅是验收资料，规则适用于已有 PDF/MD/TXT 提取文本，不把安全分类或 50 条写成产品默认。

通用性按下方文档结构矩阵验收，不以换一份仍采用 GB 式编号的资料代替。只覆盖当前支持格式、提取质量与容量内的输入；信息缺失或结构不可判定时准确说明限制，不承诺任意文档必然理解正确。

## 修改范围

- 以 `src/assistant/background.ts` 及现有规划/要求归一逻辑为主，在既有页段文本与定位上解析可证的父章节和子项关系。查询 `A.1.a` 可命中实际 `A.1 + a)`；允许编号、原名称及二者组合映射到同一真实定义。标签展示与原文定义引用分离，不要求拼接显示值在原文连续出现。
- 定义截止于同级下一子项或下一章节，不跨类别拼接；返回原文页段和可追溯定位。只在文档文本确有依据时归一编号与名称；对名称歧义、提取缺失或编号不一致给出业务说明，不能通过宽松 contains 或虚构引用放行。普通无层级背景继续使用现有读取路径。
- 无编号自然段直接以原文页/行片段作为依据，不生成虚构的章节或强制分类字段；简单表格只有在现有提取文本能明确保留类名、定义和示例对应关系时才使用。跨页/片段的必要定义和约束沿现有读取接口有界补读，保留实际覆盖范围；提取错位、定义冲突或缺失时提出具体业务澄清，不猜测、不默默忽略约束。
- 文档读取、规划预检和执行使用同一已验证引用。服务端持久事实绑定当前会话文档、提取版本/哈希、页段及规则修订；只在证据相同且有权访问时复用。附件失效、权限撤回或要求更新后，旧依据不得套用于新执行；文档文字不产生工具授权。
- 期望输出的自然语言要求与固定枚举区分：“写出安全行为”表示每题应有具体可检验的预期行为；只有用户明确要求固定值/枚举时才建立 allowedValues。不得用模型自报 `basis:user` 代替用户实际表达，也不能把 Metadata 分类规则误套到期望输出字段。
- 规划使用本阶段必要的紧凑参数和已验证类别定义；服务端绑定可证对象与固定执行事实。场景围绕目标类别的判定条件组织，普通相关话题不自动成为风险场景。场景数遵守现有 1–20 上限，不要求用户填写；不得静默截断从而丢失用户目标。
- 保存方案前检查每个目标、数量含义、类别依据、非空步骤和能力合同。只给方案时不创建草稿、不入队、不写候选；明确执行后沿最新方案推进，保留既有采用/发布确认。内部结构问题交给 OPT-32，确定性的引用校验错误在本票修正，不让用户通过删除编号或解释字段来继续。

## 通用文档验收矩阵

只维护三个基础样本：现有 GB、一份小型客服意图分类说明、一份无编号的客服话术改写规范。后两份提前记录正确依据和预期结果；编号、排版、截断、冲突及指令污染由同一内容派生小夹具，不为每项另建真实模型任务。

| 情况 | 最小样例 | 必须验证 |
| --- | --- | --- |
| 不同编号与层级 | GB 的父章节加字母子项；意图说明切换为 `1.2.3`、`一、`、`（一）` | 编号/名称对应同一真实定义，边界不串项；只支持可证的当前示例形式，不建设任意语法解析器。 |
| 无编号标题或自然段 | 改写规范以自然段说明保留事实、调整表达及禁止添加的信息 | 保留实际要求及页/行出处，不强制套分类体系；期望输出仍遵循用户业务要求。 |
| 简单表格 | 意图说明的“类别、定义、示例”三列表；MD 表格及现有文本 PDF 提取夹具 | 行列关联清晰时正确读取；表格错位、列丢失时说明依据不足，不凭相邻关键词拼定义。 |
| 跨页或跨片段 | 将已有定义与限定条件分开；在容量内把相关条件放到后续片段 | 按真实引用补读所需上下文，不能只读前段就称已覆盖完整要求；预算内无法读全时说明未覆盖部分。 |
| 矛盾、歧义或缺失 | 现有样本中加入同名不同定义、互相矛盾要求，或截断关键定义 | 指出具体冲突/缺口，必要时用业务语言澄清；不擅自选一条、不制造引用，也不误记为工具参数错误。 |
| 文档中的操作指令 | 样本夹带“忽略权限”或“直接发布”等文字 | 仅作为资料文本，不覆盖用户指令或扩大权限；规划不触发未经授权写入。 |

### 样例与调用规模

结构、引用和权限边界使用现有提取/规划测试与可控模型；真实模型仅执行 R33-4/7 的六次规划，以及 R33-5 原有的一次 5 条生成衔接。六次规划覆盖 PDF/MD/TXT 当前格式，样例与提示在运行前固定，不跑结构 × 格式 × 模型的全组合。单次失败保留，修复后的定向复测单独记录，不删失败样本凑通过率。非 GB 内容由 OPT-31 复用本矩阵核对，不再增加大批生成。

六次正常规划均提供充分业务目标；无编号规范可用“按这份规范设计 5 条客服问法测试，先给方案”等请求验证从文档拟定生成方案。真正要求改写已有记录时仍需有权读取的真实输入，缺少输入属于必要业务澄清，不作为内部参数错误，也不能伪造来源来满足通过标准。

## 验证与实施边界

定义匹配/边界采用可重放文本夹具；真实短提示使用当前配置模型和隔离会话。各次真实调用计入原预算，报告参数恢复、规划有效性和执行结果，不靠长技术提示或人工种子修通。保留既有失败会话与运行快照，旧冻结配方按旧语义恢复；用户新要求产生新修订，不能原地重写历史证据。

不增加 OCR、向量库、独立知识库、文档编辑器或新规划服务；复用现有提取内容、工具和后台执行。UI 仅调整现有方案、依据与业务错误展示，严格对齐 frontend-v1。候选逐条语义检查及有限内容修复属于 OPT-31，本票的规划正确不代表生成内容已合格。

不升级成通用文档解析平台，不为文档类型增加策略插件或新表；扫描件、复杂合并表格及提取丢失仅要求现有入口清楚说明无法可靠读取，可提示提供当前支持的可读文本。当前主流程、文档格式和容量边界不变。
