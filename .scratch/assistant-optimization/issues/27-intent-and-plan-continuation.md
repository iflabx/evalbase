# OPT-27 最新用户意图与计划暂停、续接修复

Status: ready-for-agent
Implementation: not-started
Blocked by: none

优先级：P1。第一批，可独立修复；合批验证使用 OPT-26 的反馈合同。本次仅文档，开发待后续授权。共同边界见 [三批修复方案](../../../docs/assistant-generation-repair-batches.md)。

## 问题与目标

本轮明确只要求文本时，旧待执行步骤仍优先于 `nextAction:none`。目标是由最新有效用户意图决定是否继续业务操作，已有成果保留，用户无须猜测怎样才能阻止助手继续执行旧计划。

## 修改范围

- 梳理 `src/assistant/agent.ts` 的 `plan_task`、`pendingPlanAction`、固定步骤执行和自动续做，配合 `plan.ts`、`tasks.ts`：本轮回答/规划/执行意图及现有执行授权先于旧 pending 步骤；明确暂停业务执行时不能被旧步骤覆盖。
- 复用现有任务/计划状态与修订。`nextAction:none` 在本轮仅回答或规划时不能被重解释为立即执行；“继续执行”只恢复最新获授权方案。不要把模型一次未选工具永久等同于用户撤销授权。
- 区分暂停后续步骤与已入队运行的取消：暂停不再派新任务；用户明确停止运行则使用已有取消机制。已完成回执保留，停止/改要求后的旧自动事件和迟到响应不能重新启动旧工作。
- 计划调整后仅保留仍匹配对象、范围及修订的有效回执；读取进度、刷新或重新打开会话不会重复创建草稿或重新执行完成步骤。
- 界面只用既有状态和简短下一步说明表达“方案待执行”“已暂停”“处理中”“待审核”；不新增强制确认卡或每轮规划弹窗。

## 非目标

不建立独立状态机平台、自然语言关键词规则库或新任务调度器，不取消用户已授权且未改变的正常自动推进。只改当前助手链及其持久恢复边界。

## 验收标准

| 编号 | 验收 |
| --- | --- |
| R27-1 | 有旧 pending 步骤时说“先别执行，只解释方案”，本轮无新草稿/处理/写入；允许必要只读查询。`nextAction:none` 不被旧 action 覆盖。 |
| R27-2 | “按方案执行”使用最新方案及真实回执继续，完成步骤不重做；初始已明确执行的请求不会再次要求开工确认。 |
| R27-3 | 暂停后收到自动续做、迟到工具响应或刷新恢复，仍不启动旧步骤；明确停止后沿用取消保护，不能写入失效结果。 |
| R27-4 | 执行中修改数量/范围仅影响后续授权工作，不能沿旧方案提交；已完成成果不丢失，失效确认卡不能写入。 |
| R27-5 | 同会话经历方案→执行→暂停解释→继续，状态和真实副作用一致；界面不增加无意义确认，沿用 frontend-v1 样式。 |
