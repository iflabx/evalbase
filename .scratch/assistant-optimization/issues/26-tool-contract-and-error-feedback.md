# OPT-26 工具参数合同与用户错误反馈修复

Status: ready-for-agent
Implementation: completed
Blocked by: none

优先级：P1。第一批。依赖已存在的 OPT-20–25 实现；已按 Owner 后续单张授权完成开发、定向验证及同一 4217 更新，Owner 人工验收 pending。共同边界见 [三批修复方案](../../../docs/assistant-generation-repair-batches.md)，实际证据见 [实施与验证](../opt26-verification.md)。

## 问题与目标

计划接受的输入描述与工具实际参数不一致，`create_draft.instructions`、`submit_processing.allSelected` 等错误反复出现；界面直接把跨工具纠错说明交给用户。目标是让模型使用真实可执行合同，在有界范围内自行修正内部参数错误，用户只处理业务问题。

## 修改范围

- 对齐 `src/assistant/agent.ts` 中工具定义、计划步骤输入和校验/执行映射：每个 action 复用实际工具 schema 或从同一来源派生薄合同，避免通用 input 暗示所有 action 都接受同一组字段。读取、规划和执行阶段暴露的能力与当前模式一致。
- 已知当前对象、草稿及候选引用继续由服务端校验绑定；区分背景文档和资产引用，不把非法 ID 静默转换成另一个来源。结构错误在任何业务副作用前被拦截。
- 内部修复信息只包含本次工具、错误路径、允许字段及必要正确结构；去掉每次重复的跨工具大段提示。沿用现有共享预算，重复相同错误无进展时停止，不增加第二套重试循环。
- 调整 `src/assistant/diagnostics.ts` 与 `frontend-v3/src/components/project-assistant.tsx`：普通视图说明“哪一步未完成、已有成果是否保留、能做什么”；技术信息收进诊断详情，不能优先直接显示底层 hint 或让用户删除 `allSelected`。
- 从实际回执决定成功与失败；工具完成但总结失败时不把业务操作显示为未执行。仅业务信息不明确时要求用户补充。

## 非目标

不支持空输入生成（见 OPT-29），不替换模型框架，不建设通用 schema 注册平台，不靠扩大可接受任意字段掩盖错误。UI 沿用现有布局和 frontend-v1 风格。

## 验收标准

| 编号 | 验收 |
| --- | --- |
| R26-1 | 计划与直接调用对同一 action 的合法/非法参数结论一致；覆盖本次两个错误字段、背景 ID 误作资产及缺少必填字段。非法步骤未创建草稿、任务或候选。 |
| R26-2 | 可控模型先给错误字段后改正，在原预算内完成；重复同错耗尽后有明确终止原因，无无限续做、无重复业务写入。 |
| R26-3 | 用户用“先写方案”“按方案执行”等短话即可走通已有能力；无需内部 ID、工具参数或人工纠错提示。依赖 OPT-29 的能力暂时明确反馈尚不支持。 |
| R26-4 | 参数错误、来源失效、模型暂时不可用、业务成功但总结失败分别给出准确反馈；普通界面没有长堆栈、密钥、跨工具参数教学，诊断保留定位所需信息。 |
| R26-5 | 定向浏览器覆盖报错及恢复、已有成果入口、诊断展开、键盘及窄窗口；保持 frontend-v1 风格、权限与确认流程。 |
