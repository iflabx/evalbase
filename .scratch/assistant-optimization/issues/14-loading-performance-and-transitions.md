## 目标与依据

减少页面加载、刷新、搜索及翻页的等待和布局跳动：页面框架及时出现，数据加载有反馈，内容自然呈现，后台更新保持稳定。UI 严格对齐 frontend-v1，保留当前数据选择、保存、权限、来源与冲突语义。

继承 [PRD](../../../docs/PRD-data-selection-and-assistant.md)、[领域词汇](../../../CONTEXT.md)、[处理架构](../../../docs/architecture/data-selection-and-assistant.md)、[ADR 0014](../../../docs/adr/0014-project-agent-and-processing-runtime.md)与[前端复用约定](../../../docs/architecture/phase1a-frontend-reuse.md)。本张集中记录 Owner 本次确认的加载交互及验收，后续实施同步受影响架构和测试计划；历史记录及冻结原型不改写。

## 修改范围

### 1. 处理任务列表减量与刷新策略

- 将处理列表改为服务端分页，每页最多 20 项；保留当前最近 100 项的历史范围、排序及搜索/状态筛选语义。筛选作用于完整授权范围，不能只过滤当前页；总数、页数和空态与条件一致，条件变化回到第一页。
- 列表只返回任务名称/要求短摘要、输入数量、类型、执行及保存状态、发起人/时间、来源与父任务/成果入口所需的有限摘要；完整要求与详情按需读取。列表不携带记录 ID 大数组、输入/输出正文、背景全文或完整执行配置，不能为减量伪造缺失信息。
- 分页及统计继续执行账号、项目、个人背景、来源生命周期等校验，不通过总数或摘要泄漏不可见任务。用当前页批量查询或请求内复用减少重复来源/发起人查询；不增加跨权限的长期正文缓存。
- 有活跃任务时按既有频率更新必要状态，进入终态后停止该任务的高频刷新；无活跃任务时不再每 5 秒重取整个历史列表。列表不在前台时暂停其常规定时刷新。
- 本人创建、取消、重试、保存等实际成功后使相关查询失效；回到页面、窗口恢复前台或网络恢复时及时重新核对。其他用户新建的任务须能在恢复前台或显式刷新后出现；若需持续发现，使用有界低频摘要检查，不能恢复无条件全量轮询。
- 保留草稿协作、在线成员、助手执行及运行恢复所需机制；不把列表节流套用为全站停止实时更新。

### 2. 稳定布局与后台更新

- 范围为原始数据列表、测试集列表、处理任务列表、处理输入/结果读取及共用页面加载外壳。复用共用组件覆盖直接调用方，不顺带重做全站页面。
- 首次加载先展示可公开的品牌/布局及页面骨架；身份、项目和权限未确认前，不展示缓存的项目名称、成员或正文。会话恢复保留清晰状态，不因优化跳过鉴权。
- 已获授权的页面保留标题、搜索筛选、表头及分页区域；骨架行与对应表格列宽、行高和密度一致，并预留合理内容高度。空态和错误态使用相同容器，避免反馈出现时整块内容上下挤动。
- 同一已授权对象后台更新保留最近有效内容，在固定位置显示轻量状态。搜索、筛选或翻页可保留旧结果作过渡，但须明确“更新中”，旧响应不得覆盖新条件；新条件未确认时禁止按旧行发起依赖新范围的操作。
- 短暂网络/服务错误可保留同一范围的已授权结果并提供重试；401/403、对象失效、登出或切换账号/项目时按现有规则清理或隔离内容，不能沿用旧正文兜底。
- 区分后台状态刷新与范围/修订变化：不会仅因后台读取便让整张表和所有按钮反复变灰；保存、采用、发布、继续处理仍复检真实范围、修订和权限，不放开原有安全禁用条件。
- 加载过程不重挂载编辑表单、不抢焦点、不重置滚动、输入或跨页选择；草稿离焦保存和离开前等待规则保持有效。

### 3. 搜索防抖与有限缓存

- 对原始数据、测试集及本张改为服务端搜索的处理任务列表，输入框立即响应，停止输入约 250–300 ms 后查询；中文输入法组合期间不查询未确认拼音。清除搜索和显式提交可立即执行，筛选/翻页行为保持明确。
- 使用现有查询库及请求取消机制；过时响应不能替换当前结果，取消读取不显示为失败。不得把防抖套到草稿自动保存、提交、取消或权限处理上。
- 为受影响只读列表设置合适的短期缓存和失效时机，避免正常返回页面反复空白；不全局关闭焦点刷新或无限延长缓存。缓存键及旧数据过渡必须覆盖账号、项目、对象和查询条件，保留撤权发现与写前复检。
- 核对初始化与列表读取的依赖，仅并行已满足权限和输入条件的独立请求；原测试集草稿/已发布统一分页计数与权限不能因提速失真。

### 4. 轻量加载动画与页面过渡

| 场景 | 交互与动画 | 稳定性要求 |
| --- | --- | --- |
| 首次进入 | 立即占位；请求约 200 ms 尚未完成时显示柔和骨架/加载提示 | 快速请求取消提示，避免一闪而过；必要身份状态始终可理解 |
| 首批数据完成 | 内容以约 150–200 ms 淡入 | 不等待动画再展示数据，不强制最短等待时间 |
| 项目内页面切换 | 内容区短暂淡入，侧栏和顶部栏保持稳定 | 不淡出整站、不叠加可操作的旧页面，不跨权限保留内容 |
| 搜索/筛选/翻页 | 保留表格框架，在固定位置显示更新状态，完成后平滑替换 | 不逐行错峰播放，不随高度变化推挤工具栏和分页 |
| 后台刷新 | 数据原位更新，必要时显示小型状态指示 | 不重复播放整页/整表入场动画，不打断阅读和编辑 |

- 严格复用 frontend-v1 的字体、浅灰/品牌色 token、间距、圆角、表格密度和适用组件。骨架只需轻微明暗变化，淡入以 opacity 为主；不新增另一套卡片、全屏遮罩、夸张位移或动画主题。
- 优先使用现有 Skeleton、CSS 和查询状态，不为本张引入动画库或通用过场框架。不虚构加载百分比，不用动画掩盖错误或尚未确认的保存结果。
- 遵循 `prefers-reduced-motion`，减少动态效果时关闭循环骨架及入场动画，保留静态占位和文字状态。设置适当的忙碌/状态语义，避免读屏随每次轮询重复播报；键盘焦点稳定。

## 实施边界

1. 正式 UI 仅在 frontend-v3 修改；frontend-v1、frontend-v2 和冻结原型只读。必要后端变更限于列表读取、字段投影、分页与查询复用，不预设新表、数据库迁移或新基础设施。
2. 收紧处理列表前核对 HTTP、前端和助手直接调用方；保持已有详情、采用、助手多批成果和恢复协议。内部调用若仍需要原形状，显式适配，不能静默截断助手结果范围。
3. 原始数据、处理输入/结果、草稿内容、来源身份、字段保护、幂等和人工确认均不改变。不重构 Agent/Worker，不重跑模型或处理任务来制造性能样本。
4. 一张 Ticket、一次最终 Owner checkpoint。复用现有项目及管理员/编辑账号；额外权限与分页夹具放自动测试隔离环境，不在 Owner 环境批量创建项目、任务或账号。

## 验收标准

| 编号 | 场景 | 通过条件 |
| --- | --- | --- |
| R14-1 | 处理列表跨页、搜索、状态筛选，含超过 20 项与最近 100 项边界 | 单页响应最多 20 项有限摘要；不夹带大正文/ID 数组；顺序、总数、空态和边界一致，无不可见对象泄漏 |
| R14-2 | 无活跃任务、运行至终态、窗口隐藏/恢复、另一账号新任务 | 无任务时不再每 5 秒全量拉取；活跃进度可见，终态停止高频更新；前台恢复/显式刷新可发现其他用户变化，本人成功操作及时更新 |
| R14-3 | 快响应、延迟约 1–2 秒、首次进入、浏览器刷新、返回页面 | 快响应无骨架闪现；慢响应有稳定占位；标题/表头/分页不因加载提示反复跳动；无额外人为等待 |
| R14-4 | 中文组合输入、快速输入/清空、交错响应、连续翻页筛选 | 组合期间不查拼音，防抖生效；最后条件获胜，取消不报错，过渡旧行不会被当作新范围提交 |
| R14-5 | 处理结果后台更新、详情核对、跨页选择；草稿有未保存输入 | 无整页重复淡入及按钮反复闪烁；焦点、输入、选择和有效滚动位置保持；旧响应不覆盖编辑，原保存等待/冲突机制有效 |
| R14-6 | 网络失败后重试、登出/换账号/换项目、撤权、来源失效 | 普通失败可恢复且提示真实；安全失效不显示缓存正文，不用旧授权解锁写入；助手及其他直接调用方不因列表收紧回归 |
| R14-7 | 桌面和窄窗口、键盘操作、减少动态效果 | 对齐 frontend-v1；无整页横向溢出或叠层拦截；减少动态效果生效，状态可理解且不重复播报 |
| R14-8 | 同一数据规模的优化前后比较 | 记录响应字节、列表请求次数与少量接口耗时；单页请求减量、空闲高频全量请求归零；不以动画完成或网络偶然变快代替优化证据 |

## 验证与交付

- 首个针对性回归优先覆盖“终态列表仍全量轮询、分页返回过重”，再验证加载过渡与搜索竞态；可控延迟/错误使用现有测试拦截，不给共享服务器施加人工负载。
- 选择受影响的接口/权限及浏览器回归、类型检查、lint 和前端构建；只验证列表收紧的直接调用方，不自动扩为全仓测试。遵循根 AGENTS.md 的比例规则完成一次必要审阅。
- 性能复测只读现有数据：同一账号、范围与页大小，分别记录服务端本机和 SSH 隧道结果，少量顺序请求即可；不做 5/10 用户压力测试、两小时稳定运行或服务重启演练，不承诺所有网络均达到固定毫秒数。
- 实施同步更新受影响架构及测试文档；沿用现有 4217，将必要服务更新到固定代码提交并核对健康与前端请求，提供简短验收步骤。未变服务保持原版本，保留现有用户数据。
- 本轮实现及同一 4217 Web 更新已获授权；不合并 main、不推送 GitHub 或正式部署。
