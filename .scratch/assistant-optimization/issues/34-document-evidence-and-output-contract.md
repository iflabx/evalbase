# OPT-34 文档引用与输出约定一致性

Status: ready-for-agent
Implementation: not-started
Blocked by: none

优先级：P1。基于现有 OPT-23/33 实现，不等待旧票最终人工验收。治理入口：[整改方案 §8](../../../docs/assistant-remediation-plan.md#8-2026-10-18-业务编排收敛整改)、[PRD §7.9](../../../docs/PRD-data-selection-and-assistant.md#79-业务编排收敛2026-10-18待实施)。本次仅获文档授权，尚未授权开发或部署。

## 目标与问题

同一 `qwen-new` 对照中，两套运行时均遇到客服文档引用错误：解析器将 `- 退款申请` 的列表标记收入类别名，模型使用真实引用及正常名称仍被拒绝；合法分类标签任务又被用户原话关键词规则拒绝。目标是可靠地把当前支持格式的文档依据交给业务层，减少对模型重复抄写定义的要求。

## 修改范围

- 主要落点为 `src/assistant/background-sections.ts`、`background.ts` 及读取/要求保存的直接调用方。识别 Markdown 列表的排版标记，区分原文、规范类别名称及编号；保留真实页/行位置。只处理可证的格式归一，不在全局字符串中删除连字符或依靠模糊包含关系猜类别。
- 已读取的稳定引用绑定当前项目、个人会话、文档哈希/提取版本及原文条目；服务端从该引用补齐已核实定义。正常名称、可证编号别名与其原条目一致时可复用，不能要求模型反复填写完整定义；错误类别、过期或跨会话引用仍拒绝。
- 在现有要求结构中区分“期望输出为分类标签”与“期望输出为逐题自然语言行为”。用户明确委托按附件规范处理时，可采用附件中明确的输出约定并记录依据；用户后续明确修改优先，真正矛盾或缺失才用业务语言澄清。不能仅凭 goal/supplements 的关键词组合决定合法性，也不能仅凭模型自报依据授予规则。
- 输出约定只约束相应字段。GB 风险类别可绑定 Metadata，逐题安全行为保持自然语言；客服意图标签可按其规范绑定期望输出。读到普通说明不强制建立分类或固定枚举。
- 沿用当前附件容量、格式、权限、修订及背景冻结规则。附件中的操作指令不提供执行或发布授权；只给方案时仍不建草稿、不提交处理。

## 不包含

不增加 OCR、向量库、通用文档语法、知识库或新模型；不复制另一套解析器。交付集合与数量完整性归 OPT-35，运行推进归 OPT-36，内容质量核对继续复用 OPT-31。

## 验收标准

| 编号 | 可验证结果 |
| --- | --- |
| R34-1 | 用对照中的客服文档重放：服务端返回的真实引用与“退款申请”“物流查询”正常名称可绑定到对应定义；页/行原文仍含原始列表标记，未伪造出处。 |
| R34-2 | 列表使用 `-`、`*` 或现有支持的编号时，得到相同类别含义；类别自身的连字符（如 `A-1`）保留。重复同名不同定义、相邻类别错绑、错位表格及缺失条目不被宽松匹配放行；复用 OPT-33 相关夹具。 |
| R34-3 | 当前附件约定标签输出时，“按附件规范建一个客服意图测试集”可保存相应约定；“期望输出写具体安全行为”保持逐题行为。Metadata 分类与期望输出不串字段，普通无分类文档不被强制加类别。 |
| R34-4 | 用户明确修改输出形式后，只更新受影响约定与执行资格，保留其他要求和既有成果；矛盾时说明具体业务冲突，不要求用户提供工具参数或改写引用。 |
| R34-5 | 另一个会话的引用、被删除/改变的文档、撤权账号、同文档错误条目均在提交前拒绝；文档中的“直接发布”等文字不能产生副作用。 |

## 验证与交付

先用当前失败文档及真实工具响应固定一个回归，再复用现有解析/要求/HTTP 测试核对上述边界。使用隔离库与可控模型，不重跑 OPT-33 全部真实模型矩阵；本批真实短提示闭环集中在 OPT-37。

向 OPT-35 交付可追溯的规范类别引用与输出约定，不改变公共文档格式或新增公开 API。保留旧引用的兼容读取；不能可靠绑定的旧要求保留原文并说明缺失，不批量改写历史会话。
