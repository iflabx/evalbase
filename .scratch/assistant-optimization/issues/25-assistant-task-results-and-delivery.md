# OPT-25 项目助手整任务结果审核与短请求交付闭环

Status: ready-for-agent
Implementation: not-started
Blocked by: OPT-21, OPT-22, OPT-23, OPT-24

优先级：P1。仅文档授权。范围见 [总方案 §7、§9](../../../docs/assistant-workspace-reliability-plan.md)，沿用 [PRD §7.4](../../../docs/PRD-data-selection-and-assistant.md#74-审核与确认)、OPT-10/17 有效成果、OPT-13 保存回原草稿和既有确认/字段冲突合同。

## 目标与实施范围

- 独立工作区默认显示当前助手任务的完整有效候选；批次仅用于历史追溯。整任务数量、筛选、分页、结构检查与采用使用同一集合，不能以历史运行简单拼接。
- 复用现有有效成果函数及业务权限入口，处理局部替换、扩写追加、排除、缺失及已保存状态。助手 task 与 processing task 不强行合为一张表；一个助手任务的多运行按有效引用组合。
- 在既有会话候选 API 必要时增加任务范围读取，保留 run 范围用于历史。返回当前实际运行/结果引用、稳定采用身份及派生 `reviewRevision`；不接受前端任意运行清单，不建立候选副本表或新结果引擎。
- 复用 ProcessingReview 的问题、期望输出、Metadata、来源、搜索筛选、分页/选择与详情。选择绑定有效集合修订和稳定身份；不能用屏幕序号作为局部改写/采用身份。
- 选中若干行后用短话提出局部改写，输入区显示准确作用范围。服务器冻结该选择，未选成果保持不变；替换或排除导致旧选择失效时明确重新核对。
- 草稿起点默认保存回原草稿；其他去向次级展示。采用前使用现有固定确认，保留最初草稿基线、当前权限、修订、容量、字段保护和幂等；最终发布仍单独遵守既有确认。
- 结果对话说明、结构核对、内容审核及真实保存/发布分别展示。真实成果入口来自领域回执；部分采用不能标整个任务完成。
- 汇总 OPT-20–24 受影响基线，在最终固定 HEAD 完成短请求同会话闭环。只补证据缺口，不创建第二套测试平台或重复全库流程。

## UI 对齐与非目标

页面布局沿 OPT-24，表格/过滤/确认弹层直接复用 frontend-v1 风格和现有业务组件。结果页头只显示当前任务范围与真实数量；历史批次折叠，来源分实际记录来源与整次参考范围。

不增加语义自动评分器、测试集版本树、自动发布、多任务任意合并或全量缓存。处理去重/补齐和继续处理沿用已有服务，本张不重新设计模型生成算法。

## 验收

| 编号 | 验收 |
| --- | --- |
| R25-1 | 多批候选、局部替换、扩写和排除后，列表/总数/筛选/核对/采用一致；被取代项不重算，参考输入不冒充新增结果，分页覆盖真实全部成果。 |
| R25-2 | 选两条提出改写只影响固定两条；刷新、翻页及搜索不换身份；结果更新使失效选择显式重核对，旧范围不误改/误采用其他行。 |
| R25-3 | 草稿入口默认保存回原草稿，保留未选项、最初字段修订与来源；并发修改冲突不覆盖，重复点击/丢响应不重复追加。 |
| R25-4 | 保存/发布均有当前固定确认及真实回执，部分采用标明范围；助手与直接处理页看到相同保存事实，权限撤销后不泄漏正文。 |
| R25-5 | 同会话完成方案→执行→整任务审核→选中局部修改→保存/发布目标，不靠用户手写内部 ID/批次/工具名；安全/性能结果与已有 baseline 比较。 |
| R25-6 | 按总方案 §9 完成最终短请求重复样本和一次 200 条隔离集成任务，报告目标达成、恢复、耗时、内容审核范围与人工修改；未核实内容不得声称全量可用。 |

先测试有效集合与选择修订、确认冲突等确定性边界，再做定向浏览器和有限真实模型样本；此前同 HEAD 下已通过结果复用。没有 5/10 人压测、两小时稳定或服务器重启测试。

本张结束提交实际代码版本和六张 Ticket 的验证链接，复用同一 4217 供一次完整人工验收，保留原资料/会话/版本。通过自动检查不代表 Owner 验收，不自动合并或推送。
