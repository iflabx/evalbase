# OPT-32 工具参数调用前纠错与真实模型恢复验证

Status: ready-for-agent
Implementation: not-started
Blocked by: none

优先级：P1。沿用现有 OPT-21/22/26 及 OPT-30 后的代码；不等待旧票 Owner 验收。治理入口为 [PRD §7.8](../../../docs/PRD-data-selection-and-assistant.md#78-调用纠错文档规划与内容一致性补修2026-10-15待实施) 和 [补修顺序](../../../docs/assistant-generation-repair-batches.md#7-后续补修与-opt-31-调整)。本次仅文档，尚未授权开发。

## 问题与目标

模型多次返回错误字段、错误类型和过长的嵌套计划。已有统一 schema 校验和普通对话错误反馈，但没有接入当前 `ai@7.0.127` 的正式 `repairToolCall`；校验回调还会改变无进展/终止状态。部分回归预设下一次模型调用正确，无法证明真实模型具有恢复能力。目标是在执行前集中消化可修复的参数错误，用户无需说明工具名、字段名或内部 ID。

本票负责参数合同与调用前恢复；文档编号/定义匹配由 OPT-33 负责，生成内容与类别是否相符由 OPT-31 负责。

## 修改范围

- 优先修改 `src/assistant/agent.ts` 的公共工具入口及现有诊断/预算模块，覆盖直接工具调用和 `plan_task` 中嵌套步骤的同一参数合同。模型声明、运行时校验和修复依据复用同一 schema，避免再维护一套手写示例合同。
- 使用已安装 AI SDK 的 `repairToolCall`：已知、无歧义且无信息损失的形式可定向归一化，其余结构问题提供原工具、原参数、目标 schema 和准确字段错误，在调用前修复并完整复检。不能无条件删除未知字段，尤其不能丢弃其中的用户要求；不能靠 JSON 正则截取放宽边界。
- 参数校验只返回校验结果；尝试可记录，首次可恢复失败不修改任务终态。一次逻辑调用最多两次修复模型请求，由 SDK 单次修复回调内部控制；后续普通对话重试、自动续做不得为同一未解决错误重置额度。原调用、修复、网络重试共享现有请求/时间预算及取消信号；额度不足立即停止，不另开宽限预算。
- 修复请求只产出参数，不具备业务执行能力；限定当前阶段的原工具、用户目标、对象与输入范围。模型不得猜 ID、换工具绕过权限、改数量、删要求或解除字段保护。修复后重新检查权限、业务规则和修订；取消、撤权或要求更新后的迟到结果不能执行。
- 缩小模型需要拼装的计划参数：当前身份、真实引用及固定执行事实由现有服务端状态绑定；每阶段只提供必要工具。保留真实业务澄清，不能用默认值掩盖歧义。领域校验失败、网络错误、已执行失败和未知写入不进入纯格式修复；未知写入仍先查原操作回执。
- 当前模型端点的严格工具输出能力必须实际核实；支持时采用兼容 schema 的约束输出，不支持时保留上述服务端校验。不得仅因兼容适配器可发送 `strict` 就宣称已启用受约束生成，也不以升级依赖或更换模型为默认前提。
- 用户界面沿用既有简短业务错误与恢复入口，技术字段保留在受权限保护的诊断中；内部修复成功不留下失败卡或要求用户纠正参数。UI 严格对齐 frontend-v1，不新增配置页。

## 验收标准

| 编号 | 验收 |
| --- | --- |
| R32-1 | 真实 SDK 路径覆盖未知字段、错误类型、未知工具及嵌套步骤参数错误；包括历史 `instructions`、`allSelected`、`steps` 非数组案例。仅完整校验通过的调用执行，保留用户语义；失败调用产生零业务写入。 |
| R32-2 | 首次校验失败、修复成功后正常推进，不残留 `noProgress`/预算终止状态；修复失败、再次无效和耗尽分别保留可定位原因，单调用修复最多两次且计入原总预算。 |
| R32-3 | 修复试图换对象、扩大范围、改目标数量、删要求、跨项目或修改保护字段时拒绝；停止、撤权、修订变化后的迟到修复不执行。相同操作只执行一次，未知写入依旧先对账。 |
| R32-4 | 直接调用与计划内同名操作使用同一合同；领域错误不被伪装成格式修复成功；当前阶段不支持的能力不靠新工具名绕过。 |
| R32-5 | 在隔离夹具中，将至少 6 种脱敏历史错误参数交给当前真实模型的修复回调；保留原始失败，逐例记录首次/修复后合法性和预算。不得预设第二次正确回复；每种已知可修复案例须在上限内修好，安全拒绝案例须不执行。 |
| R32-6 | 固定代码与模型配置，用至少 3 条普通短提示覆盖查询、先给方案、已授权执行；每条固定跑两次，所有成功与失败均纳入记录。统计首次合法率、修复后合法率、最终业务完成数、修复次数和额外耗时；0 次用户内部参数纠正、0 次重复写入。GB 完整规划按 R33 验收，不能以通用样例代替。 |
| R32-7 | 严格输出模式支持与不支持的路径均有明确证据；协议可控测试和真实模型测试分开报告。内部纠错成功后的页面不出现误导失败，额度耗尽时保留已有成果；未解决的指定正常案例不记为通过。 |

## 验证与实施边界

复用现有集成测试、公开接口、诊断和小样本脚本；可控模型用于确定性协议及副作用边界，真实模型用于修复能力证据。修复请求必须走相同管理员配置的端点，不记录凭据或完整背景正文。共享实现的相关调用方一起核对，未变功能复用已有证据；不在本票运行八类 400 条生成。

使用现有框架、存储和权限机制；不引入第二执行循环、通用工作流平台或新评审智能体。新模型声明只影响新调用；已有已确认操作和运行的固定参数、幂等身份、修订保护保持。验收环境沿用同一 4217，保留全部现有数据；开发、环境更新和最终验收以后续实际授权及证据记录。
