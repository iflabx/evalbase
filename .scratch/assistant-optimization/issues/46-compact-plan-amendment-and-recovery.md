- 优先级：P1。范围：第7项规划修改、核对及原额度内恢复。
- 依据：[共同合同§10](../../../docs/assistant-mechanism-consolidation-2026-10-22.md#repair-long-tasks)、[PRD §7.12](../../../docs/PRD-data-selection-and-assistant.md#long-task-product)、[实际诊断§1–2](../batch2-repair-20261022/root-cause-review-20261022.md)。
- 诊断基线6c2cd08；现有方案类别已正确，但再次要求相同类别后两次4096 token截断，随后普通继续被repair_limit拒绝。首次完整方案仅879输出token，证据不支持先扩大输出限额。

## 目标

已有方案的小修改使用小合同；已满足要求得到可核验回执。截断后真正缩小请求，在剩余额度内保存，达限时给准确说明，不把用户逼成工具参数调试者。

## 修改范围

1. 在现有plan_task接线明确首次建立、已有方案增量修改和核对三种意图；有附件不再自动等于完整文档规划。使用相同事实构造器生成工具Schema、模型上下文和服务端合并输入，消除完整新增字段与局部修改指令冲突。已有合法完整方案仍能兼容。
2. 增量表达稳定deliveryId、基准修订及明确变化；复用reviseDeliveryGoals，合回原合法场景、定义、配额和未改交付后完整验证。不能放松创建校验、删除未改限制或擅自调整数量来获得通过。
3. 已有生效字段确实满足本轮要求时，在当前修订和权限下保存“已核对满足”回执，关联本次修改身份；这是一项真实核对，不伪造数据变更或修订更新。仅有模型explanation、未知语义或模糊映射不能完成核对。实际需要修改则走保存回执。
4. 输出length/不可解析进入现有修复控制器，切换真正受限的修改Schema、可用工具和必要事实；不携带完整坏参数、全历史和无关交付。参数不可解析时用已保存待修改意图限定范围；不能确定对象时只询问必要业务信息。
5. 纠正仍共用同一修改身份及原2次/其中1次截断额度。普通“继续规划”恢复未保存变化；读取/消息提交/控制请求共用实际恢复理由，repair_limit、期限和总预算不足不能映射为泛泛“请重试”。已有事实可本地核验完成时不额外请求模型。新增有界预算授权由OPT-49负责，本票不加额。

## 结构与接口边界

重点为assistant/agent.ts、delivery-plan.ts、tool-repair.ts、恢复/反馈及对应DTO；按实际调用链收敛一个方案变更准备与核对接口，SDK适配、强制补保存和恢复都接入。移除被替代的documentPlanning宽泛分支；不新增第二份生效计划或独立修复循环。诊断保留第一次截断、长度、修复合同版本、范围摘要、额外请求数及最终回执，不存密钥或完整敏感模型正文。

## 验收标准

| 编号 | 公共流程及断言 |
| --- | --- |
| R46-1 | 有背景且已保存退款进度/退款到账时间各2条方案，再普通确认相同类别：产生当前要求的核对回执、pending清除、原交付/数量/定义保持；没有草稿生成或处理任务，不以口头回复判成功 |
| R46-2 | 真实改名、单交付数量修改和多交付局部修改：工具实际Schema及修复请求只暴露本次必要合同，服务端合并后完整合法；保留其他字段、已完成回执及仅规划权限 |
| R46-3 | 从用户入口注入“已有control→口头答复→截断”：观测下一次请求Schema/字节范围及可用工具真实收缩；合法纠正后持久成功；不是仅断言提示词包含“增量” |
| R46-4 | 同一修改连续截断/业务错误共享最多2次额外纠正，其中截断重提最多1次；有余额的普通继续恢复原意图，额度耗尽不发模型请求、不改旧计数；消息与按钮返回相同准确原因 |
| R46-5 | 核对/保存响应丢失、双击、更新修订、停止、撤权和背景变化：按原回执对账，最多一次有效核对/写入；旧响应不能解除新修改或越权执行 |
| R46-6 | 新建完整方案、合法旧完整更新和旧任务读取保持可用；旧失败、预算和已保存成果不重写；本地核对与“技术干预后成功”分开记录 |

## 定向验证与依赖

使用已有HTTP/SDK/持久化测试入口和固定错误夹具，覆盖完整用户消息→模型提议→校验→保存/核对→刷新→继续链；观察请求合同、计数和业务副作用。先写失败回归再实现，不用脚本化合法下一步掩盖请求本身仍过宽。无需真实模型调用或重跑旧CU，本票通过不代表第7项真实模型已通过；统一在OPT-50复测。

OPT-48依赖本票增量投影；OPT-49使用其修改身份/修复计数；OPT-47可独立实施。本票需交付共享调用方、退出分支与兼容说明。沿用frontend-v1，只提供必要中文原因，完整续接交互由OPT-50统一。

## 数据保护与完成口径

保留当前验收数据、关闭预算和旧会话；不克隆原失败任务以规避限额，不重跑已完成部分，不改变OPT-31质量状态。完成指代码接入和本票定向验证完成；真实CU状态另记，不标任意输入零失败。
