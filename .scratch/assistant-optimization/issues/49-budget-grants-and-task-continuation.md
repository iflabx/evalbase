# OPT-49 复杂任务预算分层与可续接执行

Status: ready-for-agent
Implementation: not-started
Validation: not-run
Blocked by: OPT-47、OPT-48（传递依赖OPT-46）


- 优先级：P1。前置：OPT-48任务身份/检查点引用、OPT-46紧凑修改/核对、OPT-47统一业务预检。
- 依据：[共同合同§10.4](../../../docs/assistant-mechanism-consolidation-2026-10-22.md#budget-continuation)、[既有OPT-44](44-resume-decision-and-budget-continuity.md)、[PRD §7.12](../../../docs/PRD-data-selection-and-assistant.md#long-task-product)。
- 本票实现明确追加授权功能；当前开票不授予任何现有任务新的额度，不重开旧验收。

## 目标

有进展的复杂任务在有界段之间正常续接；达总额度后保留成果并明确暂停。用户可在知晓范围与上限后另授一份有限额度，不改旧账、不通过“继续”无限重置，不让每个正常段都要求用户确认。

## 修改范围

### 1. 分层预算与单一累计账本

- 用OPT-48的taskId绑定当前任务消耗，区分一次模型输出/输入窗口、执行段、任务预算授权、处理Worker冻结配方和外部验证总限额；所有重试/修复/工具调用仍计实际消耗，不把参数修复免费化。
- 保留共同合同的默认数值；既有初始额度固定，后续明确授权追加独立记录。original policy、used、原deadline与旧授权不覆盖；总计由历史授权和实际增量派生，避免多个计数副本各自修改。
- 沿现有事务/锁预留并结算，同一尝试重读不双扣、未知发出结果不错误退款；等待用户/后台不计活跃消耗，重复Worker事件不重复领取模型段。工具次数、SDK步数、实际HTTP尝试分别记录，不互相冒充。
- 全部请求服从最小有效剩余上限；新任务或续接授权都不重置processing根预算，也不突破外层CU campaign。旧合同不可用新策略重算、刷新或转换预算。

### 2. 可证检查点与正常让出

- 在实际模型请求前检查段剩余时间/调用数；接近边界而有合法待完成位置时，原子保存检查点并沿现有调度让出，不依赖最后一次模型总结成功。
- 同段重试继承原deadline；新段拥有自己的有限窗口但继承任务消耗、修改身份、纠错计数、回执与授权。续段前复检权限、修订、依据、当前步骤和未知写回执。
- 进展根据新有效要求/范围/业务回执/检查点前移计算；相同查询、错误和状态不算进展。使用现有方案节点推导有限自动事件额度，去重事件不会挤占正常推进额度；无进展和总资源限制始终生效。
- 确定性后续工作直接使用服务端真实成果推进，后台等待由现有事件通知，禁止模型轮询。剩余额度不足则保存并暂停，不显示已交付，也不反复给无效重试按钮。

### 3. 明确且有上限的追加授权

- 只对新版本任务提供共同合同规定的单段预设追加额度，用户明确接受当前任务/修订/待完成范围及上限才创建授权。沿既有控制入口兼容增加受限动作；不增加预算控制台、任意数值接口或独立审批系统。
- 普通“继续”只消费已有余额；无余额时返回一次准确的追加授权选择，不能将该词直接等同同意额外费用。初始明确执行授权覆盖原预算内自动段，无须逐段弹窗。
- 同一失败修改已耗尽纠错额度时，额外普通任务额度不能自动解锁；只有明示“对该未保存修改进行新的有限修复尝试”的授权可创建关联尝试，旧used保留，新尝试仍受同一追加额度和单次修复上限约束。没有自动再授权链。
- 授权绑定用户/任务/修订/用途/有效期和幂等键；过期、换目标、停止或撤权失效；双击/双标签页只增加一次。旧关闭campaign和旧预算格式不得追加、克隆或通过新会话重跑。

### 4. 统一恢复与可行动反馈

会话读取、普通消息、控制按钮、调度领取、发请求前共用决策，分别返回：可自动续段、可消费余额继续、待业务补充、待明确追加额度、无进展/修复到限、模型服务失败。输出当前任务/修订及已保留成果；repair_limit和预算拒绝不再回退为“操作未完成，请重试”。供OPT-50展示，前端不能自行计算授权额度。

## 结构边界

收敛assistant/budget.ts、recovery.ts、tasks.ts、store.ts和实际调用包装器；优先现有JSON/回执/锁及Worker，不增加新调度框架。允许为任务/授权/段的稳定归属调整持久结构和内部接口；记录直接调用方、未知结果对账以及旧分支退出。原外部模型/处理超时不会因此被保证消失，要保留可恢复的真实故障。

## 验收标准

| 编号 | 场景与通过标准 |
| --- | --- |
| R49-1 | 可控小段容量下完整多步骤任务跨至少3段：真实完成而非保护停止；同一taskId，段deadline独立，累计调用/活跃时长准确，已完成操作不重复，未越过总上限 |
| R49-2 | 足量新任务预算下超过原12个事件的合法推进与重复事件混合：合法步骤完成，重复事件不重复调度；保留有限事件/资源上限，不硬编码“第13次就失败”或无限自动续段 |
| R49-3 | 同一修改跨段：原2次/截断1次修复计数不重置；连续无进展停止；普通继续不产生新额度，读取/消息/领取决策一致 |
| R49-4 | 任务余额耗尽：原子保留检查点/成果；普通继续无外部请求。明确单段追加后只执行未完成部分，旧账不变、总计增加；额外授权耗尽后再暂停，不自动再批 |
| R49-5 | 明示有限修复授权与普通追加授权分别验证：仅前者可新建关联修复尝试，旧尝试完整；模型伪造、双击、失效修订、跨账号、撤权/停止均不能增额或重复领取 |
| R49-6 | 发出请求后超时、业务成功响应丢失及并发续段：消耗预留不被错误释放，先对账原操作，最多一次副作用；时钟边界和后台等待不双扣 |
| R49-7 | 对话任务尚有额度但processing根预算或CU外层额度耗尽：不重建处理任务规避、不发新请求；新任务初始额度也不能绕过外层限制 |
| R49-8 | 冻结旧任务/关闭预算/已有验收读取和受控恢复：原policy、used、deadline和历史哈希不变；无自动转换或重跑，缺证据如实限制 |

## 定向验证与交付

用隔离数据库、可控时钟、脚本化故障和HTTP/Worker入口，降低测试专用段额度以快速触发边界；测试配置只在隔离夹具生效，生产默认不调高/调低。测试需实际跨段完成目标，再验证耗尽保护，两者分别报告。受控历史/计数注入不作为真实模型稳定性证据。

本票不触发真实追加费用、不启动旧任务、不改验收数据；真实小流程在OPT-50集中进行。开发时补充API兼容和幂等验证，不为预算功能做通用计费系统。UI继续对齐frontend-v1，完整页面衔接由OPT-50完成。
