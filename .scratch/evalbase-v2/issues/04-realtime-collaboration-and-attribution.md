# V2-04：实时共同编辑、在线状态与修改归属

Status: ready-for-agent
Implementation: in-progress

Blocked by: 批次 B 经 Owner 验收通过；获得本 Ticket/批次 C 执行授权。
Checkpoint: C（本 Ticket 完成后双人完整验收）

## Outcome

两个真实账号能看到谁在线、谁在编辑、谁修改过，并安全实时编辑同一草稿；完成 v2 全流程的最终受影响验收。

- Spec §1 链接的 PRD、CONTEXT、架构、测试计划、冻结原型与 donor 复用合同。

## Scope

- 在 V2-03 HTTP 保存协议上增加真实同步接收与重连恢复，事件按稳定 draft ID 隔离、排序、去重；旧游标重取快照且保留未提交输入。
- 右上角彩色首字头像、悬浮权限、登出；按用户聚合多连接，离线超时清除。草稿行和字段显示编辑位置头像，焦点移开及时清除。
- 实时更新不同字段，完整展示同字段冲突双方值并逐项解决；删除、发布、撤权、回收事件不能丢失或复活数据。
- 记录/字段修改者、修改时间及来源与修改页面读取 V2-03 已存事实；当前名称展示，发布者分离，旧历史显示未记录。
- 固定最终 HEAD 完成真实双人并发发布、断线恢复、权限变更和旧版本读取的集中闭环；复用已完成能力，不另增整合 Ticket。

## Acceptance Criteria

1. 两独立账号同草稿正常保存在测试计划目标内同步；异父/异项目消息不串线，离线/重连/重复乱序事件不丢用户输入。
2. 同人多页一个在线头像，离线按约定超时消失；在线、编辑焦点、已保存修改者明确区分。查看者只看项目级在线状态，不看草稿内容/位置。
3. 多项字段冲突逐项保留，可采用远端或重提本地；Metadata 按完整字段冲突处理；不增加逐字 CRDT。
4. 修改者由服务端身份确定，账号改名后显示当前名且归属不变；正式版本不把所有作者归给发布者，也不更改内容哈希/CSV 列。
5. 登出、降权、移除、父对象回收后流与后续请求正确失权；永久删除内容不能从事件或浏览器重连恢复。
6. 双人发布同一草稿返回同一正式版本，另一人迟到输入得到明确反馈；最终 C 包含 A/B 主要路径的定向回归，未实现项不能写成通过。

## Frontend parity

**前端 UI 严格对齐冻结原型，样式严格沿用 frontend-v1。** 执行 [PRD §7](../../../docs/PRD-evalbase-v2.md#7-视觉与实现边界)，仅允许已确认产品差异及本 Ticket 明确分期项；checkpoint 前提供实际页面对照证据，修正未经确认的偏离。

在线首字头像及悬浮框、草稿行/字段头像、多冲突提示、记录修改者和来源与修改页；移除旧用户名/账号权限常驻块和协作状态卡片，frontend-v1 风格保持一致。不增加聊天、评论或新通知中心。

实施前在本节补充 Ticket-local 对照表，逐项记录字段、顺序、标签、启用条件、空/错态和排除项；正式前端仅 frontend-v3，frontend-v1 只读。

## Owner checkpoint

按 Spec 的 C 提供两个独立浏览器上下文及合成账号，先同草稿并行修改，再冲突/断网/发布/撤权。记录实测同步延迟与离线清除时间，核对固定 HEAD、旧版本、CSV 和重启恢复。通过后释放 C 资源；合并/推送/部署仍需另行授权。

## Out of scope

不增加历史用户名快照、查看者只读草稿、未注册邀请、SSO、邮件或逐字自动合并；不再建立第二套草稿/发布服务。
